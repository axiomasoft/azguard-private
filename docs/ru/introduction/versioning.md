# Политика версионирования

AzGuard следует SemVer и пока остаётся на 0.x: 1.0.0 не запланирован. До тега 1.0
несовместимое изменение публичного API, поведения по умолчанию, схемы или
поддерживаемой версии рантайма может выйти в minor-релизе. Новая совместимая
возможность — MINOR, совместимое исправление — PATCH. Решение о версии, запись в
корневом `CHANGELOG.md`, руководство по обновлению и snapshot-проверка API входят
в один кандидат релиза.

## Публичный API

Публичной считается поверхность `@api` в `packages/core/src`, замороженная `tests/Unit/ApiBoundaryTest.php`: типы и публичные методы, включая имена и порядок параметров, типы и значения по умолчанию. `@internal` — рабочие швы и не гарантируются как контракт потребителя.

## Что считается breaking change

- удаление, переименование или de-publication `@api` элемента;
- изменение сигнатуры, включая имя параметра для named arguments;
- изменение поведения существующего значения по умолчанию;
- добавление обязательного метода в публичный интерфейс.

Перед изменением замороженной поверхности создайте решение, обновите migration guide и осознанно регенерируйте snapshot в том же изменении. Полная англоязычная политика находится в [Versioning](/introduction/versioning).
