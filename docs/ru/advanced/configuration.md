# Конфигурация

Опубликовать файл конфигурации:

```bash
php artisan vendor:publish --tag=az-guard-config
```

Это создаёт `config/az-guard.php`. Ниже — полный файл с аннотациями.

```php
<?php

return [

    /*
    |--------------------------------------------------------------------------
    | Точки расширения
    |--------------------------------------------------------------------------
    | Заменяемые «единственная активная стратегия»-швы — переопредели своим
    | подклассом, чтобы заменить реализацию целиком. Пример каждого — раздел
    | «Замена базовых сервисов» в Extending.
    */
    'manager' => \AzGuard\AzGuardManager::class,
    'resolver' => \AzGuard\Registry\Resolver\EffectivePermissionResolver::class,
    'matcher' => \AzGuard\Registry\Matching\HierarchicalPermissionMatcher::class,
    'abilities_resolver' => \AzGuard\Abilities\DefaultAbilitiesResolver::class,
    'role_permission_validator' => \AzGuard\Registry\Validation\CatalogRolePermissionValidator::class,

    /*
    |--------------------------------------------------------------------------
    | Модели
    |--------------------------------------------------------------------------
    | Eloquent-модели, используемые AzGuard. Замени своими подклассами.
    */
    'models' => [
        'role'            => \AzGuard\Models\Role::class,
        'scope'           => \AzGuard\Models\ModelHasScope::class,
        'direct_grant'    => \AzGuard\Models\DirectGrant::class,
        'role_permission' => \AzGuard\Models\RolePermission::class,
    ],

    /*
    |--------------------------------------------------------------------------
    | Пространство имён моделей
    |--------------------------------------------------------------------------
    | Используется при резолюции класса модели по имени.
    */
    'models_namespace' => 'App\\Models\\',

    /*
    |--------------------------------------------------------------------------
    | Имена таблиц
    |--------------------------------------------------------------------------
    | Переопредели, если имена по умолчанию конфликтуют с существующими.
    */
    'table_names' => [
        'roles'            => 'roles',
        'model_has_roles'  => 'model_has_roles',
        'model_has_scopes' => 'model_has_scopes',
        'role_permissions' => 'az_guard_role_permissions',
        'direct_grants'    => 'az_direct_grants',
    ],

    /*
    |--------------------------------------------------------------------------
    | Имена колонок
    |--------------------------------------------------------------------------
    | morph_type задаёт тип полиморфных колонок: 'int' (по умолчанию), 'ulid'
    | или 'uuid' — под тип первичного ключа модели User. Любое другое
    | значение бросает InvalidMorphTypeException при boot (fail-fast).
    */
    'column_names' => [
        'morph_type' => env('AZ_GUARD_MORPH_TYPE', 'int'),
    ],

    /*
    |--------------------------------------------------------------------------
    | Панели
    |--------------------------------------------------------------------------
    | FQCN классов PanelProvider. Каждая панель — изолированное
    | пространство имён для прав и ролей.
    */
    'panels' => [
        // \App\Guards\App\AppGuardPanelProvider::class,
        // \App\Guards\Admin\AdminGuardPanelProvider::class,
    ],

    /*
    |--------------------------------------------------------------------------
    | Панель по умолчанию
    |--------------------------------------------------------------------------
    | ID панели для проверок вне HTTP-запроса (консоль, очереди, роуты без
    | middleware azguard.panel). null — не угадывать: при активной панели
    | не установлено и панелей >1, проверки fail-closed отказывают.
    |
    | Модельные API ($user->hasPermission() и т.д.) при null падают на
    | встроенную панель 'app' — задай default_panel явно, чтобы изменить это
    | проектно. Путь Gate/Authorizer остаётся fail-closed как описано выше.
    */
    'default_panel' => null,

    /*
    |--------------------------------------------------------------------------
    | Строгие панели
    |--------------------------------------------------------------------------
    | Опционально. true — резолюция явной, настроенной, текущей или fallback
    | панели, которой нет в registry, бросает PanelNotFoundException, в том
    | числе при пустом registry. По умолчанию выключено (back-compat).
    | Независимо от флага итоговый panel id не длиннее 128 символов.
    */
    'strict_panels' => false,

    /*
    |--------------------------------------------------------------------------
    | Обязательные permission-атрибуты
    |--------------------------------------------------------------------------
    | Опционально. true — azguard.check бросает MissingPermissionAttributeException,
    | если у action нет ни #[CheckPermission], ни #[SkipGuardCheck]. По умолчанию
    | выключено: отсутствующие атрибуты пропускаются в runtime, guard:doctor
    | пишет warning.
    */
    'require_permission_attributes' => false,

    /*
    |--------------------------------------------------------------------------
    | Scope (изоляция query-scope)
    |--------------------------------------------------------------------------
    | on_missing_panel — поведение глобального query-scope HasScopedRoles,
    | когда НЕТ активной панели вообще (например, job очереди её не выставил):
    |   'exception' (по умолчанию) — PanelNotSetException (fail-closed).
    |   'empty'                    — запрос не возвращает строк.
    |   'all'                      — применить все scope вне зависимости от
    |                                panel_id (агрегатное до-0.3 поведение) —
    |                                явный opt-out.
    */
    'scope' => [
        'on_missing_panel' => 'exception',
    ],

    /*
    |--------------------------------------------------------------------------
    | Middleware
    |--------------------------------------------------------------------------
    */
    'middleware' => [
        'check_access_alias' => 'check.access',
        'register_middleware_in_appServiceProvider' => false,
    ],

    /*
    |--------------------------------------------------------------------------
    | Кеш
    |--------------------------------------------------------------------------
    | Кеширование прав пользователя между запросами.
    | store: любой store из config/cache.php, либо 'array' — отключает
    |        межзапросное кеширование (по умолчанию, нужно для тестов).
    | expiration_time: TTL в секундах. null — бессрочно, но только для
    |        store'ов 'array'/'null'; на персистентном store AzGuard
    |        откажется загружаться (InvalidCacheConfigException) — иначе
    |        ключ per-user epoch тоже никогда не истечёт.
    */
    'cache' => [
        'store' => 'array',
        'expiration_time' => 3600,
    ],

    /*
    |--------------------------------------------------------------------------
    | Источники грантов
    |--------------------------------------------------------------------------
    | null (по умолчанию) — все встроенные источники активны, отсортированы
    | по GrantPriority. Явный список — сужает набор и порядок:
    |
    |   'grant_sources' => [
    |       \AzGuard\Registry\Sources\ClassRoleGrantSource::class,
    |       \AzGuard\Registry\Sources\DatabaseRoleGrantSource::class,
    |       // Опусти DirectGrantSource, чтобы отключить прямые гранты
    |   ],
    */
    'grant_sources' => null,

    /*
    |--------------------------------------------------------------------------
    | Чистка истёкших прямых грантов
    |--------------------------------------------------------------------------
    | true — регистрирует ежедневную задачу `guard:prune-grants`. По
    | умолчанию выключено — планируй команду сам, если нужен явный контроль.
    | Истёкшие гранты и так никогда не учитываются (их фильтрует scope
    | active()) — чистка только следит за порядком в таблице.
    */
    'prune_expired_daily' => false,

    /*
    |--------------------------------------------------------------------------
    | Фича-флаги
    |--------------------------------------------------------------------------
    | Включай только нужное. Все флаги по умолчанию false (кроме
    | direct_grants) — максимальная обратная совместимость.
    */
    'features' => [
        'wildcard_permission' => false,        // УСТАРЕЛО: true возвращает legacy-грамматику 0.2 ('*' пересекает точки)
        'teams'               => false,        // Мульти-тим / изоляция тенантов
        'audit_log'           => false,        // Событие AccessDecision из Authorizer::explain()
        'direct_grants'       => true,          // Прямые гранты (HasDirectGrants + az_direct_grants)
        'validate_role_permissions' => false,  // Сверять ключи RolePermission с каталогом при saving()
    ],

    /*
    |--------------------------------------------------------------------------
    | Teams
    |--------------------------------------------------------------------------
    | Настройки мульти-тим режима (требует features.teams = true).
    */
    'teams' => [
        'foreign_key' => 'team_id',
    ],

];
```

Исключение из любого `GrantSource::permissionsFor()` прерывает проверку доступа.
Прежний переключатель `fail_on_source_exception=false` больше не поддерживается:
упавший источник нельзя пропустить, пока другой источник разрешает действие.
Удалите ключ из опубликованного конфига и обрабатывайте ожидаемые ошибки источника явно.

::: tip Тесты
Оставь `cache.store` равным `'array'` (значение по умолчанию), чтобы права хранились только в памяти — это предотвращает утечку состояния между тест-кейсами.
:::
