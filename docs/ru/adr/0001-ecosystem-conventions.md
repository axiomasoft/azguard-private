# ADR 0001: Общие правила экосистемы

- **Статус:** Proposed (принят для AzGuard, предложен экосистеме `axiomasoft`)
- **Дата:** 2026-10-01
- **Принимающие решение:** мейнтейнеры AzGuard

## Контекст

Пакеты экосистемы `axiomasoft` решают разные задачи: AzGuard определяет, кто что может, Vaulter хранит файлы.
Разработчик, знающий один пакет, должен быстро разобраться в другом, поэтому пакеты устроены одинаково: одна форма
конфигурации, команд, событий, ошибок и тестовых помощников.

При этом у каждого пакета свои предметные слова. Авторизация и хранение файлов — разные предметы, а навязанный общий
словарь скрыл бы эту разницу.

Этот ADR — копия AzGuard общего текста. Он фиксирует инженерные правила, которым следует AzGuard, и словарь,
которым AzGuard владеет. Остальные пакеты применяют те же правила в своей колонке; Vaulter применяет свою колонку в
своём репозитории. ADR не описывает состояние чужих репозиториев.

## Решение

### 1. Общие инженерные правила

Каждое правило дано один раз как общее и один раз как значение AzGuard.

| Тема | Общее правило | AzGuard |
|:--|:--|:--|
| Установка | Один vendor на всю экосистему: `axiomasoft/<package>` | `axiomasoft/azguard` |
| Версии внутри продукта | Пакеты одного продукта требуют друг друга как `self.version` | `self.version` |
| Конфигурация | Один файл конфигурации на пакет; readonly-объекты `*Config`; проверка при загрузке; `config()` читается только в `Configuration\` | То же |
| Ключи хоста | `<package>.ids.host_keys` принимает `string`, `bigint`, `uuid`, `ulid` | `azguard.ids.host_keys` с теми же значениями |
| Подключение и префикс таблиц | Собственная настройка подключения и короткий префикс таблиц у каждого пакета | `azguard.storages.<имя>.connection`, `table_prefix = 'azg_'` (хранилищ может быть несколько) |
| «От чьего имени» | `ActorRef` и зарезервированный системный тип актора `<package>:system` | `AzGuard::actingAs(...)`, `ActorRef`, `SYSTEM_TYPE = 'azguard:system'`; актор необязателен |
| Конверт события | `eventId` (ULID), `occurredAt`, `actor`, `correlationId`; `EventType` имеет вид `noun.verb_past`; события отправляются после commit | Те же поля плюс `state` (`StateToken`) |
| Ошибки | `<Condition>Exception` с кодом в `snake_case` | То же |
| Команды | `<package>:<area>:<verb>`, `<package>:make:*`, `<package>:doctor --json` | `azguard:<area>:<verb>`, `azguard:make:*`, `azguard:doctor --json` |
| Ключи расширений | `vendor/name` | `vendor/name` |
| Тесты для потребителей | Пространство имён `<Package>\Testing\` и контрактные наборы | `AzGuard\Testing\` и контрактные наборы |
| Ссылки на сущности хоста | Morph alias и id строкой | Morph alias и id строкой (`SubjectRef`, `AssignmentScopeRef`) |

Правила именования — нормативные шаблоны:

- типы событий имеют вид `noun.verb_past`;
- команды имеют вид `azguard:<area>:<verb>`;
- исключения имеют вид `<Condition>Exception` и отдают код в `snake_case`.

### 2. Предметные слова

Слова не подгоняются друг под друга. Если понятие в двух пакетах действительно одно (актор, событие, ключ хоста),
оно одинаково называется и кодируется. Если понятия лишь похожи, у них разные имена.

| Термин AzGuard | Что это | Ближайший термин в экосистеме | Почему это не одно слово |
|:--|:--|:--|:--|
| **Panel** | Конструктор прав части приложения: субъекты, источники, настройки | Profile: набор политик для drives хранилища | Панель описывает *кто и что может*; профиль описывает *как ведёт себя хранилище* |
| **Context** | Сущность, в которой действует право (магазин, проект) | Owner drive, tenant | Контекст выбирает выдачи; владелец или tenant изолирует данные |
| **Permission grant** | Выдача права субъекту напрямую, без роли | Node grant: доступ к узлу дерева | В AzGuard это право на действие; в другом пакете — уровень доступа к файлу или папке |
| **Policy** (второй уровень AzGuard) | Метод политики домена, уточняющий выданное право | Профиль, выбирающий драйвер прав | Разные уровни: в AzGuard одно право, в другом пакете поведение drive |
| **Role**, **Role grant** | Набор прав и его выдача | нет | Пакеты без ролей задают доступ уровнями |

## Последствия

- Фазы AzGuard, вводящие ключи хоста, события и команды, ссылаются на этот ADR и не пересказывают правила.
- Изменение общего правила требует такого же изменения в общем тексте и в колонке каждого пакета; AzGuard не может
  менять своё значение в одиночку и оставаться согласованным.
- Принять общие правила другим пакетам предлагается их владельцам. Отправка ADR им выходит за границы AzGuard и не
  меняет его статус `Proposed` для экосистемы.
- Словарь остаётся локальным. Использование слова AzGuard для другого понятия в другом пакете — дефект того пакета,
  а не этого ADR.
