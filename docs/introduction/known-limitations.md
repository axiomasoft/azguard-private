# AzGuard known limitations (0.3.0) — produced by P3.3

> **Status:** honest catalog of gaps that are **documented, not blockers** — none of these violate the SemVer
> policy (`root/semver-policy.md`) or the `@api` freeze (`root/api-surface.md`); they are named here so they
> don't masquerade as undiscovered bugs. At archival (`/task:plan-close archive`, D26) this file's content moves
> to `docs/introduction/known-limitations.md` (EN+RU).

| # | Limitation | Why it exists | Address |
|:--|:--|:--|:--|
| 1 | Cross-process **race test** for the permission-cache epoch bump is not written yet; the epoch counter also grows unbounded (no reset). `Cache::lock()` already serializes `forget()`→`increment()`→`put()` (T6, closed in TAILS), but no test exercises concurrent processes actually racing. | The test needs a real multi-process harness (`proc_open`), out of scope for the SQLite-only unit/feature suite this plan has run so far. | **`P4.4`** — cross-process race tests (Redis `proc_open`), tail of C-05/T6 in `research/02-backlog.md`. |
| 2 | **Octane `RequestState`** panel-reset is verified within a single process (the `JobProcessing` listener added in P1.3/C-14 resets `currentPanel` symmetrically to the existing Octane listener), but no test runs under an actual Octane worker to confirm the reset survives Octane's persistent-process request boundary. | Requires an Octane test harness; not exercised by the plain PHPUnit/Pest process model used through P1–P3. | **`P4.4`** — Octane `RequestState` test, tail of C-14 in `research/02-backlog.md`. |
| 3 | **Legacy wildcard grammar** (`WildcardPermissionMatcher`, dot-crossing `*`) is only reachable via the deprecated `features.wildcard_permission = true` opt-out flag; the class and flag still ship in 0.3.0. | One-cycle deprecation window (D18) — consumers who relied on the pre-0.3 dot-crossing semantics get exactly one minor release to migrate before it's removed. | **Opt-out for one deprecate cycle** — `WildcardPermissionMatcher` + the flag are removed together in the release *after* 0.3.0. Tracked via `root/semver-policy.md` §3. |
| 4 | **Headless / embedded consumers** get a doc-only minimal-setup path (`docs/introduction/headless-quick-start.md`) — there is no lenient runtime that works with zero registered panels. `guard:doctor` only *hints* at the quick-start when it sees 0 panels; it does not relax any check. | Deliberate: a lenient/panel-less runtime path was evaluated and rejected (D14) — it would weaken the fail-closed default the whole plan is built around (brief/01-refinements.md "maximum reliability, fail-closed, nothing weakened"). | **Doc-only by design** — not a gap to close; see P2.8 Scope Excluded. |
| 5 | The **`@api`/`@internal` snapshot freeze** (P3.2) covers **`packages/core` only**. `filament` has zero class-level `@api`/`@internal`-tagged files; `context` has exactly 2, both tagged only at the method level on wiring constructors, not class-level `@api`. Neither satellite package runs `ApiBoundaryTest`'s reflection convention or the snapshot gate. | The convention (and its enforcement) was built for core first (`ApiBoundaryTest`'s pre-existing boundary); extending it to two more packages is its own scoped item, not a P3.1/P3.2 side effect. | **Unscheduled follow-up** — extend the `@api` convention + a satellite snapshot to `filament`/`context` (candidate post-0.3.0 item; `root/api-surface.md` §8). |
| 6 | **`Attributes/*`** (`CheckPermission`, `GuardPolicy`, `GateAbility`, `SkipGuardCheck`, `RoleOnly`) are documented, consumer-facing PHP attributes but carry no `@api` tag — they sit outside the snapshot's unit of freeze entirely. | Pre-dates P2.1 (never lived in the old `Support/` catch-all); a pre-existing tagging-hygiene gap, not something P3.1's cut-line touched (`root/api-surface.md` §8). | **Unscheduled follow-up** — candidate for `@api`-tagging in a future doc/tagging-hygiene pass. |
| 7 | **`Testing\AzGuardFake`** is `@api`-tagged and its full delegated `AzGuardManagerInterface` surface is therefore frozen by the snapshot — including passthrough methods that carry **no** method-level `@internal` on the fake itself (`grant`/`revoke`/`grants`/`isSuperAdmin`/`tryPermission`/`panelIdForPermission`), even though the same methods are `@internal` on the real manager/facade. | The fake mirrors the interface it implements; nobody has yet decided whether that asymmetry is noise worth trimming (P3.2 Pending Work). | **Unscheduled follow-up** — if judged noisy, close via a `D#` + method-level `@internal` tags on the fake, **not** by weakening the snapshot gate itself. |
| 8 | `AzGuard::fake()`'s recording (`GrantGiven`/`GrantRevoked` event listeners + `Gate::after()`) is suppressed if the same test also calls a blanket `Event::fake()` — the fake's own listeners stop firing, so `assertGranted()`/`assertDenied()` silently see nothing. Not yet called out in `docs/advanced/testing.md`. | `AzGuardFake` observes real dispatch rather than replacing it (P2.6 design) — that's precisely what a global `Event::fake()` in the same test defeats. Genuine interaction gotcha, not a bug. | **Doc-only follow-up** — add an explicit caveat to `docs/advanced/testing.md`'s `AzGuard::fake()` section (not yet written; noted here per handoff Open risks). |
| 9 | `HasScopedRoles::removeScopedRoleEverywhere()` is `public` on the trait but **absent from** the `@api` contract `Contracts\HasScopedRoles` (found by the reverse-parity check added in P1.3/D-03, allow-listed there with an explicit reason). | Adding it to the interface now would be a breaking interface-addition — every manual implementer of the contract would be forced to add the method (§2.5 of `root/semver-policy.md`). | **Unscheduled follow-up** — candidate for a contract review (originally flagged for P2, not picked up; `phases/P1.md` P1.3 Pending Work). |
| 10 | The MySQL-specific branch of migration `2026_01_01_000005_add_unique_constraints_to_model_has_roles_and_scopes.php` (functional/prefixed unique-key parts, InnoDB 3072-byte limit workaround) and the context migration `2026_01_01_000011_add_expires_at_to_az_guard_context_roles_table.php` have only been exercised on the SQLite test lane so far. | This plan's P1–P3 test runs use the fast SQLite `:memory:` lane; the multi-database matrix is a P4 deliverable, not yet executed. | **`P4.2`** (DB matrix) / **`P4.7`** (MySQL collation hardening) — both migrations get their MySQL-branch coverage there (`plan.md` D24). |
| 11 | `tests/Unit/Support/` (5 test files) still carries the pre-canon directory name after the `AzGuard\Support` namespace was dissolved into domain namespaces (P2.1) — the tests themselves were relocated by reference, only the containing directory's name drifted from the new canon. | Out of `Files` for every P2 item that touched this area (P2.1, P2.10) — a cosmetic rename, not a contract change. | **Unscheduled follow-up** — candidate directory rename, no functional impact (`phases/P2.md` P2.1 Pending Work). |
| 12 | `composer check:coverage` reports an **honest skip** — no coverage driver (Xdebug/PCOV) is installed in the environment these plan sessions ran in, so line-coverage thresholds cannot be enforced locally. | Pre-existing local-environment gap, unrelated to any code produced by this plan. | **Unscheduled / CI-side** — CI environments that install a coverage driver are unaffected; local `composer check` reports the skip rather than a false pass. |
