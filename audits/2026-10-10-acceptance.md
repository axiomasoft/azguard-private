# Приёмка hardening: 2026-10-10

**Вердикт: принимать после внесённых исправлений.** Концептуальных причин отклонять схему ядра не обнаружено.
Исходный кандидат: `review/v1-hardening`, `99b8f591`. Исправления находятся в `review/acceptance-0.7.0`.
`main`, исходная ветка и удалённые refs не изменены. Реструктуризация ядра и границ пакетов остаётся отдельной задачей.

## Архитектурное решение

- Согласованность базы обеспечивается снимком состояния и грантов на одном физическом PDO. Разные логические
  хранилища на этом PDO сохраняют свои таблицы, но разделяют снимок. Разные PDO, включая primary/replica,
  не образуют общий снимок. `Reads::Primary` даёт свежие чтения; `Reads::Default` допускает задержку реплики.
- Ревизия субъекта вместе с epoch панели — подходящая граница кэша. Обычная запись меняет ревизию субъекта;
  изменения общего состояния меняют epoch. Блокировку строки панели при записи следует сохранить:
  усложнять её до блокировок субъектов без измеренного узкого места сейчас не нужно.
- Модель, переданная вызывающим кодом, сохраняет собственные атрибуты. Совпадение primary key не делает
  разные экземпляры взаимозаменяемыми для политик и eligibility-фильтров.
- Типизированные failures и опциональное HTTP-отображение 403/503/500 обоснованы. Ошибки чтения и нарушения
  контрактов не должны превращаться в разрешение. Лимит DecisionSet должен отказать целиком, без скрытого дробления.
- Публичный API ядра остаётся границей Filament. Для принятия hardening новая разбивка на пакеты не требуется.

## Проверки, чистота и передача

Ранее CI/скрипты допускали skipped tests, MariaDB исключала engine suite, API check отсутствовал в общей
команде. Это исправлено (`0e1d90f`); неуспешный mutation-runner больше не превращается в успешный гейт.
В исходной ветке добавлены/расширены исключения Rector для сохранения API, readonly/clone-контрактов и стиля;
обоснованные исключения оставлены. PHPStan, пороги покрытия и mutation, набор исключённых mutation-директорий
не ослаблены. Новых baseline, phpstan-ignore или skipped tests не добавлено.

Служебные файлы восстановлены локально и игнорируются. Planning artifacts и agent logs исключены из
деревьев коммитов кандидата; это убрало 4 JWT-находки исторического gitleaks. История до очистки сохранена
в локальной `review/acceptance-original-history-0.7.0`. История `main` не переписывалась.

### Актуальное решение владельца — 2026-10-10

Концептуальная приёмка завершена; существенные ошибки исправлены. Первый публичный релиз — 0.7.0,
API может изменяться до 1.0. Mutation отложен владельцем на этапе нестабильного API и больше не блокирует
приёмку, фиксацию или релиз 0.7.0. Исторические неуспешные запуски выше остаются неуспешными;
mutation-score не получен. Новый запуск mutation для этой подготовки не требуется.

`composer check` исключает mutation; отдельные команды и пороги сохранены. Mutation workflow запускается
только вручную. Compatibility patch mutation-runner не развивается; его дальнейшая проверка — отдельная задача.
Остальные обязательные проверки, тесты, PHPStan и пороги не ослабляются.

Release workflow теперь требует успешного split обеих частей (`de32590`); для публикации владельцу нужно
настроить `SPLIT_ENABLED=true` и `MONOREPO_SPLIT_TOKEN`, которых при проверке не было.

**Нужно обсудить:** новых концептуальных решений для принятия этой ветки нет.
Перестройка ядра, разделение на пакеты и замена блокировки панели относятся к последующей стабилизации.
