# R02 — Многослойный контроль backward compatibility

**Статус:** предварительный Perplexity synthesis, сохранён из этой сессии. Вопрос сформулирован на уровне области, без точных фрагментов текущего кода. Советы о локальном AzGuard использовать только после сверки с [репозиторием](../repository-inventory.json) и [первичными источниками](../primary-sources.md). Пересечения с другими темами смотрите в [карте исследования](../README.md).

## Исходный вопрос

PHP library backward compatibility beyond reflection method snapshots: default argument VALUES, named parameters, inheritance, traits, enums, readonly/final, interfaces, event payloads, config, CLI and database schema. Explain precisely Roave BackwardCompatibilityCheck coverage and limitations, semantic snapshots and consumer contract fixtures. Practical minimum CI for Laravel package.

## Ответ Perplexity

Краткий вывод. Для библиотеки авторизации на PHP 8.3+ Roave BackwardCompatibilityCheck (Roave BC Check) полезен как автоматический контроль структурных изменений публичного PHP API, но его недостаточно считать полным тестом совместимости трёх Composer-пакетов. Отдельно следует фиксировать семантику API и проверять интеграционные контракты: конфигурацию, события, команды и схему БД. Это исследовательская оценка по публичной документации; к частному репозиторию доступа не было и его состояние здесь не проверялось.

## Что покрывает Roave — и где предел

Документированные факты. Roave сравнивает API двух ревизий; обычный CI-вызов может сравнить текущий HEAD с последним минорным тегом SemVer, а найденные нарушения приводят к ненулевому коду завершения. Условия для типового сценария включают Git, Composer и autoload-пути, покрывающие исходники; незакоммиченные изменения не попадут в сравнение. Это делает выбор базовой ревизии и охват исходников частью надёжности проверки.
История релизов показывает, что охват развивается: релиз 8.8.0 добавил выявление изменений enum и добавления enum-case; 8.9.0 — проверку добавления параметра в метод. Поэтому нельзя без проверки закреплённой версии инструмента считать, что все интересующие виды изменений уже выявляются.
PHP делает имена параметров частью фактически доступного контракта: именованные аргументы появились в PHP 8, а документация отдельно предупреждает, что реализации интерфейсов могут иметь другие имена параметров — технически допустимо, но опасно для вызовов с named arguments. Laravel сам исключает именованные аргументы из своей гарантии обратной совместимости. Это полезный сигнал: политика пакета должна быть собственной и явной.
Ограничение вывода: доступный официальный README конкретной версии не удалось извлечь полностью. Поэтому ниже не утверждается, что Roave гарантированно проверяет каждую категорию в любой версии. До внедрения следует сверить точную версию и её правила на искусственных парах «до/после», в том числе для default values, readonly и final.

## Семантические snapshots и fixtures

Архитектурный вывод. Снимок контракта должен отражать не только имена и типы, но и публичные значения: сериализованное событие, конфигурацию после слияния с defaults, сигнатуры команд и ожидаемые таблицы/индексы. Проверка должна сравнивать снимок с закоммиченным baseline; изменения — требовать осознанного обновления и объяснения.
Consumer fixtures — минимальные проекты/тесты, которые употребляют пакеты так, как это делает клиент: named arguments, наследование, собственная реализация интерфейса, event listener, опубликованный config и запуск команды. Для трёх пакетов проверять отдельно: каждый пакет как устанавливаемый Composer-потребитель и согласованность их версий/зависимостей.

## Практический минимум CI

- Roave BC Check для каждого пакета, сравнение с явно выбранным релизным тегом; закрепить версию инструмента и проверить охват autoload.
- PHPUnit/Pest на минимальном и актуальном поддерживаемом PHP; интеграционная матрица Laravel 11/12/13 только там, где Composer constraints это допускают. Laravel 13 требует PHP 8.3; Laravel 11 указан как PHP 8.2–8.4, Laravel 12 — 8.2–8.5. Сверять constraints, не выводить поддержку лишь из этих диапазонов.
- Статический анализ и проверка Composer-метаданных/установки пакетов.
- Consumer contract fixtures для API, событий, config и CLI; миграционный upgrade-тест на поддерживаемом драйвере БД.
- Отдельные тесты инвариантов ревизионного fence и кэш-конвертов, включая истечение и смену поколения.
Laravel рекомендует Testbench для тестирования пакета как в типичном приложении, а официальный пакетный skeleton включает Pest, Larastan, Pint и workbench. Это хорошая отправная точка, но не заменяет перечисленные контракты.

## Нерешённые пробелы

Публичные источники не позволяют установить версию Roave в проекте, фактический API, конкретные DB-драйверы, обещания совместимости каждого из трёх пакетов или наличие опубликованных config/migrations. Перед решением о CI нужно подтвердить эти данные в репозитории; сейчас это обозначенные вопросы аудита, не выводы о его реализации.
