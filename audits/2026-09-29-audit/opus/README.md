## Главное в десяти строках

1. **Сначала безопасность (F1, T0-патч 0.3.N):** class-роль с `*` — superadmin во всех панелях (N01), Filament пишет
   произвольный `class_name` роли и не знает делегирования (N02), Gate игнорирует настроенный resolver (N03),
   «изоляция» `HasScopedRoles` открыта в очереди и ломается на двух назначениях (N04), межзапросная утечка через
   коллизию контекста (C01 → P07). Все воспроизведены probes.
2. **Ключ права всегда квалифицирован**, realm берётся из ключа: исчезают четыре правила выбора панели, ambient
   «текущая панель» и поломка моста Vaulter (N05, N09).
3. **Словарь без коллизий**: Panel → **Realm** (как Panel → Profile в Vaulter из-за Filament), `GrantSource` →
   **PermissionSource**, DirectGrant/ContextRole → **Grant**, model_has_roles/scopes → **RoleAssignment**,
   Subject/Actor — как в Vaulter.
4. **Одна модель назначений** (роль или право × субъект × контекст × срок × актор) вместо четырёх таблиц; в
   идентичности нет NULL → уходят ~1100 строк driver-специфичного DDL, требования к СУБД снижаются.
5. **Контекст — измерение назначения** с политикой на realm (`inherit`/`isolated`/`required`/`none`); членство в
   tenant — отдельный обязательный constraint, а не побочный эффект стратегии.
6. **Алгебра решения явная**: вклады источников ∪ → обязательные constraints ∧ → superadmin как политика с радиусом,
   а не значение `*`; один `Decision` с причиной для Gate, модели, CLI и `decideMany`.
7. **Запись только через `AccessManager` с актором** (`actingAs`/`asSystem`, как Vaulter): делегирование без
   эскалации, одна транзакция «строки + ревизия + аудит», события после commit.
8. **Консистентность обещана словами**: чтения с primary, ревизия раз в lifecycle, дословная гарантия отзыва;
   горячий путь — 0 запросов на повторную проверку.
9. **Пакеты**: `axioma-studio/azguard` (core + context) и `azguard-filament`, lockstep, граница API — namespace +
   машинный манифест, без тегов на 150 классах.
10. **Экосистема**: общий ADR конвенций с Vaulter (actor, host keys, конфиг, события, команды, doctor, testing kit),
    мост `vaulter-azguard` на `decideMany` и квалифицированных ключах; путь 0.3.N → 0.4.0 → 0.9.0 → 1.0.0.

## Отличия от предыдущих проходов

- **От аудита Perplexity:** не размечаю 150 классов тегами (граница — namespace + манифест); не делаю context
  plugin-API, а сливаю его в ядро; не ввожу два типа строк прав; беру префикс `azg_`, но главное — меняю саму схему
  назначений; исправляю факты, которые Codex уже опроверг (unknown abilities, context в ключе кэша).
- **От Codex:** принимаю рамку «семантика раньше раскладки» и почти все C-находки, но довожу до решений и имён;
  выбираю B **внутри одного дистрибутива** без store-порта в 1.0; C01 довожу до межзапросной утечки (P07); нахожу
  N01–N04, которые меняют порядок работ (T0-патч до канона).

## Границы этого прохода

- Прочитаны все исходники трёх пакетов, миграции, конфиги, стабы, выборочно тесты и документация; мост Vaulter и
  решения Vaulter — для согласования.
- **Запускались:** существующий набор тестов (871 зелёный, SQLite) и 19 probes (все воспроизводят дефекты) —
  см. [evidence](evidence/README.md). Зависимости ставились из git без rector/phpstan/larastan (загрузка zip с GitHub
  закрыта политикой egress окружения) — на тесты и probes это не влияет; PHPStan/Rector не запускались.
- **Не запускались:** PostgreSQL/MySQL, реплики, Redis, Octane, конкурентные сценарии, Filament-UI в браузере —
  для них сценарии в [14](14-verification.md).
- Код пакетов и Vaulter **не менялся**; probes лежат в `evidence/`, не в `tests/`.
- Связь с mAInd из контейнера не проверена (`maind` не установлен) — [Q17](15-owner-questions.md).

5. Пункты E2/E4/E5 из [10 §4](10-ecosystem-vaulter.md#4-порядок-релизов-и-действия-по-репозиториям) — отдельной
   задачей в план Vaulter.
