# 15 — Вопросы владельцу

## Ответы третьего прохода

| # | Вопрос | Ответ владельца | Что сделано | Где |
|---|---|---|---|---|
| Q1 | Слово: Panel или Guard? | «Panel или Guard» | **Рекомендую Panel.** В Laravel guard — способ входа, и на одном guard'е `web` живут несколько панелей (кабинет, кабинет продавца); `->guard('web')` внутри guard'а `cabinet` путал бы всех. Если выберете Guard — это механическая замена имён | [D04](02-decisions.md#d04) |
| Q2 | Слить `azguard-context` в ядро? | да, если архитектурно правильнее | слито: доступ внутри сущности — базовая возможность | [D03](02-decisions.md#d03) |
| Q3 | Трейт модели — только чтение? | нужно управление из сущности; сущностью может быть не только пользователь; у модели несколько панелей и одна по умолчанию; синтаксис как в Spatie | трейт `HasAzGuard` на любой модели: проверки и изменения с именами Spatie, `inPanel()`, панель по умолчанию, все панели субъекта в одном наборе | [D10](02-decisions.md#d10), [D11](02-decisions.md#d11) |
| Q4 | Gate authoritative? | выбрать лучшее по философии | authoritative для прав панели: политики и Gate — механики внутри панели, поэтому второго пути решения нет; `additive` — настройка панели | [D26](02-decisions.md#d26) |
| Q5 | Чтения с primary? | выбрать лучшее | primary по умолчанию (одна дешёвая выборка версии на запрос, отзыв не зависит от реплики); настраивается на панели | [D24](02-decisions.md#d24) |
| Q6 | Версия раз в запрос? | принято по умолчанию | да (`state_refresh = request`) | [D24](02-decisions.md#d24) |
| Q7 | Имена прав в нижнем регистре? | принято по умолчанию | да (`view_any`) | [D18](02-decisions.md#d18) |
| Q8, Q9 | Имя пакета и публичный репозиторий | `axiomasoft/azguard` | `axiomasoft/azguard`, `axiomasoft/azguard-filament`, `github.com/axiomasoft/azguard` | [D03](02-decisions.md#d03) |
| Q10 | Глобальный суперадмин? | не нужен: суперадмин — обычный пользователь, для которого любая проверка «да», плюс `isSuperAdmin()` | правило суперадмина на панели; для всех панелей — `defaults.super_admin` или `configurePanels()` | [D19](02-decisions.md#d19) |
| Q11 | Членство в сущности — по желанию? | да, важна гибкость | необязательное ограничение; членство задаётся связью, классом или замыканием | [D15](02-decisions.md#d15) |
| Q12 | Явные запрещающие выдачи? | не вводим | запрет — ограничением или хуком | [D17](02-decisions.md#d17) |
| Q13 | Мост Vaulter | отдельная задача Vaulter; описать идею | идея моста описана | [10 §9](10-integrations.md#9-идея-моста-vaulter--azguard) |
| Q14 | Прямые записи моделей: исключение в local/testing, предупреждение в production? | да | так | [D22](02-decisions.md#d22) |
| Q15 | Снизить требования к СУБД? | да, при зелёной CI-матрице | PG 13+, MySQL 8.0+/MariaDB 10.6+, SQLite 3.35+ | [08 §2](08-data-model-and-migration.md#2-схема-хранилища) |
| Q16 | Патч 0.3 до новой версии? | не нужен: пакет не в работе, делаем сразу правильно | патча, миграции данных и нормализатора нет; находки — регрессионные тесты | [D01](02-decisions.md#d01) |
| Q17 | mAInd | игнорировать | убрано из досье | — |
| Q18 | Встроенные возможности отключаемы? | всё настраивается для каждой панели; одна панель на БД, другая на жёстких правилах в классах; перестраивается в любой момент | панель — конструктор механик; код проверок не зависит от механики | [D52](02-decisions.md#d52), [D45](02-decisions.md#d45) |
| Q19 | Хранилище по умолчанию | по умолчанию | общее хранилище `azg_*` с колонкой `panel` | [D34](02-decisions.md#d34) |
| Q20 | Кто управляет правами другой панели | задача панели — дать схему заполнения прав; редактирование — отдельные интерфейсы; при правах из политик вопрос не встаёт | `administeredBy`, мета-права и делегирование убраны; добавлена схема панели для интерфейсов | [D23](02-decisions.md#d23), [D54](02-decisions.md#d54) |
| Q21 | Подтверждение изменений в ядре? | не нужно думать об администраторах; нужен надёжный конструктор ролевой системы и хуки | подтверждения и делегирование — рецепты на хуках, не ядро; добавлены хуки проверки и изменений | [D49](02-decisions.md#d49), [D55](02-decisions.md#d55) |
| Q22 | `meta` (JSON) для своих полей? | да, nullable, архитектурно правильно | `meta` nullable; поле описывается в модели; для фильтров и больших объёмов — колонка; doctor предупреждает | [D46](02-decisions.md#d46) |

## Открытые вопросы

У каждого — решение по умолчанию: без ответа план исполняется с ним.

| # | Вопрос | По умолчанию | Если ответ другой | Решение |
|---|---|---|---|---|
| Q23 | Vendor в Composer: AzGuard — `axiomasoft/*`, Vaulter — `axioma-studio/*`. Выравнивать? | оставить как есть; разница записана в ADR экосистемы | перевести один из продуктов на vendor другого (затронет интеграции и документацию) | [10 §8.1](10-integrations.md#81-общие-инженерные-правила-adr-ecosystem-conventions-один-текст-в-репозиториях-экосистемы) |
| Q24 | Имена методов трейта — как в Spatie (`givePermissionTo`, `hasPermissionTo`, `removeRole`)? | да | короткие (`givePermission`, `hasPermission`); переход со Spatie станет менее прямым | [D10](02-decisions.md#d10) |
| Q25 | Локальное имя права — минимум два сегмента (`orders.view`), чтобы не перехватывать Laravel-abilities `view`/`update`? | да | разрешить одно слово; тогда нужен явный список «наших» abilities для Gate | [D05](02-decisions.md#d05) |
| Q26 | Панель маршрута (middleware) важнее панели по умолчанию? | да: внутри маршрутов кабинета продавца короткие имена относятся к нему | всегда панель по умолчанию, другие — только явно (строже, но длиннее код в каждой панели) | [09 §1](09-authorization-semantics.md#1-как-выбирается-панель) |
| Q27 | Право, которое решает политика, можно ли по умолчанию выдавать через БД? | нельзя; можно включить `#[Decides(..., assignable: true)]` | можно всегда: выдача из админки обойдёт логику политики | [D53](02-decisions.md#d53) |
| Q28 | Суперадмин проходит и ограничения (блокировка, членство)? | да — «всё имеет» | ограничения действуют и для суперадмина (тогда нужен флаг «обходит» на каждом ограничении) | [D19](02-decisions.md#d19) |
| Q29 | Автопоиск политик в папке (`discoverPolicies`) — оставить рядом с явным списком? | да, результат кэшируется `azguard:catalog:cache` | только явный список `->policies(...)` | [D53](02-decisions.md#d53) |
