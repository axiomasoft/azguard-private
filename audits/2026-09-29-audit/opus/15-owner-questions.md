# 15 — Вопросы владельцу

Каждый вопрос имеет **решение по умолчанию**: если ответа нет, план исполняется с ним. Вопросы упорядочены по влиянию
на порядок работ.

| # | Вопрос | По умолчанию | Если ответ другой | Решение |
|---|---|---|---|---|
| Q1 | Слово для бывшей «панели»: **Realm** или **Area**? | Realm | меняется только словарь (03) и имена классов/ключей конфига; семантика та же | [D04](02-decisions.md#d04), [D06](02-decisions.md#d06) |
| Q2 | Сливать `azguard-context` в core? | да | придётся спроектировать SPI контекстного слоя под единственного потребителя; D13/D15 усложняются (две таблицы назначений) | [D03](02-decisions.md#d03) |
| Q3 | Убрать запись из host-модели (`$user->assignRole()` и т. п.)? | да, только `AzGuard::access()` | оставить тонкие шорткаты, делегирующие в `AccessManager::asSystem('model: …')` с явным предупреждением в docs, что они обходят делегирование | [D10](02-decisions.md#d10) |
| Q4 | Gate по умолчанию authoritative (своя ability без гранта → `false`)? | да | `additive` по умолчанию; генерация политик остаётся нужной, N19 не закрыт | [D26](02-decisions.md#d26) |
| Q5 | Чтения авторизации по умолчанию с primary? | да (`reads = primary`) | `default` + документированное окно устаревания при репликах | [D24](02-decisions.md#d24) |
| Q6 | Ревизия читается раз в request/job (`state_refresh = request`)? | да | `check`: строже, +1 запрос на каждую проверку (как сейчас) | [D24](02-decisions.md#d24) |
| Q7 | Ключи прав только в нижнем регистре (`view_any`, а не `viewAny`)? | да | разрешить регистр, но тогда collation-зависимость и нормализация при сравнении во всех хранилищах | [D18](02-decisions.md#d18) |
| Q8 | Переименовать Composer-пакет в `axioma-studio/azguard`? | да | оставить `azguard-core`; Vaulter-мост требует `azguard-core` | [D03](02-decisions.md#d03) |
| Q9 | Какой репозиторий публичный (`composer.json` `homepage`, docs, ссылка «Star on GitHub»)? Сейчас `axioma-studio/azguard`, код — `axiomasoft/azguard-private` | неизвестно → ссылки убираются до ответа | подставить верный URL | [D40](02-decisions.md#d40) |
| Q10 | Платформенный superadmin (`*:superadmin`, все realm) включён по умолчанию? | да (совместимость с `guard:super-admin`) | выключен; superadmin только в пределах realm | [D19](02-decisions.md#d19) |
| Q11 | Членство в контексте — opt-in на realm? | opt-in + doctor warning для `inherit` без членства | обязательное членство для всех контекстных realm (строже, требует `ContextMembership` у каждого хоста) | [D15](02-decisions.md#d15) |
| Q12 | Явные deny-правила в 1.0 не вводим (запрет — только constraint)? | не вводим | добавить `azg_denies` и deny-override — отдельная спецификация алгебры и UI | [D17](02-decisions.md#d17) |
| Q13 | Vaulter переименовывает мост `azgard` → `azguard`? (решение владельца Vaulter) | да, в окне канона Vaulter 0.3 | мост остаётся `azgard`; расхождение фиксируется в ADR конвенций | [D43](02-decisions.md#d43) |
| Q14 | Прямые записи моделей AzGuard: исключение в local/testing, warning в production? | да | всегда исключение (строже, ломает хосты с сидерами на моделях) / только warning | [D22](02-decisions.md#d22) |
| Q15 | Понизить требования к СУБД (PG 13+, MySQL 8.0+, MariaDB 10.6+) после ухода NULL из идентичности? | да, при зелёной CI-матрице | оставить текущие (PG 16+, MySQL 8.0.13+, без MariaDB) | [08 §1](08-data-model-and-migration.md#1-схема-04-префикс-azg_) |
| Q16 | T0-патч 0.3.N выпускаем до канона, даже если он меняет поведение (N01: class-роль с `*` перестаёт действовать в чужих панелях)? | да, с разделом «Security» в CHANGELOG | только в 0.4 (пользователи 0.3 остаются уязвимыми) | [D01](02-decisions.md#d01), F1 |
| Q17 | Связь с mAInd из этого контейнера не проверена (`maind` не установлен). Синхронизировать память/граф этой сессии из рабочего окружения? | да, владелец запускает `maind health --cwd` и заносит решения D01–D44 | — | — |
