# 15 — Вопросы владельцу

У каждого вопроса есть **решение по умолчанию**: если ответа нет, план исполняется с ним. Вопросы упорядочены по
влиянию на порядок работ.

## Уже решено

| # | Вопрос | Ответ | Где отражено |
|---|---|---|---|
| Q1 | Переименовывать «панель» (Realm/Area)? | **Нет.** Панель остаётся главным понятием: несколько независимых панелей в одном приложении, у каждой свои настройки, хранилище, модели, плагины | [D04](02-decisions.md#d04), [D06](02-decisions.md#d06), [00](00-overview.md) |
| Q13 | Мост Vaulter — чья работа? | **Vaulter.** AzGuard даёт стабильный контракт интеграции для Vaulter и других пакетов; заметки по текущему мосту передаются Vaulter | [D43](02-decisions.md#d43), [D51](02-decisions.md#d51), [10](10-integrations.md) |

## Открытые вопросы

| # | Вопрос | По умолчанию | Если ответ другой | Решение |
|---|---|---|---|---|
| Q2 | Слить `azguard-context` в ядро (как встроенный плагин `azguard/contexts`)? | да | отдельный пакет должен был бы опираться только на разъёмы плагинов; это возможно, но вторая установка и второй релизный цикл ради одного плагина | [D03](02-decisions.md#d03) |
| Q18 | Встроенные возможности (роли, прямые права, контексты, суперадмин, мета-права, аудит) — отключаемые плагины панели? | да; все, кроме аудита, включены по умолчанию | зашить их в ядро: проще код, но API-панель без ролей или сайт без прямых прав станут невозможны без обходов | [D47](02-decisions.md#d47) |
| Q19 | Где хранятся данные панелей по умолчанию? | в общем хранилище `default` (таблицы `azg_*`, колонка `panel`); отдельное хранилище — по желанию на панель | всегда отдельные таблицы на панель: полная изоляция, но больше миграций и таблиц у хостов с многими панелями | [D46](02-decisions.md#d46) |
| Q20 | Кто управляет правами панели, чьи субъекты — не сотрудники (например, `site`)? | только явно: `site->administeredBy('admin')`; по умолчанию панель администрирует сама себя | Filament-админка автоматически администрирует все панели из `manages` — удобнее, но неявное право одной панели над другой | [D23](02-decisions.md#d23), [11 §2](11-filament.md#2-плагин) |
| Q21 | Подтверждение изменений вторым администратором: в ядре только разъём и статус `pending` или готовый плагин? | в 0.4 — разъём, статус, событие и пример плагина в документации; готовый плагин — позже | готовый встроенный плагин в 0.4: +таблица, +UI, +объём работ F6/F8 | [D49](02-decisions.md#d49) |
| Q22 | Колонка `meta` (JSON) во всех таблицах хранилища — для своих полей без миграций? | да, nullable | только настоящие колонки: строже, но каждое поле требует миграции | [D46](02-decisions.md#d46) |
| Q3 | Убрать запись из host-модели (`$user->assignRole()` и т. п.)? | да, только `AzGuard::panel($id)->manage()` | оставить тонкие ярлыки, делегирующие в менеджер доступа `asSystem('model: …')`, с предупреждением в docs, что они обходят делегирование | [D10](02-decisions.md#d10) |
| Q4 | Gate по умолчанию authoritative (своя ability без права → `false`)? | да, настраивается на панели | `additive` по умолчанию; генерация политик остаётся нужной, N19 не закрыт | [D26](02-decisions.md#d26) |
| Q5 | Чтения авторизации по умолчанию с primary? | да (`reads = primary`) | `default` + документированное окно устаревания при репликах | [D24](02-decisions.md#d24) |
| Q6 | Версия состояния читается раз в request/job (`state_refresh = request`)? | да | `check`: строже, +1 запрос на каждую проверку (как сейчас) | [D24](02-decisions.md#d24) |
| Q7 | Ключи прав только в нижнем регистре (`view_any`, а не `viewAny`)? | да | разрешить регистр: зависимость от collation и нормализация при сравнении во всех хранилищах | [D18](02-decisions.md#d18) |
| Q8 | Переименовать Composer-пакет в `axioma-studio/azguard`? | да | оставить `azguard-core` | [D03](02-decisions.md#d03) |
| Q9 | Какой репозиторий публичный (`homepage`, docs, ссылка «Star on GitHub»)? Сейчас `axioma-studio/azguard`, код — `axiomasoft/azguard-private` | неизвестно → ссылки убираются до ответа | подставить верный URL | [D40](02-decisions.md#d40) |
| Q10 | Во что превращается `super-admin` 0.3 при обновлении? | в роль `{panel}:superadmin` в каждой панели (назначения дублируются) | `--superadmin=global-plugin`: подключить `GlobalSuperadminPlugin` к панелям с перечнем субъектов | [D19](02-decisions.md#d19), [08 §6](08-data-model-and-migration.md#6-upgrade-03x--040) |
| Q11 | Членство в контексте — включается на панели по желанию? | да + doctor-предупреждение для `inherit` без членства | обязательное членство для всех панелей с контекстами: строже, требует `ContextMembership` у каждого хоста | [D15](02-decisions.md#d15) |
| Q12 | Явные запрещающие выдачи в 1.0 не вводим (запрет — только ограничением)? | не вводим | добавить таблицу запретов и правило «запрет сильнее» — отдельная спецификация алгебры и UI | [D17](02-decisions.md#d17) |
| Q14 | Прямые записи моделей AzGuard: исключение в local/testing, warning в production? | да | всегда исключение (строже, ломает хосты с сидерами на моделях) или только warning | [D22](02-decisions.md#d22) |
