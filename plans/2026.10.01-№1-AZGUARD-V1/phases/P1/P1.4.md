### P1.4 — Arch-правила зон

**Intent:** Сделать зоны ядра проверяемыми: блокирующий arch-набор по таблице 04 §2 и машинный манифест публичного API D12 в обоих пакетах, чтобы незаметно нарушить зависимость или изменить `@api`/`@spi`-контракт было нельзя.
**Why:** RAG:— 04 §2 (зоны и arch-правила, блокирующие в CI), 04 §7 (Panel readonly value допустим в SPI; `Sources\Database` — явное исключение), D02 (ядро понятий в центре), D12 (`@api`/`@spi` по расположению и тегу; `api-manifest.json` сравнивается в CI), D6 п.4 (публичность вне перечня D12 — только тегом); целевой инвариант 7 плана.
**Scope Included:** `tests/Arch/ZonesArchTest.php` — правила, выразимые сейчас: (a) `AzGuard\Kernel` не использует `Illuminate`, `Carbon`, `Laravel`, функции `app`, `config`, `now`, `today`, `env`, `resolve`, `request`, `auth`, `cache`, `event`, `logger`, `info`, и зоны `AzGuard\{Contracts,Panels,Catalog,Scopes,Sources,Policies,Authorization,Changes,Schema,Storage,Plugins,Laravel,Testing,Roles,Configuration,Diagnostics,Internal,Facades,Concerns,Events}`; (b) `AzGuard\Exceptions` не использует `Illuminate` и никакие зоны, кроме Kernel; (c) `AzGuard\Contracts` не использует реализации `AzGuard\{Authorization,Changes,Storage,Sources,Laravel,Internal,Testing,Diagnostics,Configuration}`; (d) `AzGuard\{Authorization,Schema}` не используют `AzGuard\Changes`; (e) `AzGuard\{Panels,Catalog,Scopes,Policies,Schema}` не используют `AzGuard\{Storage,Changes}`; `AzGuard\Sources` не использует `AzGuard\{Changes,Authorization}`; `AzGuard\Storage` не использует `AzGuard\{Authorization,Changes}`; `AzGuard\Roles` не использует `AzGuard\{Storage,Changes,Authorization}`; (f) `Illuminate\Support\Facades\DB`, `Illuminate\Support\Facades\Schema`, `Illuminate\Database\Connection`, `Illuminate\Database\ConnectionInterface`, `Illuminate\Database\Schema` используются только в `AzGuard\Storage` и `AzGuard\Sources\Database`; (g) `AzGuard\Sources` (кроме `AzGuard\Sources\Database`) и `AzGuard\Plugins` не используют `AzGuard\Storage`; (h) `AzGuard\Contracts\Sources\StoresGrants` используется только в `AzGuard\Changes\ChangePipeline`, `AzGuard\Sources\Database`, `AzGuard\Testing`; (i) production-код `AzGuard` и `AzGuard\Filament` не использует `AzGuard\Testing`; (j) `AzGuard\Plugins` не использует `AzGuard\Internal`. `tests/Arch/SourceConventionsTest.php` — сканирование текста `packages/*/src`: `config('azguard` только в `src/Configuration/`; внутренние коды задач (`PLAN\d+`, `P\d+\.\d+`, `[CDNQRV]-?\d{2,3}\b`, `F\d{2}\b`) в комментариях запрещены; каждый класс/интерфейс/enum в `Contracts/` имеет тег `@api` или `@spi`. `bin/api-manifest.php` (`--write`, `--check`) и `packages/core/api-manifest.json`, `packages/filament/api-manifest.json`; `tests/Arch/ApiManifestTest.php`: манифест актуален и `AzGuard\Filament` ссылается только на классы ядра из манифеста. Composer-скрипты `api:manifest`, `api:check`.
**Scope Excluded:** правило «все входы выбирают панель через `PanelResolver`» (вводит P2.2 вместе с resolver); правило «писать выдачи может только `StoresGrants`» сверх (h) — семантика пишущего пути (P3.4/P5.2); snapshot DDL/events/config/commands (owning items P3–P6); удаление старых имён (P6.9).

**Implementation Rules:** Правила для ещё пустых зон пишутся сейчас и становятся активными по мере появления кода; это фиксируется в evidence списком «правило → первый owning item». Каждое правило (a)–(j) — отдельный `arch()` с говорящим именем, чтобы падение называло нарушенную границу. Манифест D12: публичные по расположению — `Kernel\*`, `Exceptions\*`, `Schema\*`, `Events\*`, `Facades\AzGuard`, `Concerns\HasAzGuard`, `Roles\BaseRole`, `Panels\{PanelBuilder,Panel,PanelProvider}`, `Testing\*`, `Storage\Models\*`; `Contracts\*` — по обязательному тегу `@api`/`@spi`; остальные — только по явному тегу (`via: tag`). Запись класса: FQCN, вид (class/interface/trait/enum), `final`/`abstract`/`readonly`, родитель, интерфейсы, кейсы enum (имя, значение), публичные константы (имя), публичные свойства (имя, тип, readonly, static), публичные методы (имя, static, параметры: имя, тип, по ссылке, variadic, наличие и `var_export` значения по умолчанию; тип возврата), стабильность (`api`/`spi`), способ (`location`/`tag`). Детерминизм: сортировка по FQCN и именам, `JSON_PRETTY_PRINT|JSON_UNESCAPED_SLASHES`, завершающий перевод строки; без docblock-текста и путей файлов. Список классов — сканирование `src` пакета по PSR-4 из его `composer.json`, загрузка через `vendor/autoload.php`. `--check` при расхождении: код выхода 1 и краткий diff (добавлено/удалено/изменено по FQCN). Тест вызывает `php bin/api-manifest.php --check` через `Symfony\Component\Process` или `proc_open` (без новых зависимостей) и ожидает 0. Правило Filament → core: токены `T_NAME_QUALIFIED`/`use`-импорты в `packages/filament/src`, начинающиеся с `AzGuard\` и не с `AzGuard\Filament\`, должны входить в манифест ядра. Скан кодов задач — только комментарии (`T_COMMENT`/`T_DOC_COMMENT` через `token_get_all`), не строки кода. `BaselineArchTest.php` не дублируется и не удаляется.
**Code Guidance:** Порог ложных срабатываний для кодов задач проверить на текущем `src` (ноль совпадений) и на синтетическом комментарии в unit-фикстуре теста (строка, не файл `src`). Для доказательства, что правила срабатывают, временно добавить нарушение и откатить: `use Illuminate\Support\Str;` в класс Kernel; вызов `now()` в Kernel; комментарий `// see P1.4` в `src`; изменение сигнатуры публичного метода Kernel без `--write`; класс в `Contracts/` без тега.
**Validation:** 1) `vendor/bin/pest tests/Arch` — GREEN; 2) `php bin/api-manifest.php --check` — exit 0; 3) пять временных нарушений из Code Guidance дают RED каждое, после отката GREEN (в evidence: правило, вывод, откат); 4) `composer test`; 5) `vendor/bin/pint --test`; 6) `vendor/bin/phpstan analyse --memory-limit=1G`; 7) `vendor/bin/pest --type-coverage --min=98`; 8) `git diff --check`.
