### P2.5 — Каталог из источников, коллизии, O(1)-поиск, catalog:cache

**Intent:** Собрать при загрузке статичный каталог панели из вкладов источников — права с режимом authority, кодовые роли, привязки политик — с обнаружением любой коллизии как ошибки сборки, поиском права за O(1) и снимком в файл кэша, оставив готовый шов для динамического overlay по tenant.
**Why:** RAG:— D36 (static catalog immutable, dynamic scoped `(panel, tenant)`; static names зарезервированы во всех tenants; compiled cache не содержит DB rows); 06 §1.1 (`ProvidesPermissions`, `ProvidesRoles`, `ProvidesPolicies`), §1.2 (проверки сборки: `id()` источников не повторяются, `DuplicatePermissionException`/`DuplicateRoleException` с id источников; статичная часть и привязки политик — в `azguard:catalog:cache`; для статичной сборки `tenant = null`); 19 §2, §5 (одно право = один owner definition + immutable mode; повтор enum FQCN идемпотентен; другое определение с тем же key/mode или static/dynamic shadow — conflict; dynamic всегда `Grants`; PolicyOnly binding обязателен; назначение PolicyOnly-права запрещено); 05 §6 (`BaseRole::permissions()` — enum, локальные имена, шаблоны), §10, §12 (`PolicyBinding::for`); D05 и 09 §1 (префикс не совпадает с первым сегментом локального имени); 18 §8 (frozen catalog — metadata без Model/Closure/сервисов; fingerprint = metadata + build id); D44 (чужая Gate ability — 0 запросов, статичный O(1) ownership index); 07 §5 (`duplicate_permission`, `duplicate_role`, `duplicate_policy_binding`, `invalid_policy_structure`, `prefix_conflict`); V08, V81 (часть), V119 (часть); D7 п.4 (проверка переопределённых `key()`/`formerKeys()`); D8 п.1, п.3–п.7.
**Scope Included:** Контракты `Contracts\Sources\{ProvidesPermissions,ProvidesRoles,ProvidesPolicies}` (`@spi`). `Catalog\PermissionDefinition` (final readonly, `@spi`: `local`, `authority`, `label`, `group`, `description`, `case`, `resourceModel`). `Policies\PolicyBinding` (final readonly, `@api`: `for(UnitEnum|string $permission, string $policy)`, поля `permission`, `policy`). Внутренний `Sources\PanelSources`: источники-объекты панели в порядке записей рецепта, проверка `id()`. `Contracts\Catalog\PermissionCatalog` (`@api`: `panel()`, `has()`, `find()`, `get()`, `keyOf(UnitEnum)`, `all()`). `Catalog\PanelCatalog`: сборка из статичных `ProvidesPermissions`, `ProvidesRoles`, `ProvidesPolicies`; индексы «локальное имя → определение», «enum FQCN + case → ключ», «первый сегмент → есть»; происхождение вклада (провайдер или плагин) в определении и в сообщениях о коллизиях — имён плагин не меняет (D10); `withDynamic(iterable<PermissionDefinition>): PermissionCatalog`. Компиляция ролей панели (`Catalog\RoleCompiler`): ключи, `formerKeys`, права, `scopes()`/`scopeRequired()`. Проверка привязок политик. Подключение каталога к `PanelResolver`: конфликт префикса с первым сегментом локального имени и владение неквалифицированным именем. `DuplicatePermissionException`, `DuplicateRoleException`, `DuplicatePolicyBindingException`, `InvalidPolicyStructureException`, `UnknownSourceException`. Кэш: `azguard:catalog:cache`, `azguard:catalog:clear`, `catalog.cache_path`, чтение снимка при загрузке с проверкой актуальности. Каталог и источники — в `PanelFingerprint`. Arch-правила зон `Catalog` и `Sources`.
**Scope Excluded:** фабрика имён источников, `#[AsSource]`, экземпляры на область исполнения, писатель, остальные возможности источника (P2.7): строка-имя в `permissions([...])` до P2.7 не разрешается. Чтение enum, атрибутов `#[Describe]`/`#[RequiresGrant]`/`#[PolicyOnly]`, `#[Decides]` и поиск классов (P2.8 — превращает их в `PermissionDefinition`, роли и `PolicyBinding`). Чтение динамических прав из БД, версия и version fence overlay (P4.4/P4.8). Вызов политик и сигнатуры их методов (P4.3). Сверка `scopes()` роли с зарегистрированными определениями панели (P4.6). `optimizes()` и `about` (P6.10). `PanelAccess::catalog()` (P6.1). Схема (P5.5).

**Implementation Rules:** Три контракта повторяют сигнатуры 06 §1.1 дословно (`permissions(Panel, ?TenantRef)`, `isDynamic()`, `roles(Panel)`, `policies(Panel)`), docblock `@spi`. `PermissionDefinition`: `local` проверяется `PermissionGrammar::assertLocalKey`; `authority` обязателен; `case` — `?BackedEnum`; равенство — по всем полям. `PolicyBinding::for()`: право — enum case или локальное имя по грамматике, `policy` — существующий класс, иначе `DefinitionException`. `PanelSources`: объекты `Source` из записей `permissions([...])` в порядке слоёв и регистрации; enum class-string пропускаются (их забирает `FolderSource`, P2.8); `id()` проверяется `IdentityCodec::assertSourceLabel`; повтор `id()` → `DefinitionException` с обоими классами; строка-имя → `UnknownSourceException` (`unknown_source`): до P2.7 ни одно имя не зарегистрировано. Сборка каталога: `tenant = null`, источники с `isDynamic() === true` при загрузке не читаются. Ключ права = панель + локальное имя вклада как объявлено: плагин имён не преобразует, модуль сам называет свои права в своём пространстве (`blog.posts.edit`) (D10); вклад провайдера префикса не получает. Коллизия: два вклада с одним ключом и равными определениями — один элемент, владелец — первый источник; любое отличие (включая режим и `case`) → `DuplicatePermissionException` с ключом, id обоих источников и id плагинов; один enum FQCN с разными итоговыми префиксами на одной панели → `DuplicatePermissionException`. Роли: экземпляр `BaseRole` на класс; повтор того же класса идемпотентен; ключ роли плагина — как объявлен у роли (`blog-editor` задаёт сам модуль, D10); итоговый ключ и каждый `formerKeys()` проверяются `PermissionGrammar::assertRoleKey` (в том числе при переопределённых методах), `formerKeys` не содержит текущий ключ; два класса с одним ключом, либо `formerKey` одной роли равен текущему или прежнему ключу другой роли панели → `DuplicateRoleException` с ключом и обоими классами. `permissions()` роли: enum case → ключ через индекс каталога, непривязанный enum → `UnknownPermissionException`; строка с `*`/`**` → `PermissionPattern` по грамматике; точная строка — локальное имя, обязана быть в статичном каталоге, если на панели нет динамического `ProvidesPermissions`, иначе `UnknownPermissionException`; точное право режима `Policy` в `permissions()` роли → `DefinitionException` (назначение PolicyOnly-права запрещено; шаблон такие права не покрывает). `scopeRequired() === true` при `scopes() === []` → `DefinitionException`; элемент `scopes()` — объект или class-string `AssignmentScopeDefinition` (создаётся контейнером), два разных класса с одним `type()` в ролях панели → `DefinitionException`. Привязки политик: право привязки обязано быть в каталоге (`UnknownPermissionException`); две привязки одного права к разным политикам → `DuplicatePolicyBindingException`, одинаковые — идемпотентны; право режима `Policy` без привязки → `InvalidPolicyStructureException`. `PermissionCatalog`: `has`/`find`/`get` принимают локальное имя или `PermissionKey` своей панели, ключ чужой панели → `find` null и `get` → `UnknownPermissionException`; `keyOf(case)` — непривязанный enum → `UnknownPermissionException`; все поиски — обращения к хеш-таблицам, без перебора и без запросов к БД. `withDynamic()`: определение не `Grants` → `InvalidSourceContributionException`; имя совпало со статичным → `DuplicatePermissionException`; первый сегмент имени — префикс панели → `PrefixConflictException`; результат — новый неизменяемый каталог. Resolver: итоговый префикс любой панели равен первому сегменту локального имени статичного каталога любой панели (включая имена из вкладов плагинов) → `PrefixConflictException` с панелью и именем; владение неквалифицированным именем — панель-кандидат шагов 2–3 владеет им, только если `has()` её каталога истинно, иначе ability чужая (null). Кэш: файл `catalog.cache_path` или `bootstrap/cache/azguard.php` — PHP-массив скаляров (ключи, режимы, подписи, enum FQCN и case, классы ролей и их ключи, привязки, id источников, отпечаток, build id), без объектов и замыканий; при загрузке снимок используется, только если его build id и отпечаток рецепта совпали с текущими, иначе игнорируется и каталог собирается живьём; `azguard:catalog:clear` удаляет файл. Каталог из снимка и живой — равны по `all()`, индексам и отпечатку. `Sources\` не использует `Changes`, `Authorization`, `Storage`.
**Code Guidance:** Фикстурные источники-объекты (`StaticSource` с `ProvidesPermissions`/`ProvidesRoles`/`ProvidesPolicies`, `isDynamic() = false`) подключаются провайдером и фикстурными плагинами P2.4. V08 — два источника с `orders.view`: одинаковые определения → один элемент; разные подписи → `duplicate_permission`, сообщение содержит оба id; источник провайдера и источник плагина с тем же именем → `DuplicatePermissionException` с id плагина; плагин с именем в своём пространстве (`blog.posts.edit`) рядом с `posts.edit` провайдера → два ключа. V119 (часть) — один ключ с режимами `Policy` и `Grants` из разных источников → ошибка; dynamic-определение `Policy` → `invalid_source_contribution`; PolicyOnly без привязки → `invalid_policy_structure`; роль с PolicyOnly-правом → `DefinitionException`. D7 п.4 — фикстурные роли: override `key()` с `Bad Key` → `InvalidRoleKeyException`; override `formerKeys()` с текущим ключом; две роли с ключом `manager`; роль с `formerKeys = ['seller']` при существующей `SellerRole`. V81 (часть) — панель с префиксом `orders` при локальном имени `orders.view` в каталоге другой панели → `prefix_conflict`. Владение — `orders.view` есть в каталоге текущей панели → панель; `posts.view` нет → null; `DB::enableQueryLog()` пуст. O(1) — каталог из 5 000 прав: `has()`/`find()`/`keyOf()` не делают запросов и читают хеш-индексы; время не измерять. Кэш — Feature: `artisan azguard:catalog:cache` → файл; повторная загрузка приложения даёт равный каталог и отпечаток; изменение build id → снимок игнорируется; `azguard:catalog:clear` → файла нет. Имя источника в `permissions(['ldap'])` → `unknown_source`. Доказать RED правил `Catalog ↛ Storage, Changes` и `Sources ↛ Changes, Authorization` на временной копии.
