### P2.1 — PanelProvider, PanelBuilder, Panel, PanelRegistry, CurrentPanel

**Intent:** Дать панель как неизменяемое значение, собранное из рецепта провайдера: builder записывает каждую настройку вместе с её происхождением, реестр принимает, заменяет и дополняет панели до заморозки на `booted`, после чего состав панелей нельзя изменить незаметно.
**Why:** RAG:— D06 (папка = каталог провайдера; `DuplicatePanelException`, `replace()`, `configurePanel`/`configurePanels`, заморозка после `booted`); 05 §4 (сигнатуры `PanelProvider`, `PanelBuilder`, `Panel`, `PanelRegistry`; `getId()` — явное static значение, `id()` обязан совпасть); D11 (`for(model, guard:)`, `default()`, одна панель модели = панель по умолчанию, две default → ошибка); D73 (`permissions([...])` — один метод для enum, `Source` и имён); D74 (`for(guard:)` — auth guard Laravel, не панель); 07 §6 (аддитивные списки с origin metadata; `configurePanel(id)` — дополнение провайдера); 04 §5 (порядок `register`/`boot` провайдера ядра); V05, V06, V107, V108 (части P2.1); D8 п.2, п.5, п.6.
**Scope Included:** `AzGuard\Panels\PanelProvider` (abstract, `extends ServiceProvider`: `static getId()`, `panel(PanelBuilder)`, `register()` регистрирует себя в реестре). `PanelBuilder` (final) с методами строки P2.1 таблицы D8 п.2: идентичность, `for`, маршрутные настройки, `permissions`, `roles`, `presentation`, списки хуков и резолверов. Внутренние `PanelRecipe` (записи `настройка, значение, происхождение`) и `PanelCompiler` (рецепт → `Panel`), `PanelFingerprint` (sha256 канонического JSON нормализованных метаданных панели). `Panel` (final readonly: `id`, `label`, `isDefault`, `prefix`, `subjectModels`, `accepts`). `Contracts\Panels\PanelRegistry` (`@api`, 10 методов 05 §4) и реализация `Panels\PanelRegistry`. `CurrentPanel` (scoped: текущая панель и запуск замыкания внутри панели с восстановлением прежней в `finally`). `Contracts\Sources\Source` (`@spi`, только `id()`). Исключения `DuplicatePanelException`, `UnknownPanelException`, `RegistryFrozenException`, `DefaultPanelConflictException`, `SubjectNotAcceptedException`, `InvalidConfigurationException`; `DefinitionException` — неабстрактный (D8 п.5). `config/azguard.php` с `panels.providers` и readonly `Configuration\AzGuardConfig`. Провайдер ядра: merge конфига, singleton реестра, scoped `CurrentPanel`, регистрация провайдеров из конфига, компиляция и заморозка в `$app->booted()`. Arch-правила зон `Panels` и `Configuration`.
**Scope Excluded:** `plugins`/`withoutPlugins`/`pluginIds` (P2.4); `cache`/`gate`/`consistency`/`settings()` и значения по умолчанию из конфига (P2.3); разрешение имён источников, `sources()`/`writer()`/`isWritable()` (P2.7); `discover`/`policies` (P2.8); `tenants`/`scopes`/`fields` (D8 п.2). Проверка контракта элементов списков хуков (P4.1/P5.2/P6.4). Правило выбора панели и конфликт префиксов (P2.2). Фасад (P2.6). Enum → каталог (P2.5/P2.8): здесь enum class-string только нормализуется и записывается.

**Implementation Rules:** Id панели — только `static::getId()`, проверяется `PermissionGrammar::assertPanelId` при регистрации; `->id($x)` с `$x !== getId()` → `DefinitionException`; имя класса и namespace в id не превращаются. `register(class)`: повтор id → `DuplicatePanelException` (в том числе тот же класс); `replace(class)`: заменяет регистрацию с тем же id, неизвестный id → `UnknownPanelException`; `configure(id, fn)` копит callbacks, неизвестный id обнаруживается при компиляции → `UnknownPanelException`; `configureAll(fn)` — для всех панелей; любая мутация после заморозки → `RegistryFrozenException`; `get()` неизвестного id → `UnknownPanelException`, `find()` → null. Чтение (`get`/`find`/`all`/`forModel`/`defaultFor`) до компиляции на `booted` → `DefinitionException` «панели ещё не собраны»: частично собранный реестр наружу не виден. Компиляция панели: новый builder → `panel()` провайдера и callbacks `configure(id)` с происхождением `provider` → callbacks `configureAll` с происхождением `configure`; каждый callback выполняется один раз на панель; порядок панелей — порядок регистрации. Builder: каждый setter пишет запись в `PanelRecipe` с текущим происхождением и возвращает `$this`; происхождение — вид `provider`, `plugin` (id плагина, порядок подключения, префикс ключей) или `configure`; P2.1 выставляет `provider` и `configure`, вид `plugin` используют P2.3 и P2.4; у builder нет публичных геттеров, рецепт передаётся конструктором; после компиляции builder запечатан — вызов setter → `RegistryFrozenException`. `for()`: class-string `Model` или непустой список, иначе `DefinitionException`; несколько вызовов складываются; `guard` — имя auth guard, builder не обращается к `Auth`. `resourcePrefix(string|bool)`: строка — один сегмент `PermissionGrammar::isSegment`, иначе `DefinitionException`; `true` → id панели; `false` → без префикса; без вызова — `true` (конфиг `defaults.resource_prefix` подключает P2.3). `permissions(array)`: элемент — string-backed enum class-string (дедуп по FQCN, порядок первой регистрации), объект `Source`, либо строка-имя источника; class-string не-enum, не string-backed enum и любой другой тип → `DefinitionException`; повторные вызовы дополняют список. `roles(array)`: class-string наследника `BaseRole`, иначе `DefinitionException`; дедуп по FQCN. Списки хуков и резолверов — аддитивные, без замены; `tenantResolvers`/`scopeResolvers`/`resourceScopes` проверяют class-string или объект своего SPI из `Contracts\Scopes`. `Panel::accepts(Model)` — `instanceof` одной из моделей субъектов; `accepts(SubjectRef)` — `type()` равен `getMorphClass()` одной из моделей. `defaultFor(model)`: панель с `default()`, принимающая модель; иначе единственная панель модели; иначе null; две `default()` для одной модели → `DefaultPanelConflictException` при компиляции. `PanelFingerprint` считает по отсортированным ключам; в P2.1 входят id, префикс, модели субъектов, enum-классы, роли, имена и классы источников, списки хуков (имя класса или `closure`), порядок записей; замыкания и объекты моделей в отпечаток не сериализуются. `AzGuardConfig` — единственное место чтения `config('azguard…')`; неизвестный ключ в секции `panels` → `InvalidConfigurationException`. Публичные методы `PanelBuilder`/`Panel` — только из таблицы D8 п.2; внутренние классы без тегов. Docblock без кодов задач.
**Code Guidance:** V05 — `DuplicatePanelException` на повтор; `replace()` до заморозки меняет провайдера; после `booted` `register`/`replace`/`configure`/`configureAll` → `RegistryFrozenException`. V06 — dataset id `''`, `a.b`, `*`, `A`, `a b`, `a:b` → `InvalidPanelIdException`. V108 (часть) — две панели с `guard: 'web'` и id, отличным от имени guard; `Auth::getDefaultDriver()` до и после компиляции одинаков.
