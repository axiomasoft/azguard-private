### P2.7 — Фабрика источников: Source, возможности, SourceManager, AsSource

**Intent:** Завершить контракты возможностей источника и собрать источники панели через фабрику в стиле Laravel `Manager`: имя → новый экземпляр на панель, не больше одного писателя, без общих объектов между панелями и запросами.
**Why:** RAG:— D52 (панель собирается из источников; фабрика — `Illuminate\Support\Manager`; писатель один; порядок не влияет на решение, но входит в отпечаток); 06 §1.1 (сигнатуры возможностей и `EvaluationContext`), §1.2 (порядок сборки, проверки, lifecycle: registry хранит definitions/factories, scoped instance создаётся на request/job; `SourceManager::make` не использует кэш `Manager::driver()`; одно имя `AsSource` у разных классов — ошибка), §1.3 (`#[AsSource]`, `extend()`, `config('azguard.sources.<name>')`, создание контейнером); D58; D73 (неизвестная строка → `UnknownSourceException`; повтор source id и два писателя — ошибка); 05 §3 (`AzGuard::sources()`), §4.1 (`SourceManager::extend`/`make(name, panel)`); 04 §7 (`StoresGrants` не вызывает обратно `ChangePipeline`); V77, V102, V107; D8 п.1, п.3, п.5, п.6, п.7.

**Implementation Rules:** Контракты повторяют сигнатуры 06 §1.1 дословно, кроме отложенного D8 п.3: `StoresGrants extends Source` несёт только `transaction(Closure $callback): mixed`. Каждый интерфейс — docblock `@spi` (`EvaluationContext` — `@api`) и одна строка назначения. `SourceManager`: `extend($driver, Closure(Application, array): Source)`; `make($name, $panel)` каждый раз вызывает creator и возвращает новый объект, `driver()`/кэш `$drivers` не используются; `getDefaultDriver()` бросает `UnknownSourceException` (источника по умолчанию нет); creator получает `AzGuardConfig::source($name)` (`[]` без секции); класс с `#[AsSource('имя')]` создаётся контейнером `makeWith(['config' => …])`; одно имя у двух разных классов или у класса и `extend()` → `DefinitionException`, повторная регистрация того же класса — без ошибки; неизвестное имя → `UnknownSourceException` при компиляции панели. `PanelSources`: строка-имя в записях `permissions([...])` теперь — фабрика через `SourceManager` на месте своей записи (порядок сохраняется); объект `Source` остаётся неизменяемым рецептом; проверки P2.5 (`id()`, повтор) распространяются на именованные источники; больше одного `StoresGrants` → `WriterConflictException` с id источников. Экземпляры: для компиляции создаётся build-экземпляр; на исполнении именованный источник создаётся заново на каждую область (scoped-привязка контейнера, сбрасывается между запросами и jobs) и отдельно для каждой панели; объект-рецепт переиспользуется. Статичные возможности именованных источников (`ProvidesPermissions`/`ProvidesRoles`/`ProvidesPolicies`) попадают в каталог P2.5 тем же путём, что у объектов. `Panel::sources()` — `list<SourceDescription>` в порядке сборки: `describe()` для `DescribesSchema`, иначе описание из реализованных интерфейсов возможностей; `isDynamic()` → `dynamic`. `Panel::isWritable()` — есть источник `StoresGrants`; `writer()` — экземпляр текущей области или null. Секреты из параметров источника в `SourceDescription` не попадают. `PanelFingerprint` получает имена и классы именованных источников в порядке сборки. `AzGuardManager::sources()` возвращает singleton `SourceManager`; фасад получает шестой `@method`. Arch-правило «`StoresGrants` используется только в `ChangePipeline`, `Sources\Database`, `Testing`» расширяется на `Panels\Panel` и `Sources\PanelSources`: там интерфейс — тип возврата и признак писателя, `transaction()` в них не вызывается. `AzGuard\Attributes` добавляется в `AZGUARD_OUTER_ZONES`.
**Code Guidance:** Фикстуры: `LdapSource` с `#[AsSource('ldap')]` (`ProvidesRoleGrants`), два `WriterSource` (`StoresGrants`), источник с scoped-зависимостью в конструкторе; `StaticSource` из P2.5. V77 — `permissions(['ldap'])` через атрибут и через `AzGuard::sources()->extend()`; creator получил `config('azguard.sources.ldap')`; `permissions(['nope'])` → `unknown_source`; два писателя → `writer_conflict`; именованный и объектный источники с одним `id()` → `DefinitionException`; панели `admin` и `cabinet` с `'ldap'` получают разные объекты (`not->toBe`). V102 (часть) — после `$app->forgetScopedInstances()` именованный источник создаётся заново; экземпляр одной панели не возвращается другой. V107 (часть) — mixed-список `[Enum::class, new StaticSource, 'ldap']`: порядок источников `StaticSource`, `ldap`; enum не становится источником. P12 на уровне P2 — перестановка источников не меняет множество ключей каталога и `id` в `Panel::sources()`, но меняет отпечаток. Доказать RED расширенного правила `StoresGrants` на временной копии (вызов `transaction()` из `Panels\`).
