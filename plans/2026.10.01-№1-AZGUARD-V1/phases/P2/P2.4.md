### P2.4 — Плагины: typed factories, PluginContext, изоляция, конфликты

**Intent:** Дать плагин как готовый набор дополнений панели с собственными именованными типизированными параметрами: SPI жизненного цикла, общая база без параметров и без префикса ключей, `PluginContext` только с build-метаданными, отдельный экземпляр на панель, зависимости и участие порядка плагинов в отпечатке панели.
**Why:** RAG:— D47, D78 и 19 §4 (у `BasePlugin` нет `make()`/`options()`/`withOptions()`; конкретный `make(...)` с named typed parameters; build-конфигурация не удерживает request/user/role/Builder); 06 §3 (SPI `Plugin`, `DependsOnPlugins`; жизненный цикл провайдеры → `register()` в порядке подключения → источники и проверки → заморозка → `boot()`; один плагин на нескольких панелях видит каждую свою; порядок плагинов входит в отпечаток); 18 §7, §10 (`PluginContext`: `panelId`, `pluginId`, `buildId`, `dependencies`; factories fresh, shared mutable object изолируется); 07 §6 (plugin `register` добавляет definitions, `boot` не меняет registry); V47 (сквозная часть), V48, V85, V115, V118; D6 (`PluginContext` → P2.4); D8 п.1, п.4, п.5, п.7; D10 (у плагина нет префикса ключей: нет `PrefixesKeys`, `BasePlugin::prefixed()`/`prefix()` и `PluginContext::namespace()`).
**Scope Included:** `Contracts\Plugins\{Plugin,DependsOnPlugins}` (`@spi`). `Plugins\BasePlugin` (abstract, `@spi`: реализует `Plugin`, `boot()` по умолчанию пустой). `Plugins\PluginContext` (final readonly, `@api`: `panelId`, `pluginId`, `buildId`, `dependencies`). `PanelBuilder::plugins(array)`, `withoutPlugins(array)`; `Panel::pluginIds()`. В `PanelCompiler`: экземпляр плагина на панель, `register()` в порядке подключения с происхождением `plugin:<id>`, проверка зависимостей и дубликатов, запечатывание builder, `boot()` после заморозки. `PluginDependencyMissingException`; повтор id плагина — `PluginConflictException` (класс из P2.3). `AzGuardConfig::buildId()` и ключ `catalog.build_id` (D8 п.5). Плагины и их порядок — в `PanelFingerprint`. Arch-правила зоны `Plugins` становятся невакуумными.
**Scope Excluded:** встроенный плагин `azguard/audit` (P5.4). Логика порядка настроек и конфликта двух плагинов по scalar-настройке (P2.3 — уже есть; здесь только сквозной сценарий V47 с настоящими плагинами). Коллизии имён вкладов плагинов в каталоге (P2.5): плагин имён не меняет (D10). `PluginContractTests` (P6.7). Проверки doctor плагинов (P6.4). Filament-плагин (P7.1).

**Implementation Rules:** `plugins(array)`: элемент — объект `Plugin` или class-string `Plugin` (создаётся контейнером), иное → `DefinitionException`; списки аддитивны, порядок подключения сохраняется. Id плагина — грамматика D8 п.5, иначе `DefinitionException`; два плагина с одним id на панели → `PluginConflictException`. `withoutPlugins(ids)` убирает плагин, подключённый `configurePanels()`; id, которого нет, не ошибка. Экземпляр на панель: компилятор берёт `clone` переданного объекта перед `register()`; объект, полученный из контейнера, тоже клонируется — состояние, записанное в `register()` одной панели, не видно другой. `DependsOnPlugins::requires()`: каждого id нет среди подключённых после `withoutPlugins` → `PluginDependencyMissingException` с id плагина и зависимости. Порядок сборки панели: записи провайдера и `configure` → плагины из рецепта по порядку: `register(PanelBuilder, PluginContext)`; плагин, подключённый внутри `register()` другого плагина, регистрируется после текущего; повторный обход до исчерпания. Во время `register()` текущее происхождение builder — `plugin:<id>`. Префикса у плагина нет (D10): поле `prefix` из происхождения `PanelRecipe::plugin()` и из проверок P2.1 удаляется, плагин приносит ключи как объявлены. После фазы `register` builder запечатан: любой setter, в том числе из сохранённой ссылки в `boot()`, → `RegistryFrozenException`; `boot(Panel, PluginContext)` вызывается после заморозки реестра в порядке подключения. `PluginContext`: `panelId()`, `pluginId()`, `buildId()` (из `AzGuardConfig::buildId()`), `dependencies()` (из `requires()`, иначе `[]`); нет геттера опций, контейнера и панели-объекта. У `BasePlugin` нет `prefixed`, `prefix`, `make`, `options`, `withOptions`, публичного конструктора с массивом; id плагина отдаёт `Plugin::id()`, fluent-сеттера id база не объявляет. `AzGuardConfig::buildId()`: `catalog.build_id`, если непустая строка; иначе sha256 по отсортированным парам «класс зарегистрированного провайдера панели → sha256 содержимого его файла» — значение известно до `register()` плагинов (от отпечатков панелей не зависит) и стабильно между запросами одного кода. `PanelFingerprint` получает id плагинов в порядке подключения. `Plugins\` не использует `AzGuard\Internal` и `AzGuard\Storage`.
**Code Guidance:** Фикстуры: `AuditTrailPlugin::make(int $retentionDays = 90)` с `retention(int): static` (clone) по 06 §3; `CrmAccessPlugin::make(CrmModels $models, string $clientScope)` с DTO `CrmModels`, проверяющим `is_a(..., Model::class, true)` и `Authenticatable` (19 §4), использующий только доступные методы builder (`for`, `resourceScopes`); плагин с `requires()`; плагин, меняющий builder в `boot()`. V48 — отсутствующая зависимость → `plugin_dependency_missing`; изменение в `boot()` → `RegistryFrozenException`; перестановка двух плагинов меняет отпечаток панели; один объект плагина на двух панелях получает два разных `PluginContext::panelId()`. V85 — `make()` через `app()->makeWith(...)` работает с привязкой контейнера; `retention(30)` на одной панели и `retention(90)` на другой не делят состояние; плагин в `register()` добавляет фикстурный `Source`, класс ограничения и pipe — записи рецепта несут происхождение `plugin:<id>`. V47 (сквозной) — два фикстурных плагина с разным `cache(ttl:)` → `plugin_conflict` с id обоих; при заданном провайдером ttl — без ошибки; `settings()->origin(...)` возвращает `plugin:<id>`. V115/V118 — reflection: у `BasePlugin` нет `make`/`options`/`withOptions`/`prefixed`/`prefix`, интерфейса `PrefixesKeys` нет, у `PluginContext` нет `namespace`; `CrmModels` с не-`Model` или не-`Authenticatable` субъектом → исключение до сборки панели; сигнатура `make` фикстур — именованные типизированные параметры. Доказать RED правил `Plugins ↛ Internal` и `Plugins ↛ Storage` на временной копии.
