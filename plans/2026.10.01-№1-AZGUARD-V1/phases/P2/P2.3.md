### P2.3 — Настройки панели и PanelSettings

**Intent:** Закрепить один порядок получения итоговой настройки панели — провайдер → плагины в порядке подключения → `configurePanels()` → значение по умолчанию из конфига — и показать, откуда взято каждое значение, не давая ни одной настройке отключить гарантии безопасности.
**Why:** RAG:— D45 (эффективная настройка = провайдер → плагин, конфликт двух плагинов → ошибка → `configurePanels()` → default; список «Не настраивается»); 07 §1 (precedence заменяемых настроек и presentation; `panels:list --settings` показывает значение и источник), §2 (`defaults.*`), §5 (`invalid_configuration.enum`, `invalid_configuration.cache_ttl`, `plugin_conflict`), §6 (scalar overrides с tracked explicit/default values; sources/roles/contexts/hooks/plugins — аддитивные списки с origin metadata и проверкой дублей; `configurePanel(id)` — дополнение провайдера); 05 §4 (`cache`, `gate`, `consistency`, `Panel::settings()`); V47; D8 п.1, п.2, п.4, п.5, п.6, п.7.
**Scope Included:** `Panels\{GateMode,Reads,StateRefresh}` (string-backed enum, `@api`). `PanelBuilder::cache(?string $store, ?int $ttl, ?int $generation)`, `gate(GateMode)`, `consistency(Reads, StateRefresh)`. `Panels\PanelSettings` (final readonly, `@api`): геттеры `resourcePrefix(): ?string`, `gateMode()`, `cacheStore()`, `cacheTtl()`, `cacheGeneration()`, `reads()`, `stateRefresh()`, `traceDecisions()`, `origin(string $setting): string`, `toArray()`; `Panel::settings()`. Разрешение scalar-настроек по слоям происхождения в `PanelCompiler`, включая слой плагинов; `PluginConflictException`; `Panel::prefix()` берёт итоговый `resource_prefix`. Секция `defaults` в `config/azguard.php` (ключи `resource_prefix`, `gate.mode`, `cache.{store,ttl,generation}`, `consistency.{reads,state_refresh}`, `trace_decisions`) и `AzGuardConfig::defaults()`. Слияние `presentation` по ключам с тем же приоритетом. Проверка аддитивных списков на точные дубли. Итоговые настройки — в `PanelFingerprint`.
**Scope Excluded:** настоящие плагины, их жизненный цикл и сквозной сценарий конфликта двух плагинов (P2.4): здесь слой плагинов проверяется на записях рецепта с происхождением `plugin`. `defaults.models`, `defaults.tenants`, `defaults.scopes` (P3.3/P4.6); `gate.enabled`, `schedule`, `storages`, `ids` (P3/P4/P6); остальные строки таблицы 07 §5 и публикация конфига (P6.3). AND-композиция context predicates из defaults/plugins/provider (P4.6, D8 п.7). Потребление `GateMode` (P4.11), `Reads`/`StateRefresh`/кэша (P4.8), `trace_decisions` (P5.4). Команда `azguard:panels:list --settings` (P6.6).

**Implementation Rules:** Слой плагинов читается из записей рецепта с происхождением `plugin` в порядке подключения; настоящих плагинов ещё нет, поэтому тесты создают такие записи через рецепт напрямую, а P2.4 повторяет сценарий сквозь `plugins([...])`. Проверка `PrefixConflictException` из P2.2 использует итоговый префикс после разрешения настроек. Слои scalar-настройки по убыванию приоритета: `provider` (включая `configure(id)`) → плагины в порядке подключения → `configure` (`configurePanels`) → `default` из `AzGuardConfig::defaults()`. Внутри одного слоя побеждает последняя запись. Два разных плагина задают одну scalar-настройку разными значениями, и слой `provider` её не задаёт → `PluginConflictException` с id обоих плагинов и именем настройки; одинаковые значения — не конфликт; если провайдер задал значение, конфликт плагинов не возникает. Аргумент `null` в `cache(...)` означает «не задано на этом слое», а не «сбросить». `GateMode` — один case `Authoritative = 'authoritative'`; `Reads` — `Primary`, `Default`; `StateRefresh` — `Request`, `Check`. Значение конфига вне enum → `InvalidConfigurationException` с кодом `invalid_configuration.enum`; итоговый `cache.ttl === null` при заданном `cache.store` → `invalid_configuration.cache_ttl`; `generation < 1` или `ttl < 1` → `invalid_configuration.enum`; неизвестный ключ в `defaults` → `InvalidConfigurationException`. Проверки — при компиляции панели, во всех окружениях. `InvalidConfigurationException::code()` возвращает код с уточнением после точки, базовый — `invalid_configuration`. `origin()` возвращает `provider`, `plugin:<id>`, `configure` или `default`; неизвестное имя настройки → `DefinitionException`. `presentation` — слияние по ключам верхнего уровня с тем же приоритетом слоёв. Аддитивные списки (enum, роли, источники, хуки, резолверы, плагины) никогда не заменяются слоем выше: все записи остаются в порядке слоёв `provider`, плагины, `configure`; точный дубль class-string в одном списке схлопывается, порядок — по первой записи. Гарантии D45 не имеют ни метода builder, ни ключа конфига. `PanelSettings` не содержит замыканий и объектов; `toArray()` — скаляры и пары «значение, происхождение». Enum-значения читаются из конфига строками, замыканий в конфиге нет.
**Code Guidance:** V47 — Feature-dataset по одной настройке (`cache.ttl`): задана только конфигом → `default`; `configurePanels` → `configure`; запись с происхождением плагина → `plugin:<id>`; провайдер → `provider`; все четыре сразу → значение провайдера. Записи двух разных плагинов с разным `cache(ttl:)` → `plugin_conflict`; те же записи при заданном провайдером ttl → без ошибки. Гарантии: `config(['azguard.defaults.gate.mode' => 'permissive'])` → `invalid_configuration.enum`; `azguard.defaults.strict_writes` → `InvalidConfigurationException`; reflection — у `PanelBuilder` нет методов, отключающих проверки (`withoutRestrictions`, `allowDirectWrites` и подобных нет в манифесте). Аддитивность: записи провайдера и плагина добавляют по ограничению — в итоге оба, порядок `provider`, `plugin`; `presentation(['icon' => …])` провайдера побеждает плагин по ключу, остальные ключи плагина сохраняются. Префикс: `defaults.resource_prefix = false` → `Panel::prefix()` null; `resourcePrefix('backoffice')` на панели побеждает.
