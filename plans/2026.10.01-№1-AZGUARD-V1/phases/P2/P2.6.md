### P2.6 — Модули: registerPanel, configurePanel, AmbiguousPanelException

**Intent:** Дать Laravel-модулю и стороннему пакету две точки входа — принести свою панель или дополнить панель, выбранную приложением, — через фасад `AzGuard`, и доказать на модульной фикстуре, что права и роли модулей не сталкиваются, а ошибки видны при загрузке.
**Why:** RAG:— D50 (своя панель модуля — обычный `PanelProvider` через `AzGuard::registerPanel()`; дополнение — `AzGuard::configurePanel('admin', fn)` с плагином модуля, который называет права в своём пространстве имён (D10); несуществующая панель → ошибка при загрузке; id панели модуль берёт из своего конфига; коллизия имён → ошибка с именами плагинов); 06 §8 (пример `BlogServiceProvider` и `BlogAccessPlugin`); 05 §3 (методы фасада `registerPanel`, `configurePanel`, `configurePanels`, `panels`, `currentPanel`); 07 §5 (`unknown_panel`); V07, V55; D8 п.1, п.6, п.7.
**Scope Included:** `AzGuard\AzGuardManager` (корень фасада без состояния) и `AzGuard\Facades\AzGuard` с методами `registerPanel`, `configurePanel`, `configurePanels`, `panels`, `currentPanel` — делегирование в `PanelRegistry` и `CurrentPanel`. Привязка `azguard` в провайдере ядра. Модульные фикстуры `Blog` и `Shop`: сервис-провайдер модуля, своя панель модуля, плагин, приносящий источник-объект с правами и ролью в пространстве имён модуля (`blog.posts.edit`, `blog-editor` — имена задаёт сам модуль, D10). Сценарии V55 и V07 сквозь фасад.
**Scope Excluded:** `AzGuard::sources()` (P2.7 — вместе с `SourceManager`). Вариант модуля с `discover(__DIR__)` и папкой `Guards` (P2.8). Остальные методы фасада: `panel()`, `check`, `authorize`, `withinScope`, `currentScope`, `actingAs`, `fake()` (P6.1, P6.7). `azguard:panels:list --sources` (P6.6). Генератор модуля (P6.8). Новая логика реестра, resolver, плагинов и каталога — она уже есть в P2.1–P2.5; пункт находит дефекты интеграции и записывает их с owning item в `findings/P2-execution.md`, исправляя в том же запуске только то, что нужно для собственных сценариев.
**Inputs:** `plan.md` · `phases/P2/P2.md` · `decisions/D8-p2-dependency-closure.md` · `decisions/D10-p2-no-plugin-prefix.md`. Код P2.1–P2.5 (классы `PanelRegistry`, `CurrentPanel`, `PanelResolver`, `BasePlugin`, `PanelCatalog`, фикстурные источники — прочитать реестр и resolver целиком) — из рабочего дерева после закрытия P2.5.
**Files:** `packages/core/src/AzGuardManager.php` · `packages/core/src/Facades/AzGuard.php` · `packages/core/src/AzGuardServiceProvider.php` · `packages/core/api-manifest.json` · `tests/Feature/Modules/{ModulePanelTest,ModuleExtensionTest}.php` · `tests/Unit/Facades/AzGuardFacadeTest.php` · `tests/Fixtures/Modules/Blog/**` · `tests/Fixtures/Modules/Shop/**` · `CHANGELOG.md`.
**Required Reads:** 1) `audits/2026-09-29-audit/opus/06-extension-points.md` §8 2) `brief/P2-dossier-decisions.md` §50 3) `audits/2026-09-29-audit/opus/05-php-api.md` §3 4) `audits/2026-09-29-audit/opus/14-verification.md` (строки V07, V55) 5) `decisions/D8-p2-dependency-closure.md`.
**Implementation Rules:** `AzGuardManager` не хранит состояния и не содержит логики: `registerPanel(class)` → `PanelRegistry::register`; `configurePanel(id, fn)` → `configure`; `configurePanels(fn)` → `configureAll`; `panels()` → `all()`; `currentPanel()` → `CurrentPanel`. Фасад объявляет в docblock только эти пять `@method`; остальные добавляют P2.7 и P6.1. Вызовы до заморозки допустимы из `register()` и `boot()` сервис-провайдера модуля; после заморозки — `RegistryFrozenException`. `configurePanel()` для незарегистрированной панели обнаруживается при компиляции → `UnknownPanelException` (`unknown_panel`) с id панели. Callback `configurePanel(id)` имеет происхождение `provider` (дополнение провайдера), `configurePanels` — `configure` (P2.1/P2.3). Фасад и менеджер не выбирают панель сами: правило выбора — только `PanelResolver`; arch-правило P2.2 остаётся зелёным (`CurrentPanel` в менеджере — чтение текущей панели для `currentPanel()`, список разрешённых мест правила дополняется `AzGuard\AzGuardManager`). Фикстура модуля читает id целевой панели из своего конфига (`config('blog.azguard_panel', 'admin')`), а не зашивает его.
**Code Guidance:** V55 — `BlogServiceProvider::register()`: `AzGuard::configurePanel(config('blog.azguard_panel', 'admin'), fn (PanelBuilder $p) => $p->plugins([BlogAccessPlugin::make()]))`; `BlogAccessPlugin::register()` добавляет источник-объект с `blog.posts.edit` и ролью `blog-editor`; после загрузки каталог `admin` содержит `blog.posts.edit`, роль `blog-editor`; модуль `Shop` со своим `shop.posts.edit` не сталкивается; два модуля с одним и тем же именем права → `DuplicatePermissionException` с id обоих плагинов (префикса у плагина нет, D10); `blog.azguard_panel = 'nope'` → `unknown_panel`. Своя панель модуля — `AzGuard::registerPanel(BlogGuardPanelProvider::class)` из `register()` модуля, панель видна в `AzGuard::panels()`. V07 — enum, не подключённый ни к одной панели, при разрешении → `UnknownPermissionException`; enum модуля, подключённый через `permissions([...])` к `admin` и к панели модуля, без явной панели → `AmbiguousPanelException`, с явной — панель выбрана. Порядок провайдеров в Testbench: провайдер модуля после провайдера ядра (`getPackageProviders`), как при package discovery с зависимостью от `axiomasoft/azguard`.
