### P2.2 — PanelResolver: одно правило выбора панели и префиксы

**Intent:** Реализовать единственное правило выбора панели — все явные сигналы должны согласоваться, затем текущая панель запроса, затем панель модели, иначе исключение — и закрепить его arch-правилом, чтобы ни один будущий вход не выбирал панель сам; вместе с ним ввести префиксы имён прав как однозначный сигнал панели.
**Why:** RAG:— D05 (локальное имя, префикс панели, полное имя `panel:local`; порядок: явно → панель запроса → панель модели → `PanelNotResolvedException`; префикс — один сегмент, уникален; в БД и enum имя без префикса); 09 §1 (таблица шагов; все явные сигналы собираются и должны согласоваться; `guard('a')->hasPermission('b:orders.view')` → `ConflictingPanelException`; enum нескольких панелей требует явной панели; сначала проверяется принимаемый субъект; словарь префиксов O(1); квалифицированное имя зарегистрированной панели всегда принадлежит AzGuard; изолированные слова остаются Laravel); D11 (`default()`, `azguardDefaultPanel()`, единственная панель модели); 04 §2 (arch: все входы выбирают панель только через `PanelResolver`); V07, V64, V65, V81, V86; probes P01c, P05, P09; D6 (`PermissionKey::prefixed()` → P2.2); D8 п.1, п.4, п.5, п.7.
**Scope Included:** `Panels\PanelResolver` (internal): вход — субъект (`Model|SubjectRef|null`), право (`UnitEnum|string|null`), явная панель (`?string`); выход — `Panel`, разобранный `PermissionKey` (если право задано) и шаг, по которому выбрана панель. Индексы на замороженном реестре: «префикс → панель», «enum FQCN → панели» (по enum из `permissions([...])` рецепта). Метод владения: по строке ability вернуть панель-владельца, null для чужой, без запросов к БД. `PermissionKey::prefixed(?string $prefix): string` в Kernel. Проверка сборки «префикс двух панелей совпал». Исключения `PanelNotResolvedException`, `ConflictingPanelException`, `AmbiguousPanelException`, `PrefixConflictException`, `UnknownPermissionException`. Arch-правило «панель выбирается только через `PanelResolver`». Регрессии P01c, P05, P09 на уровне resolver; `Status: covered:` в трёх spec.
**Scope Excluded:** проверки, которым нужен каталог (D8 п.1): конфликт префикса с первым сегментом локального имени и владение неквалифицированным именем по наличию в каталоге (P2.5); enum, найденные в папке панели, и префикс плагина внутри префикса панели (P2.8); значение префикса по умолчанию из конфига (P2.3). Адаптеры входов: трейт и `SubjectAccess` (P5.1), фасад `check`/`authorize` (P6.1), Gate (P4.11), middleware `azguard.panel`/`azguard.can` и восстановление панели в `finally` (P6.2), CLI (P6.6), `decideMany` (P4.9), перенос панели в `Context` очередей (P6.10) — каждый добавляет свою строку V64 и идёт через resolver. Проверка членства субъекта в tenant (P4.6). `explain()` с шагом выбора (P4.10). Dynamic-имена и префиксы при mutation (P4.4).

**Implementation Rules:** Шаг 1 — собрать все явные сигналы: аргумент панели; полное имя `x:local` (панель `x` обязана существовать, иначе `UnknownPanelException`); имя, первый сегмент которого — зарегистрированный префикс панели; enum, привязанный ровно к одной панели. Если сигналов несколько, они обязаны указывать одну панель, иначе `ConflictingPanelException` с перечислением сигналов; панель при конфликте не меняется и не выбирается по приоритету. Enum, привязанный к нескольким панелям, без другого явного сигнала → `AmbiguousPanelException`; enum одной панели при явной другой панели → `ConflictingPanelException`; enum, не привязанный ни к одной панели, → `UnknownPermissionException` (код `unknown_permission`, родитель `ChangeException` по таблице 05 §10). Шаг 2 — нет явных сигналов: `CurrentPanel`, если она есть и принимает субъект (`Panel::accepts`); текущая панель, не принимающая субъект, пропускается. Шаг 3 — панель модели: `azguardDefaultPanel(): ?string` модели субъекта (если метод есть и вернул id существующей панели, принимающей субъект), затем `PanelRegistry::defaultFor(model)`. Шаг 4 — `PanelNotResolvedException` с подсказкой (какие панели принимают модель, как указать панель); молчаливого отказа и fallback на произвольную панель нет. После выбора: субъект задан и панель его не принимает → `SubjectNotAcceptedException`. Право после выбора панели приводится к `PermissionKey` панели: префикс панели снимается, обе формы (`orders.view` и `admin.orders.view`) внутри своей панели дают один ключ; значение enum — локальное имя. Resolver не проверяет существование действия в каталоге: явно квалифицированное имя с неизвестным действием остаётся за AzGuard, отказ или `UnknownPermissionException` даёт потребитель с каталогом. Владение ability: одно слово без точки и двоеточия — чужое (null); `x:…` с зарегистрированной панелью `x` — AzGuard; первый сегмент — зарегистрированный префикс — AzGuard; для прочих имён метод возвращает панель шагов 2–3 как кандидата, а окончательное «имя есть в каталоге кандидата» подключает P2.5 через узкий интерфейс поиска (до P2.5 кандидат считается владельцем); всё на хеш-индексах, без запросов. Индекс enum строится из рецептов панелей и допускает пополнение на этапе сборки (P2.8 добавит найденные enum тем же методом). Сборка: итоговый префикс двух панелей совпал → `PrefixConflictException` с обеими панелями; id панели как префикс по умолчанию участвует в проверке. `PermissionKey::prefixed(?string $prefix)`: null → локальное имя; иначе `prefix.local`, префикс проверяется `PermissionGrammar::isSegment` (`InvalidPermissionKeyException`); панель и хранимая форма не меняются. Resolver не читает `Auth`, `Request`, `Context` и конфиг: текущую панель знает только `CurrentPanel`. Arch: `CurrentPanel`, `PanelRegistry::defaultFor` и `forModel` используются только в `Panels\PanelResolver`, реестре и провайдере ядра; `azguardDefaultPanel` вызывается только в `PanelResolver` — token-скан `SourceScan` по `packages/*/src`.
**Code Guidance:** V64 (уровень resolver) — dataset-матрица: субъект {принимается admin, принимается cabinet, обеими} × право {локальное, с префиксом admin, полное `admin:`, enum одной панели, enum двух панелей} × явная панель {нет, admin, cabinet} × текущая {нет, admin, cabinet} × default {нет, admin} → ожидаемая панель или класс исключения; одна таблица, один метод resolver. V65 — одна панель модели → она; две `default()` для одной модели → `DefaultPanelConflictException` при сборке; `azguardDefaultPanel()` переопределяет default; нет панели → `PanelNotResolvedException`. V81 (часть) — префикс по умолчанию = id; `resourcePrefix('backoffice')`; `resourcePrefix(false)`; свойство P11: при смене префикса ключ для enum с явной панелью и для `panel:local` тот же, а старое имя с прежним префиксом не разрешается в эту панель; повтор префикса → `prefix_conflict`. V86 (часть) — `guard: 'a'` и `b:orders.view` → `ConflictingPanelException`. V07 (уровень resolver) — enum вне панелей → `UnknownPermissionException`; enum в двух панелях без явной панели → `AmbiguousPanelException`. Регрессии: P01c — ключи `admin:users.delete` и `admin.users.delete` при default-панели `test` выбирают `admin`, никогда `test`; P05 — `orders.view` при нескольких панелях без default → `PanelNotResolvedException`, с явной панелью — панель выбрана; P09 — две панели, текущей нет: полное имя выбирает `admin`, локальное → `PanelNotResolvedException`. Имя теста в `covered:` должно дословно совпасть с `it(...)`. Enum-фикстуры подключаются через `permissions([Enum::class])` провайдера. Arch-правило доказать RED: временная копия класса вне `Panels\`, вызывающего `defaultFor()`.
