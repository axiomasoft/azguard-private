### P4.3 — Mode-aware policies, Decides, PolicyFor, GateSource::map

**Intent:** Довести политики до таблицы 09 §5: точная привязка через `#[Decides]`/`PolicyBinding`/`#[PolicyFor]`, нативный DI субъекта и ресурса (включая class-аргумент без экземпляра), нативный `before` политики, сохранение `Response` (status/message/code) в `Decision`; `GateSource::map()` как политика из существующей ability Laravel без рекурсии; статичный O(1) индекс «модель + слово ability → право панели» для Gate.
**Why:** RAG:— 09 §1 (одно слово + model, class argument, owned vs foreign), §5 (таблица authority, GateSource, native before), §16 (binding/Decides обязательны); 05 §7 (атрибуты ресурсов и политик); 19 §2 (`ClientPolicy`, Response, recursion), §9; D26, D53, D65, D83, D84 досье; 20 F04; V67, V68, V80, V93, V102; R21, R22, R61–R64; D14 плана п.3 (вызов политики: ядро P4.1, расширение здесь; поля отказа `Decision`).
**Scope Included:** P4.3 создаёт PanelCatalog::policyBindings(): array<string,PolicyBinding> canonical php/gate map; прежняя bindings(): array<string,class-string> сохранена PHP-only projection (D15 §3).  `PolicyDecider`: аргументы метода — модель субъекта, затем ресурс из запроса либо, если ресурса нет, class-string `resourceModel` определения права (`viewAny`/`create`); обязательный параметр без значения — отказ без вызова (`Deny(PolicyError)`, причина в логе); нативный `before($user, $ability)` политики вызывается первым, его не-`null` результат — результат политики, интерпретируемый по режиму; `Response` нормализуется через `allowed()`, `message()`, `status()`, `code()`. `Kernel\Decision\Decision` получает nullable `message`, `status`, `code` (скаляры; заполняются из `Response` политики при Deny(Policy) и Allow(Policy)). `@api` `Sources\Gate\GateSource implements ProvidesPolicies, DescribesSchema` с `make()`, `map(BackedEnum|string $permission, string $ability, ?string $resourceModel = null)`; при сборке: право существует в каталоге, ability определена Gate::has для define либо getPolicyFor+callable method при явном resourceModel (D15 §3), имя ability не является полным/локальным именем права AzGuard (иначе рекурсия) — нарушение → `DefinitionException`. Индекс ability в `PanelCatalog`: для enum с `#[Resource(model:)]` — `[класс модели][последний сегмент локального имени]` → локальный ключ (`view_any` ↔ `viewAny` через `Str::snake`); две записи на одну пару — помечена неоднозначной. PolicyBinding::gate(permission, ability, resourceModel), discriminator kind php/gate и nullable поля, compile/cache/runtime обе ветки D15 §3; существующий for() сохранён.

**Implementation Rules:** Required policy binding и duplicate checks работают по canonical typed map, не nullable policy string. Gate kind обходит ReflectionClass/Decides PHP branch; snapshot содержит discriminator/all fields, schema revision updated; tests live/cache и PHP legacy bindings compatibility обязательны.  Режим определяется только `PermissionDefinition::$authority`, не наличием политики или источника. PolicyOnly: привязка обязательна (компиляция P2.5); `true`/allow → `Allow(Policy)`; `false`/`null`/deny → `Deny(Policy)`; назначения не читаются, `matchingGrants()` пуст. RequiresGrant: привязка необязательна; её отсутствие — pass; `true`/`null` — pass только при квалифицированном вкладе; `false`/deny → `Deny(Policy)` даже при superadmin. `ConsultsGrants`/policy OR grants нет. Метод выбирается только атрибутом `#[Decides(case)]` (`PanelCatalog::bindingMethod`), имя метода свободно; вызов через RuntimeInvoker по именам отражённых параметров (D15 §2), service DI отдельно; числовой массив user/resource запрещён. Политика, бросившая исключение, или вернувшая не bool/null/`Response`, — `Deny(PolicyError)`. `GateSource` вызывает определение ability напрямую (замыкание `Gate::abilities()` или метод политики, найденный `Gate::getPolicyFor`), **не** `Gate::check/inspect`: глобальные `Gate::before` (включая будущий `GateBridge`) не вызываются повторно. `GateSource` — `ProvidesPolicies`: его результат интерпретируется по режиму права как любая политика; одно право — одна политика (`DuplicatePolicyBindingException` при второй привязке). Индекс ability строится при компиляции каталога и попадает в снимок `catalog:cache`; ключи — FQCN модели и слово ability; поиск O(1). Поля отказа `Decision` не влияют на `allowed()`; `Decision::admits` не меняется. Native gate binding не требует Decides/fake policy class; discriminator сохранён в catalog:cache. Передача user/resource строго D15 §2; user-only метод не получает лишний class-string; missing required Model instance → PolicyError.
