### P4.1 — Пайплайн проверки и authority dispatcher

**Intent:** Дать ядру одну проверку права: внутренний `Authorizer::decide()` проводит запрос через подготовку, typed before-хуки, явный authority dispatcher (PolicyOnly — только политика без чтения назначений; RequiresGrant — квалификация каждой contribution целиком, OR между ними, scoped superadmin, политика только pass/veto), restrictions и наблюдающий after; любая ошибка шага — отказ с причиной; реализация `EvaluationContext`, контракты `Restriction`/`GrantCondition`, ядро вызова политики, трасса и property-тесты свойств движка.

**Implementation Rules:** `Authorizer::decide(Panel $panel, AccessRequest $request, ?ActorRef $actor = null): Decision`; actor по умолчанию — `ActorRef::of($subject->type(), $subject->id())`. Ошибки конфигурации/идентичности direct API выбрасываются: неизвестное статичное право → `UnknownPermissionException` (dynamic lookup — P4.4), субъект, которого панель не принимает, → `SubjectNotAcceptedException`, повтор `key()` двух restrictions панели → `DefinitionException`. Всё, что бросают хуки, источники, политики, условия, restrictions, — отказ с причиной и `Log::warning` (компонент, причина, класс исключения), наружу не выходит. `now` — один `DateTimeImmutable` UTC на проверку (`Carbon::now()` → immutable). Стадии строго по 09 §2: **Prepare** — `PanelCatalog::find(local)`, режим из `PermissionDefinition::$authority`, модель субъекта через `ModelSubjectResolver` (тип субъекта ↔ `Panel::subjectModels()`/morph alias; запись загружается `newQuery()->whereKey()->first()`, отсутствующая → `null`), `AccessScope` из запроса (по умолчанию `TenantRef::global()`/global context). **Boundary** — до P4.6 только строка none/none (D14 п.3): явный не-global tenant → `Deny(TenantMismatch)`, явный не-global context → `Deny(AssignmentScopeNotAccepted)`. **Before** — хуки в порядке регистрации, каждый `(AccessRequest, EvaluationContext): BeforeResult` через `Container::call`; `Deny` → `Deny(Hook, component)`; не-`BeforeResult` или исключение → `Deny(HookError)`; первый Deny/ошибка останавливает. **Authority/Policy** — ни один источник с `ProvidesGrants`/`ProvidesRoleGrants` не вызывается; `PolicyDecider` по привязке каталога: `true`/allow-`Response` → кандидат `Allow(Policy)`, `false`/`null`/deny-`Response` → `Deny(Policy)`, ошибка → `Deny(PolicyError)`; состояние — `CodeStateToken::of(panel, buildId, fingerprint)`. **Authority/Grants** — опрашиваются **все** источники с этими capabilities (`grants($subject, [$scope], $frame)`, `roleGrants(...)`), порядок не влияет (P12); исключение любого → `Deny(SourceError)` даже при уже найденном Allow; невалидный вклад (панель паттерна ≠ панель, scope не из запрошенных, не `Grant`/`RoleContribution`) → `Deny(SourceError)`; `RoleContribution` с ключом вне `PanelCatalog::roles()` — ноль прав и диагностика в трассе/логе, не ошибка. Квалификация одной contribution: `activeAt(now)` (`expiresAt <= now` истекла), затем все `GrantCondition` панели AND с кадром этой contribution (`role()` — экземпляр класса роли из контейнера, `grant()` — сама contribution); `false` → вклад отброшен, исключение → `Deny(ConditionError)`. Роль с `super_admin` квалифицирует любое Grants-право панели; иначе компилированные паттерны роли через `PatternMatcher::covers`; прямой `Grant` — своим паттерном. Нет квалифицированного вклада → `Deny(NotGranted)`. Есть привязка политики у права → veto: `false`/deny → `Deny(Policy)`, ошибка → `Deny(PolicyError)`, `true`/`null` → pass. Причина Allow: `Granted`, либо `SuperAdmin`, если право дают только superadmin-вклады. **Restrictions** — в порядке регистрации; `appliesTo` false → пропуск; при причине `SuperAdmin` и `exemptsSuperAdmin()` → пропуск; `deny` → `Deny(Restricted, component=key)`; исключение в `appliesTo`/`check` → `Deny(RestrictionError)`; restrictions проверяют любой кандидат, включая Policy и SuperAdmin. **After** — `(AccessRequest, EvaluationContext, Decision): void`, исключение → лог, решение не меняется. `EvaluationFrame` — immutable реализация `EvaluationContext`, копия на каждую contribution (`forContribution()`); `matchingGrants()` — квалифицированные прямые `Grant`, покрывающие право (пусто для PolicyOnly); `state()` — `CodeStateToken` (fenced источников ещё нет). Повторный вход в тот же кадр (панель, субъект, право, scope) из политики → `Deny(PolicyError)` с `RecursionDetectedException` в логе; другие scoped-проверки внутри политики разрешены. `Trace` пишет шаги только при `AccessRequest::isTraced()`. Компиляция панели проверяет списки: before/after — `Closure` или class-string invokable-класса; restrictions — объект или class-string `Restriction`; grantConditions — объект или class-string `GrantCondition`; иначе `DefinitionException` с происхождением записи; class-string разрешается контейнером на операцию, не при сборке. Встроенные источники и движок зависят только от `Contracts\*` (arch).
**Code Guidance:** Фикстурные источники реализуют только публичные контракты: `GeneratedSource` отдаёт заданные `Grant`/`RoleContribution` (с полями), `FailingSource` бросает в `grants()`/`roleGrants()`, оба считают вызовы (spy для PolicyOnly). `ScenarioGenerator` — детерминированный генератор (`mt_srand(seed)`, без новых зависимостей): панели `alpha`/`beta`, 2–4 источника, роли с паттернами, сроки вокруг зафиксированного `now`, условия; не менее 200 сценариев на свойство; сбой печатает seed. Свойства: P1 (добавление unconditional grant не уменьшает результат), P2 (каждый Allow прошёл restrictions), P3 (выдачи `beta` не влияют на `alpha`), P5 (детерминизм), P6 (ссылки не смешиваются: одинаковый id разных типов субъекта/контекста), P7 (`expiresAt = now` уже истекла), P8 (ошибка любого компонента → Deny), P10 (перенос выдачи между двумя фикстурными источниками), P11 (смена `resourcePrefix` не меняет решение по enum), P12 (перестановка источников, включая ошибку и superadmin), P15 (условия одной grant не удовлетворяются полями другой: `WeekdaysCondition` + `DepartmentCondition`). V53 — по одному тесту на каждую причину ошибки и на «restriction не может разрешить». V94/V90 — superadmin-`RoleContribution` с пустыми permissions: истёкшая или с ложным условием не даёт прав; source error после разрешающего источника при любой перестановке — Deny. V119 — RequiresGrant: политика `true` без выдачи → `NotGranted`; PolicyOnly: `null` → `Deny(Policy)`, spy-источники не вызваны, `state()` — `CodeStateToken`. V88 (часть) — явный не-global tenant/context в панели без политик: отказ даже при policy true, before Continue и superadmin.
