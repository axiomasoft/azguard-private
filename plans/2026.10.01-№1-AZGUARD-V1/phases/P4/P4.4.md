### P4.4 — DatabaseSource: назначения, сроки, dynamicPermissions, писатель

**Intent:** Дать панели встроенный источник назначений из БД: `DatabaseSource` читает scoped `role_grants`/`permission_grants` хранилища одним запросом на вид выдачи, отдаёт `RoleContribution`/`Grant` с decision-полями, опционально — dynamic actions выбранного tenant, является писателем панели; чтение DB authority проверяется циклом `T_before → чтения → T_after` через новый SPI `FencesReads`; `Storage` становится публичным с `Storage::own()`.
**Why:** RAG:— 05 §4.1 (`DatabaseSource`, builder-методы), 06 §1.1 (capabilities, `FiltersQueries`), §1.2 (правила выдач, dynamic требует TenantRef), 08 §2 (схема, ключи, индексы), 09 §8 «Чтение DB authority», §16 (StateToken только при потреблённом DatabaseSource), 19 §3, §5; 20 §2 «Read state», F05/F09/F10; D13, D24, D46, D52, D62, D64, D68, D80 досье; V54, V74, V82, V91, V92; probe P08; D12 п.4/п.8, D13, D14 п.3, п.6, п.7 плана.
**Scope Included:** `@api` `Sources\Database\DatabaseSource implements ProvidesPermissions, ProvidesRoleGrants, ProvidesGrants, StoresGrants, FiltersQueries, FencesReads, DescribesSchema`: `make()`, `rolesOnly()`, `dynamicPermissions()`, `storage(string|Storage)` (`'default'` по умолчанию), `models(?roleGrant, ?permissionGrant, ?permission)`, `decisionFields(array $roleGrant = [], array $permissionGrant = [])`; per-panel экземпляр и overlay параметров `config('azguard.sources.database')` (D8 п.7). `@spi` `Contracts\Sources\FencesReads` (`state(Panel, TenantRef): StateToken`), `Contracts\Sources\FiltersQueries` (`contextsCovering(SubjectRef, PermissionKey, string $contextType, EvaluationContext): ?AssignmentScopeSelection`), `Contracts\Sources\AssignmentScopeSelection` (`everywhere()`, `in(list<AssignmentScopeRef>)`, `nowhere()`). Цикл fence в стадии Authority для источников с `FencesReads` (до 3 попыток, затем `Deny(ConsistencyError)`); `Decision::$state` — `StateToken` при потреблённом fenced источнике. Dynamic lookup в Prepare: статичный промах при `dynamicPermissions()` ищется в overlay выбранного tenant (`PanelCatalog::withDynamic()`) внутри того же fence; имя, совпавшее со статичным или с первым сегментом/префиксом панели, — ошибка определения (V92). `Storage` — `@api` с поверхностью D14 п.3, `Storage::own()`. Регрессия P08.
**Scope Excluded:** Запись назначений и dynamic actions (`StoresGrants::apply`, `PermissionManager`, `grantRole`/`revokeRole` — P5.2/P5.3); `PanelNotWritableException` и отказ `rolesOnly()` при `grantPermission` (P5.3); кэш, refresh, сроки в памяти запроса (P4.8); один fence на пачки (P4.9); исполнение `FiltersQueries` в видимости (P4.12); doctor-проверки (P6.4); tenant-политики (P4.6 — здесь scope задаёт движок).

**Implementation Rules:** Источник пишется только на публичных контрактах и `Storage`-API (arch: `Sources\Database` — единственная зона источников с `Storage\Models`). Чтение — строго scoped: `WHERE panel = ? AND tenant_key IN (scope tenants) AND subject_type = ? AND subject_id = ? AND context_key IN (scope contexts)` по индексу `(panel, tenant_key, subject_type, subject_id, context_key)`; один запрос `role_grants` и один `permission_grants` на чтение (D44), чтение с primary (`useWritePdo`), без кэша и без загрузки всех tenants. Ключи — канон `HostKeyColumns`/`IdentityCodec`; строка с неканоничным id — `Deny(SourceError)`. Строка → вклад: роль/право, `AccessScope` из `tenant_key`/`context_key`, `origin`, `expires_at` (UTC), поля — только `decisionFields` через `GrantFields::decisionValues()` (V54: необъявленное поле не читается и в вклад не попадает). `rolesOnly()` — `permission_grants` не читается. Прямой grant PolicyOnly-права из строки не применяется (в Policy mode источник не вызывается вовсе). `state(Panel, TenantRef)` — `Storage::state(panel)` с primary; нет строки — `StateToken` с `version = 0`, incarnation `none`; `generation` — `PanelSettings::cacheGeneration()`, `fingerprint` — отпечаток панели. Fence: `T_before = state()`, затем все capability-чтения этого источника (роли, выдачи, dynamic overlay), затем `T_after`; равны — набор пригоден, иначе весь набор перечитывается, всего до 3 попыток, затем `Deny(ConsistencyError)`; токен не берётся из памяти запроса. Dynamic: только при `dynamicPermissions()`, только для выбранного `TenantRef` (в non-tenant панели — `TenantRef::global()`), authority всегда Grants; без флага таблица `permissions` не читается. `StoresGrants::transaction()` — `Storage::mutate` панели. `Storage::own()` по D14 п.3. `models()` проверяет подтипы базовых моделей и хранилище (`StorageMismatchException`, P3.3).
**Code Guidance:** Данные тестов пишутся только через `Storage::mutate($panel, fn (StorageMutation $m) => $m->table('role_grants')->insert([...]))` — прямые записи моделей запрещены (P3.4). P08 — одна роль даёт одинаковые права глобально и в точной области, включая шаблон `orders.*`; вне области прав нет. V74 — право `#[GrantedToAll]` из P4.2 и роль `DatabaseSource`, выданная тем же субъектам, — одинаковые решения на матрице прав. V91 — один каталог `BaseRole` в tenant A/B (через явный `TenantRef` запроса до P4.6), разные scoped назначения; ключ/класс уникален; строка удалённой роли — ноль прав. V92 (чтение) — dynamic action виден только своему tenant, конфликт со статичным именем — ошибка, паттерн покрывает только известные actions. V82 (чтение) — без флага dynamic lookup не выполняется, неизвестное имя → `UnknownPermissionException`. Fence: фикстурный fenced источник с подставными токенами — `T` различаются дважды → успех на третьей попытке; трижды → `ConsistencyError`; реальная гонка двумя процессами — P4.8. `DatabaseSourceEngineTest` (`->group('engines')`): чтение назначений с `VARBINARY`-ключами (D13), хвостовой пробел в id не совпадает, `expires_at` после 2038, бюджет «1 role_grants + 1 permission_grants + 2 state reads» через `DB::listen`.
