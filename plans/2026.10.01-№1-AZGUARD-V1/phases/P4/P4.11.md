### P4.11 — GateBridge

**Intent:** Подключить AzGuard к Laravel Gate как authoritative adapter: `Gate::before`-мост определяет, принадлежит ли ability AzGuard (полное/префиксное имя зарегистрированной панели, локальное имя выбранной панели, одно слово + модель/класс через индекс P4.3), выбирает панель тем же `PanelResolver`, выполняет тот же пайплайн и возвращает окончательный результат `GateBridge::toGateResult(Decision)` (с сохранением `Response`); чужая ability — `null` без чтения выдач.
**Why:** RAG:— 09 §1 (выбор панели, ownership, explicit qualified name всегда наш, class argument), §7 (алгоритм Gate, отсутствие additive fallback, ранний host `Gate::before`); D26, D65 досье; V27–V30, V64 (Gate), V93 (Gate), V15 (P9), V80 («Gate model checks obey mode»); probes P03, P09; D6 п.1 (`toGateResult()`), D8 п.7, D14 п.3, п.7 плана.
**Scope Included:** `@api` `Laravel\Gate\GateBridge` (invokable `before`-callback, регистрируется провайдером `Gate::before()` при boot); `GateBridge::toGateResult(Decision $decision): Response` (D6 п.1: Kernel не импортирует Laravel `Response`, адаптер — `GateBridge`; Allow → `Response::allow()`, Deny → `Response::deny($message, $code)->withStatus($status)` с причиной `DecisionReason::value` как code по умолчанию, 05 §10); классификация ability: (1) `panel:local` зарегистрированной панели или зарегистрированный префикс — наша до lookup каталога; неизвестное действие → `false` (Deny), не `null`; (2) локальное имя с точкой при выбранной панели (`PanelResolver` current/model), есть в каталоге или dynamic overlay → наша; (3) одно слово + модель/class-string аргумента → индекс ability P4.3 выбранной панели; неоднозначная пара → `false`; (4) иначе `null`, 0 запросов к хранилищу (D44). Ресурс и tenant/context берутся из аргументов (`[$model]`, `[$model, $context]`) через границу P4.6. Ошибки панели/tenant/ресурса/каталога для нашей ability → `false`/deny `Response` с логом. Регрессии P03 (смена owning item по D14 п.7) и P09 (Gate-строка); свойство V15 P9.
**Scope Excluded:** Blade-директивы и `@can` поверх Gate (стандартный Laravel — проверяются в тестах как есть), middleware `azguard.can` (P6.2), трейт и фасад (P5.1/P6.1), Filament (P7.2); исправление порядка чужих `Gate::before` хоста (ограничение интеграции, документируется P8.2; doctor — P6.4).

**Implementation Rules:** Kernel не импортирует Laravel (arch P1.4, D6 п.1). Для нашей ability результат окончателен: Allow → allow, любой Deny (`NotGranted`, `Policy`, ошибки) → deny `Response`; `null` (передача native Laravel) только для чужой ability. Additive-режима нет. Мост не вызывает `Gate::check` рекурсивно и не вызывает сам себя для ability, отображённых `GateSource` (их определения не являются именами AzGuard — P4.3). Субъект — `$user` Gate; панель, которая его не принимает, для локального/однословного имени — ability чужая (`null`); для явного `panel:local` — `false`. Выбор панели — только `PanelResolver`/`Authorizer::resolve()` (arch-правило P2.2). Ownership-индекс статичный, O(1), из снимка каталога. P03 map/spec/covered обновляются совместно; V27 владелец здесь, explain P4.10; toGateResult только GateBridge, Kernel scalar-only.
