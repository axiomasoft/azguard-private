### P4.12 — Visibility и exact query adapters

**Intent:** Дать exact видимость окончательного доступа: `visibleTo` добавляет к запросу хоста одну сгруппированную predicate, которая повторяет скалярную семантику того же права (tenant/owner AND фильтры областей AND restrictions AND authority по режиму), строится до count/order/limit/pagination, а любой влияющий компонент без exact query adapter даёт `VisibilityNotSupportedException`, а не широкий список.

PolicyOnly не читает assignment источники.  План запроса: `(существующие WHERE хоста) AND (tenant/owner ресурса) AND (общие фильтры областей) AND (before-pass) AND (restrictions) AND (authority)`; наш вклад — одна вложенная группа `where(fn …)`, существующие условия не ослабляются внешним OR. Authority: PolicyOnly — `allow`-predicate политики (назначения не читаются); Grants — `OR` по веткам-вкладам (каждая ветка — контексты из `contextsCovering` источника AND фильтры роли AND predicate условий этой contribution) или superadmin-ветка, затем `AND NOT deny` политики-veto; `null` политики — явный `abstain`, SQL NULL нормализуется адаптером. Superadmin требует qualified whole-witness branch: common/owner/before/policy остаются, exemptions restrictions применяются лишь в этой ветке. Компонент, влияющий на право, без exact пути (`FiltersAccessQueries` для policy/before/restriction/condition; native validated Builder для AssignmentScopeFilter; queryable accessAdapter::constrain) или вернувший `unsupported` — `VisibilityNotSupportedException` (одного warning недостаточно); компонент, детерминированно не применимый к запросу (`appliesTo` false), — `pass`. Нет субъекта → пустой результат (`whereRaw('1 = 0')`), Auth не читается (P04a). Явный неподдержанный scope → исключение. Подключение модели ресурса ≠ подключение хранилища: join с таблицами выдач запрещён; допускается только материализованный выбор `AssignmentScopeSelection::in()` из fenced чтения, не более 1000 ссылок, иначе `VisibilityNotSupportedException`. `decisionNow` один на вызов; predicate вычисляется на нём (сроки выдач). Scope ресурса строится через relation контекста (Client → project), не сравнением id разных типов. `candidates()` — внутренний, не публичная безопасная коллекция; `bounded()` проверяет каждого кандидата и считает total по разрешённым. Дерево partitions и branch evidence D15§5–§6. Ref candidate prefilter не authority; expiry/fields/role/scopes/conditions одной contribution. Before Continue/Deny exact partition в обоих modes. Folder constant witnesses supported, arbitrary automatic без adapter — unsupported. PolicyOnly bounded full host universe; превышен limit — ошибка, total честный. External model=null без SQL adapter exact unsupported.
