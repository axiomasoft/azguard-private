# P09 — Ключ с префиксом панели выбирает эту панель

**Probe:** P09
**Finding:** N09
**Owning rationale:** P09 используется и в V29 (P4.11, GateBridge); правило выбора панели вводит P2.2, GateBridge только применяет его.
**Owning item:** PLAN2.P2.2
**Scenarios:** V64, V65, V29
**Defect in 0.3:** При двух панелях и без текущей панели `Gate::allows('admin.users.delete')` возвращал false при действующем гранте; `hasPermission` без панели тоже отказывал (fallback `app`). Тест: `audits/2026-09-29-audit/opus/evidence/probes/OpusAuditProbesTest.php`, `it('P09: with two panels and no current panel the Gate abstains on a fully-qualified key')`.
**Required behavior:** Полное имя (`admin:users.delete`) выбирает панель `admin` на любом входе; локальное имя без панели при нескольких панелях и без панели по умолчанию бросает `PanelNotResolvedException`.
**Status:** covered: tests/Regression/P09Test.php::picks the panel of a full name without a current panel and throws for a local name

Уровень `PanelResolver` закрыт P2.2: полное имя выбирает `admin` без текущей панели, локальное имя бросает `PanelNotResolvedException`. Ответы трейта и Gate из сценария ниже — acceptance V64/V29 пунктов P5.1 и P4.11.

## Сценарий на целевом API

```php
$user->guard('admin')->grantPermission(AdminUserPermission::Delete);

expect($user->hasPermission('admin:users.delete'))->toBeTrue()
    ->and(Gate::forUser($user)->allows('admin:users.delete'))->toBeTrue()
    ->and(fn () => $user->hasPermission('users.delete'))->toThrow(PanelNotResolvedException::class);
```
