# Аудит выполненных P1–P2 — 2026-10-08

Проверены принятые правила фаз, D6/D10 и предыдущие P1/P2 review/owning-repair findings; продукт сверялся с текущим кодом. Пользователь разрешил автоисправление и исключил долгие проверки. Ниже пять подтверждённых групп дефектов; все исправлены в рабочем дереве. Коммит не создан.

## F1 — Major — разрешённые числовые id панели и префиксы ломали загрузку

**Owning:** P2.1 / P2.2; грамматика P1.2 разрешает `0`, `7`, `007`.

PHP преобразует ключи словаря `"0"`/`"7"` в `int`. `PanelRegistry::freeze()` передавал такой ключ в `write(string $id)`, а `PanelCompiler::prefixes()` — в `nameWithFirstSegment(string $segment)`. Даже корректная панель не загружалась. `configure('7', ...)` неизвестной панели также давал `TypeError` вместо `UnknownPanelException`; `cacheState()` имел такой же дефект при обходе числовых id.

**Доказательство RED:** новый `NumericIdentifiersTest.php`: 5 тестов, 1 passed, 1 failed и 3 errors; сообщения указывали на `PanelRegistry::write`, `PanelCatalog::nameWithFirstSegment`, `PanelRegistry::unknown`. `007` проходил, поскольку PHP сохраняет его строковым ключом.

**Исправление:** преобразование ключей словаря обратно в строки на границах строгих вызовов; исходная идентичность сохраняется. Новые проверки охватывают загрузку, configure, полный/prefixed ключ, snapshot, запись/восстановление cache, fingerprint и diagnostic cache state. Итог focused: 5 passed / 27 assertions.

**Файлы:** `packages/core/src/Panels/{PanelRegistry,PanelCompiler}.php`, `tests/Feature/Panels/NumericIdentifiersTest.php`.

## F2 — Minor — отпечаток рецепта терял поля native Gate binding

**Owning:** P2.5 и последующее расширение policy binding.

`PanelFingerprint::policy()` записывал только permission/PHP policy/method. Два `PolicyBinding::gate('orders.view', ...)` с разными native ability или resource model имели одинаковые метаданные. При смене рецепта и том же build id cached catalog сохранял прежнюю привязку.

**Доказательство RED:** реальная запись cache → изменение рецепта `old-access` в `new-access` → новый boot возвращал `old-access`. Регрессия проверяет изменение fingerprint и повторное чтение источника.

**Исправление:** fingerprint включает отдельные scalar-поля permission, kind, policy, method, ability и resource_model. Итог policy-binding suite: 8 passed / 34 assertions.

**Ограничение severity:** обязательство обновлять build id при code/config deploy остаётся в силе. Это исправление неполного fingerprint и его защитного поведения при изменившемся рецепте; не заявляется воспроизведённый обход доступа при корректно обновлённом build id.

**Файлы:** `packages/core/src/Panels/PanelFingerprint.php`, `tests/Feature/Catalog/PolicyBindingsCompatibilityTest.php`.

## F3 — Major — циклические PHP arrays исчерпывали память вместо отказа значений

**Owning:** P1.1 / P1.3; contract plain immutable fields и JSON identity composition.

`Grant::assertFields()` (также используемый `RoleContribution`) и `IdentityCodec::normalize()` рекурсивно копировали arrays без распознавания обратной ссылки. Self-referential array из ошибочного custom source или вызова API завершал PHP process по OOM, вместо диагностируемого `InvalidSourceContributionException`/`InvalidIdentityException`.

**Доказательство:** исходные классы из `git show HEAD:...` запускались в отдельных процессах с `memory_limit=32M`, внешним timeout 5 s и уникальной временной директорией. Оба завершились exit 255 с `Allowed memory size ... exhausted`. Рабочие файлы для RED не откатывались. Полный вывод: `p1-recursive-red.json`.

**Исправление:** `ReflectionReference` отслеживает только ссылки текущей ветви рекурсии. Повтор одной конечной структуры в соседних ветвях остаётся допустимым, ссылки отцепляются; произвольный предел глубины не введён. Новые tests проверяют циклы, совместно используемые ациклические массивы и неизменяемость fields. Focused: 10 passed / 24 assertions.

**Файлы:** `packages/core/src/Kernel/{Decision/Grant,Identity/IdentityCodec}.php`, соответствующие unit tests.

## F4 — Minor — diagnostics объявлял непригодный cache актуальным

**Owning:** P2.5; потребители диагностики P6.

Если version/build/fingerprint совпадали, но сам snapshot не восстанавливался, boot корректно пересобирал каталог. Однако `isCached()` возвращал true, а `cacheState()` — current: они проверяли только внешний контейнер cache entry.

**Доказательство RED:** в записанном snapshot изменён authority одного permission на `invalid`; новый boot повторно прочитал sources, но assertion `isCached() === false` падал. Файл — уникальный временный cache теста.

**Исправление:** единый приватный `PanelRegistry::cachedCatalog()` используется boot и диагностикой. Он проверяет возможность восстановления и совпадение внутреннего panel id с владельцем entry. После корректной перезаписи cache состояние вновь current. Focused cache + numeric suite: 14 passed / 67 assertions.

**Файлы:** `packages/core/src/Panels/PanelRegistry.php`, `tests/Feature/Catalog/CatalogCacheTest.php`.

## F5 — Major — FolderSource обходил D10 для ролей одинакового класса

**Owning:** P2.5 / P2.8, принятое D10; расширение незамкнутого прежнего R3.

Предыдущий repair сохранял origins для custom `ProvidesRoles`, но `FolderSource` предварительно объединял role FQCN из `roles([...])` разных plugins/provider. В `RoleCompiler` приходила уже одна роль с origin folder/provider. Два независимых вклада с одним role FQCN не давали обязательного `DuplicateRoleException`; compiled metadata терял владельца plugin.

**Доказательство RED:** два новых теста — одинаковый ManagerRole у provider/plugin и у двух plugins — завершились `Exception DuplicateRoleException not thrown`. Идемпотентный повтор внутри одного plugin оставлен разрешённым.

**Исправление:** discovery сохраняет `role_origins`; внутренний `PanelSources` объединяет provenance discovery и записей recipe до дедупликации и отказывает независимым origins. `RoleCompiler` получает действительный origin каждого folder role. Это также сохраняет корректную идемпотентность, когда один plugin отдаёт одну роль и через folder, и через custom source. Старый discovery cache без provenance пересканируется; формат каталога и публичный API не меняются.

**Регрессии:** explicit provider/plugin, два plugins, повтор внутри одного plugin, folder + custom source одного plugin, настоящий cache round-trip discovered plugin role с явным повтором того же класса. Итог 5 новых tests / 12 assertions. Итог соседних catalog/folder/plugins/modules/source-lifecycle групп: 233 passed / 865 assertions, 1.112 s (`p2-role-origins-tests.log`).

**Файлы:** `packages/core/src/Sources/Folder/{DiscoverySnapshot,PanelDiscovery}.php`, `packages/core/src/Sources/PanelSources.php`, `packages/core/src/Catalog/RoleCompiler.php`, `tests/Feature/Sources/Folder/RoleOriginCollisionTest.php`.
