# P6 и сквозные проверки: аудит с исправлениями

Дата: 2026-10-08. База рабочего дерева: `ba02a9a`. Полномочие — прямое поручение владельца проверить выполненные P1–P6 и исправлять находки; ограничение — без долгих прогонов. Это инженерный аудит и ремонт, а не новая полная GREEN-приёмка P6.11.

## Исправлено root

### P6-R1 — Minor — недекларированные runtime зависимости

Владелец: P6.2/P6.3, прежний F3 из `findings-P6-review`.

`packages/core/composer.json` не требовал `illuminate/auth`, хотя фасад, middleware и Gate bridge используют его классы. В полном Laravel зависимость замаскирована framework, в Illuminate-only установке классов может не быть. `AzGuardConfig::frequencyFrom()` также без проверки вызывал `CronExpression`, который Illuminate Console только предлагает установить.

Исправлено: явно объявлен `illuminate/auth` в существующей матрице 11/12/13; cron-парсер указан в `suggest`. При cron-строке без парсера выбрасывается понятный `InvalidConfigurationException` с именем ключа и пакета, вместо class-not-found. Новая regression запускает изолированный PHP process с обычным autoload, но без загрузки `Cron\CronExpression`, и проверяет доменную ошибку. Именованная частота по-прежнему принимается; для фактического запуска Laravel scheduler в Illuminate-only host нужен предлагаемый cron-парсер. Composer validate обоих manifests — PASS. Новые vendor dependencies не устанавливались; fresh Illuminate-only Composer solve не выполнялся.

### P6-R2 — Minor — атрибуты HTTP не учитывали resolved middleware

Владелец: P6.2/P6.4, `Laravel/Http/RouteChecks::missing()`.

Сборщик сравнивал сырые строки middleware. На Laravel 11/12 check, уже добавленный FQCN или middleware-группой, выполнялся повторно. Исключение того же check через FQCN с параметрами или группу не действовало на атрибут: fallback снова применял его. Это давало лишние policy вызовы и отличия между версиями router; doctor использовал ту же неверную диагностику.

Воспроизведено четырьмя новыми тестами. Исправление разрешает aliases/groups/exclusions через штатный Router до сравнения, сохраняя исходную строку для атрибута и точное сравнение параметров. Closures не приводятся к строке. RouteChecks suite — 23 tests / 113 assertions PASS. Более широкий Configuration/Http/Laravel набор — 167 / 538 PASS за 1.635 s.

Проверка по bare имени класса без параметров первоначально оказалась неверной тестовой предпосылкой: установленный Laravel сам не исключает параметризованный middleware таким способом. Регрессия исправлена на реально поддерживаемые FQCN+parameters и middleware group; semantics router не изменялась.

### P6-R3 — Minor — генератор изменял чужую секцию конфигурации

Владелец: P6.8, `Laravel/Console/Scaffold/ProviderRegistration`.

При `return ['panels' => [], 'custom' => ['providers' => []]]` поиск следующего `providers` добавлял panel provider в `custom.providers`. Упоминание provider в комментарии ошибочно считалось существующей регистрацией; закомментированный пример `panels.providers` мог стать местом вставки.

Оба случая воспроизведены RED. Исправление использует PHP tokens с исходными offsets: пропускает комментарии, ищет именно literal `return → panels → providers`, ограничивает поиск непосредственным уровнем массива. Запись остаётся текстовой, конфиг не исполняется ради поиска и сохраняет форматирование. Если literal список не найден, генератор оставляет файл и выводит прежнюю инструкцию. Проверены 17 generator tests / 56 assertions, PASS за 145 ms. Произвольные вычисляемые конфиги автоматически не переписываются.

### CI-R1 — Major — Redis gate отключён, тестовые наборы требуют чужой инфраструктуры

Владелец: P4.21, проводка CI из P0.

В `.github/workflows/tests.yml` job `test-redis` сохранял `if: false` и комментарий о будущем P4.8, хотя RedisStoreTest уже реализован. Обычные SQLite/DB/coverage/mutation entry points при этом включали Redis-тесты: в CI без ext-redis и сервиса они падали до проверки продукта. ReplicaLagTest относился к отдельной группе `replica`, поэтому исключение только `engines` оставляло штатный skip в локальном обычном наборе.

Исправлено: существующий Redis job включён; обычные SQLite, parallel, coverage/mutation entry points исключают `engines,redis,replica`, `test:feature` исключает Redis, PG/MySQL entry points исключают `redis,replica`. Dedicated `test:redis`, engine-команды и replica fixture сохраняют свои проверки и запрет skip. Это выбор стенда, а не снижение assertion/coverage порогов. Включение job локальное; workflow на GitHub не запускался и branch protection не менялась.

Проверки: YAML parsed через установленный PyYAML; оба Composer JSON валидны; `bash -n` изменённых gate scripts PASS. Настоящий Redis на уже работающем loopback:26379, отдельный случайный prefix в DB15: **2 tests / 26 assertions / 153 ms PASS**, без skip. Проверка исключения групп: те же Redis/replica файлы вместе с одной Configuration regression и `--exclude-group=engines,redis,replica` дают ровно **1 test / 5 assertions PASS**. `--list-tests` PHPUnit перечисляет suite до фильтрации, поэтому первоначальная попытка проверить исключения этим режимом не засчитана.

### P6-R4 — Minor — arch проверка зависела от пустых локальных каталогов

Владелец: P6.9, `tests/Arch/LegacyNamesTest.php`.

Удалённый Git-справочник оставил только пустые `legacy/0.3/packages/{core,filament}/vendor`. Файлов, ссылок и tracked legacy content нет. Проверка `not->toBeDirectory()` делала ту же ревизию красной в рабочем дереве и зелёной в свежем checkout.

Безопасное удаление пустых каталогов было отклонено hook `security.safe-dirs`; отказ не обходился. Arch contract уточнён на наличие файлов/ссылок, включая symlink вместо самого legacy root. Пустые неотслеживаемые Git каталоги допускаются; файл или любая ссылка всё ещё запрещены, отдельная проверка Composer autoload сохранена. Итог arch: **90 tests / 350 assertions / 6.071 s PASS** с проектным лимитом памяти 1G. Первый запуск с default 128M завершился OOM и не засчитан. Промежуточный запуск обнаружил также отставший от параллельной правки manifest; он пересобран генератором, внутренние новые классы исключены из публичного API.

### DOC-R1 — Minor — неточные актуальные инструкции и CLI-инвариант

Владелец: P3/P6.6.

`DEVELOPMENT.md` описывал три compose services с неверным именем `pgsql`, устаревшую проверку подстроки `test` и DB-only role definitions из 0.3. Теперь документ описывает четыре default services и replica profile, суффикс `_test`, code-role catalog и assignment tables 1.0, отдельные тестовые группы.

В `knowledge/P6-surface-model#Invariants` фраза «операций все tenants нет» противоречила нормативным обслуживающим `grants:prune`/`audit:prune` из досье 12 §1/§3. Через plan API уточнено именно это исключение по expiry/retention, без расширения адресных grant/revoke команд. Исторический findings-P6-review не переписывался.

Прежний P3-review R2 о физических именах PK уточнён решением D25: установленные PG/MySQL/SQLite grammars не используют заданное Blueprint имя primary key. Контракт сохраняет состав/уникальность ключей и ограничения длины; физическое имя следует engine. Схема и данные ради косметического имени не менялись.
