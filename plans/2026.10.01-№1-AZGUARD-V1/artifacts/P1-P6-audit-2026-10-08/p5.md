# Аудит P5 и дополнительно P6.5 — 2026-10-08

Исполнитель: native child `/root/audit_p5`; аудит с исправлениями, не независимый read-only verdict. Проверены исходники и тесты текущего дерева, P5-change-model, owning scope P5.1–P5.8, предыдущие findings-P5 и известный F4 из findings-P6-review. Полные suite, coverage, mutation, fleet, consumer/engine matrix не запускались по поручению пользователя.

## Исправленные находки

### P5-A1 — Minor, P5.2: проглоченный второй вызов continuation обходил exactly-once

- Сценарий: pipe сохраняет результат первого `$next($change)`, вызывает `$next` повторно, ловит `InvalidConfigurationException` и возвращает первый результат. Запись принималась, несмотря на прямое требование D20 откатить нарушение протокола.
- Причина: `OnceTerminal::guarded()` хранил только `$called = true`. При повторе исключение бросалось, но состояние нарушения не сохранялось; завершающая проверка всё ещё принимала первый результат.
- Доказательство: новый dataset `caught double next` в `tests/Feature/Changes/PipesTest.php` до исправления: ожидаемое `InvalidConfigurationException` не брошено.
- Исправление: число вызовов увеличивается до проверки; успех разрешён только при значении ровно 1. Перехват исключения внутри pipe не стирает нарушение.
- Проверка: regression проверяет исключение, неизменность version и отсутствие новой строки. Остальные skip-next, forged result, cancellation и успешный observing pipe остаются зелёными.

### P5-A2 — Major, P5.2/P5.3: revoke по выбранному id удалял новую строку

- Сценарий: `GrantManager::revokeMany([$id])` выбирает грант; changing pipe вложенно отзывает его и выдаёт ту же logical identity вновь. У новой выдачи другой id. Внешний revoke удалял новую строку, которую manager не выбирал.
- Причина: planned `Change::$grantId` сохранялся, но финальная validation сразу пропускала revocation. Writer искал актуальную строку по logical identity и не сравнивал её с выбранным id.
- Доказательство: новый `refuses to revoke a replacement grant that was not the selected id` в `NestedMutationTest.php` до исправления не бросал `StaleSelectionException`.
- Исправление: revocation после pipes под lock перечитывает exact identity и отвергает replacement с другим id. Live eligibility orphan/expired/inactive выдачи не проверяется; cleanup остаётся возможным. Если строки уже нет, сохраняется idempotent no-op.
- Проверка: regression использует публичный manager, настоящий вложенный ChangePipeline и AuditPlugin; при ошибке сравнивает полные rows/version/audit со снимком и отсутствие опубликованных событий.

### P5-A3 — Major, P5.4/P5.2: prune удалял продлённый grant

- Сценарий: prune выбирает истёкшую строку, pipe вложенно продлевает тот же grant до 2027 года, после чего внешняя expiry-revocation удаляет уже продлённую выдачу и публикует `GrantExpired`.
- Причина: expiry не сохраняла fingerprint выбранного состояния и проходила общую раннюю ветку revocation без повторной проверки.
- Доказательство: новый `refuses to expire a grant that a nested pipe renewed after the prune selection` до исправления не бросал `StaleSelectionException`.
- Исправление: `Change::expire()` фиксирует stored fingerprint; финальная revocation проверяет его для expiry. Изменившаяся expiry-выборка отменяет весь batch через `StaleSelectionException`, включая вложенную запись, audit и callbacks. Обычный revoke после update той же строки всё ещё допустим по принятому контракту.
- Проверка: regression сравнивает полные rows/version/audit до/после и zero events; существующие prune по tenants/origins, exact-now, batch, cancel и AuditPlugin проходят.

### P5-A4 — Minor, P5.1: пустой permission batch игнорировал конфликт panel

- Сценарий: `$user->guard('crm')->hasAnyPermission([], guard: 'backoffice')` и аналогичный `hasAllPermissions` возвращали false вместо договорного `ConflictingPanelException`.
- Причина: `SubjectAccess::decisions()` завершался до panel resolver. Аналогичный role path уже проверял selector даже для пустого массива.
- Доказательство: оба новых dataset в `ImmutableWrapperTest.php` до исправления не бросали исключение.
- Исправление: пустой batch сначала проходит существующий `select()`; false для своей панели сохраняется.
- Проверка: две отрицательные проверки конфликтного guard и две положительные проверки false для своей панели.

### P5-A5 — Minor, P5.1 / известный P6-review F4: P03 не проверял HasAzGuard

- Исходная спецификация называла trait, но тест использовал plain Model; строка Future ссылалась на уже завершённый P5.1.
- Исправление: отдельная fixture `tests/Fixtures/Gate/SubjectUser.php` расширяет прежнюю User-модель, подключает настоящий HasAzGuard/AzGuardSubject и сохраняет morph identity `user`. P03 проверяет и `$user->hasPermission()`, и `$user->guard('admin')->hasPermission()` до/после запрета, для обоих вариантов — hook и source.
- Спецификация P03 теперь описывает фактическое покрытие; future-строка удалена. Остальные общие fixtures не изменялись.

### P6-A1 — Major, P6.5: install мигрировал со старой конфигурацией

- Передано root после основного P5-аудита. `InstallCommand` писал host_keys/.env/provider на диск, затем вызывал migrate и doctor в уже загруженном приложении с прежними AzGuardConfig, StorageRegistry и frozen PanelRegistry.
- Следствие: новый host-key тип и connection не доходили до фактической схемы; созданная панель отсутствовала в финальном doctor. Одни spies на имена команд этого не ловили.
- Исправление: migrate и doctor запускаются отдельными PHP/Artisan process с argv-массивом, cwd host-приложения, `--no-interaction`, timeout 300 секунд и явным env выбранного connection. `--force` передаётся только migrate и только по запросу. Output/exit code сохраняются. Новых dependencies нет: Symfony Process входит в illuminate/console. Host providers/configure hooks восстанавливаются обычным bootstrap, никаких ручных reset frozen registry.
- Старый config cache очищается штатным `config:clear` перед setup; код выхода и физическое удаление проверяются. Ошибка очищения останавливает работу до записи файлов. Физическая проверка нужна в том числе потому, что Laravel 13 memoizes `configurationIsCached()`.
- При сохранённом `.env` connection без `--force` новый параметр не навязывается дочернему процессу. При отсутствующем `.env` существующее предупреждение о необходимости задать env сохраняется, а текущие child-команды получают выбранное значение.
- Доказательство исправления: реальный child process загружает короткое disposable Testbench application, опубликованный config и созданный provider; вызывает настоящую package migration. Обе configured connection жёстко `sqlite :memory:`. Проверены отличный от parent PID, connection `audit`, host_keys `bigint`, SQL column `integer`, panel `admin`. Аналогичное новое приложение создаётся для проверки doctor entry. Это проверка нового bootstrap и DDL, не полный consumer acceptance doctor и не engine matrix.
- Spies дополнительно проверяют точные argv/cwd/env/timeout, force, вывод, return codes, сохранённый connection, успешную и неуспешную очистку cache.

### P6-A2 — Minor, P6.5: ошибка make:panel не останавливала migrate

- Сценарий: install с неправильным `--panel` и `--migrate` получал отказ генератора, но всё равно запускал migration и doctor, возвращая код генератора только в конце.
- Исправление: ненулевой статус генератора возвращается немедленно.
- Проверка: `../escape` приводит к exit 2 и zero migrate/doctor calls.

## Выполненная проверка и ограничения

Все DB-прогоны выполнялись с `env -u AUTHORITY_REPLICA_TEST APP_ENV=testing DB_CONNECTION=sqlite DB_DATABASE=:memory:` и `timeout 55s`.

1. До правки A1–A3: targeted regressions — **3 failed / 0 passed**; отсутствие ожидаемых исключений воспроизведено. После правки + P03: **32 passed / 182 assertions**, 0.50 s.
2. До правки A4: **2 failed / 0 passed**, оба conflicting guard exception отсутствовали.
3. Итоговый P5 dependency closure: `pest tests/Feature/Changes tests/Feature/Concerns tests/Feature/Events tests/Feature/Plugins/Audit tests/Unit/Changes tests/Regression/P03Test.php tests/Regression/RegressionSpecsTest.php --compact` — **430 passed / 2647 assertions**, 4.94 s; skipped не было.
4. InstallCommand: **20 passed / 113 assertions**, 0.39 s, включая два настоящих child bootstrap/DDL на SQLite memory. При создании этой новой fixture были промежуточные ошибки порядка Testbench bootstrap и отсутствующих временных cache/views directories; исправлены до итогового PASS. Ошибки продукта и ошибки fixture не смешиваются.
5. Pint только перечисленных собственных PHP-файлов — exit 0; scoped `git diff --check` — exit 0. Root агрегирует PHPStan/API/plan checks; здесь полного analyse не запускалось.

Прочитаны ChangePipeline/ChangeValidator/OnceTerminal/ChangeFrame/ActingActor/ChangeJournal/ChangeEventPublisher, все scoped managers, HasAzGuard/SubjectAccess/SubjectPanels, event observer/delivery и связанные writer/locked-read границы. Проверены существующие contract tests no-op/version, rollback, failed nested subtree, captured event tokens, nullable/nested/fiber actors, tenant/origin partition, dynamic cascade и FormerKeys cleanup. Предыдущие P5 fixes не выдаются за новые находки. Schema/directories и engine-specific serialization здесь повторно полностью не аудировались; общий root распределяет остальной P1–P6 охват.

Остаточное ограничение проверки: новые revoke/prune scenarios доказаны в одной реальной SQLite mutation, включая вложенные операции и rollback; отдельный PostgreSQL/MySQL/MariaDB replay не запускался по запрету долгих прогонов. Полного доказательства «идеальности» или новой GREEN-приёмки всего плана этот bounded audit не заявляет.

Отказ не обходился; root уведомлён. Файл содержит только Testbench bootstrap stack trace и пути временной fixture, без DB-данных/секретов.
