## Forward risks

- P3 still owns `pruneJournal` (panel lock, direct `audit_log` write) and the move of `AuditPlugin` / `AuditTableExists`. The “no database source” doctor branch is now unreachable because compilation fails first.
- `IdentityColumns` is unused by `StorageSchema` (I15). A later caller has to keep the same `HostKeyColumns` arguments or the DDL drifts from the core tables.
- Participants are ordinary in-process code. `storage()` publishes the connection name, and `Change::context()->panel->writerSource()` still reaches `@internal` `mutation()` / `boundStorage()->table()`.
- A concurrency error inside an already-open host transaction is not retried (`Storage::mutate` when `transactionLevel() > 0`). The new tests do not throw that error while nested.
- `JournalParticipant` chunks of 500 assume a bind limit of at least 7000.
- `PluginContractTests` is stricter for a companion whose `register()` runs SQL.
