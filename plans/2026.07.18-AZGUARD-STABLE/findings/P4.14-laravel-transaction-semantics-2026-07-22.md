## Laravel transaction boundary

- The locked dependency is `laravel/framework` `v13.18.0` (`composer.lock:2213-2218`).
  Its local `ManagesTransactions::transaction()` rolls back after a closure exception and
  rethrows that exception (`vendor/laravel/framework/src/Illuminate/Database/Concerns/ManagesTransactions.php:26-46,88-116`).
- A nested transaction uses `SAVEPOINT` when the grammar supports savepoints
  (`...:145-174`) and rollback goes to that savepoint (`...:261-312`). Laravel's current
  API documentation describes the same transaction/savepoint facilities; the official
  database documentation confirms that `DB::transaction()` rolls back and rethrows on
  exceptions. Source: Perplexity Web, 2026-07-22, query
  “Laravel 12 database nested transactions savepoints DB::transaction QueryException
  PDOException MySQL exception propagation official documentation source”, citing
  [Laravel database documentation](https://laravel.com/docs/12.x/database) and
  [Laravel `ManagesTransactions` API](https://api.laravel.com/docs/12.x/Illuminate/Database/Concerns/ManagesTransactions.html).
  Confidence: high for the framework mechanism (locked source plus official docs).
- The first P4.14 attempt is the package-specific proof: the savepoint wrapper made
  PostgreSQL recover twice, while its MySQL DDL path surfaced `PDOException` rather than
  the original direct-seam `QueryException` (commit `93b01a0`, journal entries for P4.14).
  This is repository-grounded evidence, not an external portability claim.

## Composer timeout

`COMPOSER_PROCESS_TIMEOUT` controls Composer child-process execution time; Composer's
default is 300 seconds. P4.10 therefore keeps the already-approved explicit 900-second
environment override for the full MySQL lane, rather than changing global project config.
Source: Perplexity Web, 2026-07-22, query “Composer COMPOSER_PROCESS_TIMEOUT environment
variable process timeout official documentation”, summarizing the official
[Composer config documentation](https://getcomposer.org/doc/06-config.md#process-timeout)
and [CLI environment variables documentation](https://getcomposer.org/doc/03-cli.md#environment-variables).
Confidence: high (official sources).

## Raw verdict for D39

Laravel supports the required PostgreSQL savepoint mechanism, but the repository's own
MySQL DDL observation rules out applying it universally while retaining the existing
exception-class assertion. The smallest honest seam is therefore `pgsql`-only wrapping
inside this one test, with no catch/rewrite and no public or global-harness change.
