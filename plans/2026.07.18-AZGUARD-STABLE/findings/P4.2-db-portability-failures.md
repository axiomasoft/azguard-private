# P4.2 — реальные portability-баги, обнаруженные PG/MySQL-лейном

Инфраструктура лейна (env-driven `TestCase::databaseConnectionConfig()`, `composer test:pgsql`/
`test:mysql`, CI `test-db-matrix`, генерализация `ScopeClassMigrationRollbackTest`) готова и
рабочая — сама переключалка коннекшена не является источником нижеперечисленных сбоев (sqlite-лейн
по-прежнему 667/667 зелёный). Прогон существующего suite против реального PG16/MySQL8 (docker-стенд
P4.1, `PGSQL_PORT=25432`/`MYSQL_PORT=23306`) вскрыл множественные реальные portability-дефекты в
прикладном коде/миграциях — вне Scope P4.2 (только тесты/инфраструктура), чинить нельзя без D#.

## PostgreSQL 16 (`composer test:pgsql`) — 659/667 passed, 2 failed + 6 errors

1. **`AuthorizerExtendedTest` / `HasAzGuardTest`** — тест на wildcard-суперадмина падает
   (`Failed asserting that false is true`) на PG, при этом зелёный на sqlite. Похоже на
   boolean-каст/сравнение, чувствительное к драйверу (PG строго типизирует boolean).
2. **`ContextTableNameConfigTest`** (оба теста) — `column "expires_at" does not exist` —
   query builder ссылается на колонку `expires_at` в контекст-таблице с переопределённым именем,
   которой там нет (реальная схема/query-баг, не sqlite-снисходительность).
3. **`ModelHasRolesScopesUniqueConstraintTest`** (3 теста) — каскадный сбой
   `current transaction is aborted` после первого сбоя в этом же тесте/транзакции — PG не прощает
   продолжение работы с "отравленной" транзакцией (sqlite это не проверяет).
4. **`MorphTypeTest::it_assigns_a_role_to_a_ULID_keyed_model`** — `COALESCE types character and
   integer cannot be matched` при создании уникального индекса
   `model_has_scopes_unique (..., COALESCE(scope_entity_id, 0), COALESCE(role_id, 0), ...)` —
   PG строго типизирует COALESCE, а морф-колонки бывают то ULID (varchar), то integer — существующая
   миграция несовместима с PG для не-integer morph keys.

## MySQL 8 (`composer test:mysql`) — 610/667 passed, 57 errors

1. **Каскад `Base table or view already exists: az_guard_context_roles`** (~40 из 57 ошибок,
   весь `tests/Feature/Context/*`) — после первого реального сбоя в этом suite `RefreshDatabase`
   не откатывает миграции чисто на MySQL (вероятно FK держит DROP TABLE) → таблица не удаляется →
   каждый следующий тест падает на `CREATE TABLE`. Корень — первый сбой ниже.
2. **`ModelHasRolesScopesUniqueConstraintTest`** — `Cannot drop index 'model_has_roles_unique':
   needed in a foreign key constraint` — DDL-порядок в `down()` миграции не учитывает MySQL-специфику
   (нужно сначала снять FK, потом индекс; PG/sqlite так не требуют).
3. **`MorphTypeTest`** — `Data truncated for column 'model_id'` (ULID-строка не влезает/не матчится
   с типом колонки) и `Specified key too long; max key length is 3072 bytes` — составной уникальный
   индекс на `az_direct_grants` (`grantable_type, grantable_id, permission_key, panel_id`) превышает
   лимит MySQL при текущих ширинах `varchar`-колонок для non-integer morph keys.
2. **`DirectGrantResourceLikeEscapeTest`** (оба теста) — `LIKE %...% ESCAPE '\\'` синтаксическая
   ошибка на MySQL (`... near ''\' limit 50' ...`) — экранирование `LIKE`, написанное под
   sqlite/PG-грамматику, не переносится на MySQL-грамматику Laravel `whereLike`/raw.
3. **`ContextCrossRequestCacheInvalidationTest`** — тот же `key too long` (3072 bytes) на
   составном индексе `az_ctx_roles_unique` — тот же класс бага, что и `az_direct_grant_unique`.

## Итог

Минимум 3 независимых класса реальных дефектов (индексы/COALESCE не типобезопасны кросс-БД,
LIKE-escape не MySQL-грамматика, DDL-порядок down()-миграции не учитывает MySQL FK, плюс минимум
одна query-ошибка с несуществующей колонкой) — затрагивают `packages/core` (миграции, LIKE-запрос),
`packages/context` (та же индекс-проблема), возможно `packages/filament` (LIKE-escape тест лежит в
`tests/Feature/Filament/`). Замороженная P3 публичная поверхность фиксом не поменяется (это баги
реализации, не контракта), но объём правок затрагивает несколько миграций + query-builder код в
нескольких пакетах — многопакетный ремедиационный item(ы), не «генерализация теста».
