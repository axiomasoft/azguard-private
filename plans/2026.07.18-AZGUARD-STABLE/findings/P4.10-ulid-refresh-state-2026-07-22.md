# P4.10 — ULID morph failure: Testbench lifecycle evidence (2026-07-22)

> Layer 1. Raw external and repository evidence collected during the P4.10
> redesign. No production or test source was changed by this design pass.

## External verification — Orchestra Testbench / Laravel lifecycle

Perplexity Web query (2026-07-22): `Laravel Testbench getEnvironmentSetUp
defineDatabaseMigrations RefreshDatabase configuration timing custom TestCase morph
migrations`.

Verdict: configuration that migrations consume belongs in Testbench's early environment
hook, before `RefreshDatabase` begins its refresh lifecycle. The source returned by the
search is the Testbench project discussion
<https://github.com/orchestral/testbench/issues/206>. This external statement is used
only to confirm the framework lifecycle; the chosen repair is grounded in the installed
source below.

## Installed-source anchors

- `vendor/laravel/framework/src/Illuminate/Foundation/Testing/RefreshDatabase.php:83-91`:
  once static `RefreshDatabaseState::$migrated` is true, a later test case does not run
  `migrate:fresh`; it only starts a transaction on the existing schema.
- `vendor/orchestra/testbench-core/src/Concerns/CreatesApplication.php:543-550`:
  Testbench calls `defineEnvironment()` / legacy `getEnvironmentSetUp()` during app
  bootstrap, before providers are booted.
- `vendor/orchestra/testbench-core/src/Attributes/ResetRefreshDatabaseState.php:11-43`:
  the supported class attribute resets `inMemoryConnections`, `migrated`, and
  `lazilyRefreshed` before and after a test class.
- `vendor/orchestra/testbench-core/src/PHPUnit/AttributeParser.php:27-51` and
  `vendor/pestphp/pest/src/Factories/TestCaseFactory.php:166-177`: Pest's generated
  class extends the `uses(MorphTypeTestCase::class)` base and Testbench recursively
  reads parent class attributes, so an attribute on `MorphTypeTestCase` applies to the
  generated `MorphTypeTest` case.
- `phpunit.xml:6` enables `executionOrder="random"`.

## Reproduction and classification

The clean detached P4.10 PostgreSQL proof at `d164d94` failed only
`MorphTypeTest::it_assigns_a_role_to_a_ULID-keyed_model` under random seed
`1784693070`. The log (`/tmp/azguard-p410-final-pgsql-clean.log:929-951`) shows a
ULID bound to a `bigint` `model_has_roles.model_id` lookup (`SQLSTATE[22P02]`). A
focused PostgreSQL run of only the MorphType tests is green, because that test class
then performs the first migration with its ULID environment override.

`MorphTypeTestCase::getEnvironmentSetUp()` sets
`az-guard.column_names.morph_type=ulid`, and `MorphColumns::add()` correctly delegates
to `ulidMorphs()` when that config exists. Thus the failure is a test-isolation/config-
timing defect: a preceding default `TestCase` can set the static refreshed schema to
integer before the ULID class runs. It is not a `MorphColumns`, package migration, or
consumer installation defect.

## Rejected alternatives

1. Change `MorphColumns` or package migrations — rejected: it would repair a correct
   production config-before-migration contract for a test-suite-only static-state leak.
2. Use Laravel `DatabaseMigrations` for every MorphType test — rejected: it performs
   `migrate:fresh` per test and broadens both cost and lifecycle semantics beyond the
   class-boundary isolation required here.
3. Reset `RefreshDatabaseState` manually in Pest hooks — rejected: the installed
   Testbench attribute owns exactly this reset and preserves the test-case boundary.

**Raw verdict:** P4.15 owns a one-class Testbench reset-state annotation. P4.10 remains
the sole owner of the subsequent clean full PG/MySQL proof, CI, documentation and B6
checkpoint.
