## 1. COALESCE composite unique indexes — migration 000005 (core)

Файл: `packages/core/database/migrations/2026_01_01_000005_add_unique_constraints_to_model_has_roles_and_scopes.php`

- `model_has_roles_unique` — обычный Blueprint `->unique(['role_id','model_type','model_id'], 'model_has_roles_unique')`
  (строки 35-38; все колонки NOT NULL).
- `model_has_scopes_unique` — **raw `DB::statement`, уже driver-branched**:
  - MySQL-ветка (46-51): `... (model_type(191), model_id, (COALESCE(SUBSTRING(scope_entity_type,1,191),'')), (COALESCE(scope_entity_id, 0)), (COALESCE(role_id, 0)), (COALESCE(panel_id,'')))`
  - PG/SQLite-ветка (56-61): `CREATE UNIQUE INDEX ... (model_type, model_id, COALESCE(scope_entity_type,''), COALESCE(scope_entity_id, 0), COALESCE(role_id, 0), COALESCE(panel_id,''))`
- **Баг PG:** `COALESCE(scope_entity_id, 0)` — при morph-type `ulid`/`uuid` колонка `scope_entity_id` = `char(26)`/`char(36)` (строка), а `0` — integer → PG: *«COALESCE types character and integer cannot be matched»*. Fallback-литерал `0` захардкожен, не зависит от `Config::morphType()`.
- **`down()`** (64-82): сперва `dropUnique('model_has_roles_unique')` (Blueprint), затем raw-drop scopes-индекса (MySQL `ALTER TABLE ... DROP INDEX ...`, иначе `DROP INDEX ...`). FK тут НЕ снимаются (миграция только добавляет индексы). Комментарий 72-74: Blueprint `dropUnique()` компилит в `DROP CONSTRAINT` на PG — не матчит expression-индекс, потому raw.

## 2. Composite unique key-length — migrations 000002 (core) + 000010 (context)

- `az_direct_grant_unique` (имя в единственном числе!) — `packages/core/.../2026_01_01_000002_create_az_guard_role_permissions_and_direct_grants.php:43-46`, `->unique(['grantable_type','grantable_id','permission_key','panel_id'], 'az_direct_grant_unique')`. Все строковые колонки — Laravel-дефолт `string()` = varchar(255), длина не капается.
- `az_ctx_roles_unique` (6 колонок) — `packages/context/.../2026_01_01_000010_create_az_guard_context_roles_table.php:37-40`, `->unique(['model_type','model_id','context_type','context_id','panel_id','permission_key'], 'az_ctx_roles_unique')`. Все varchar(255), не капаются.
- **Баг MySQL:** 6× varchar(255) под utf8mb4 (4 байта/симв) >> лимит ключа InnoDB 3072 байта → *«Specified key too long»*. Единственное место, где префикс уже применён — scopes-индекс из §1 (191). Прочие — нет.
- **Расчёт-ориентир:** 191 симв × 4 = 764 байта/колонка; даже при 191 шесть строковых колонок ≈ 4.5 KB > 3072 → нужен per-column подбор длин (короткие идентификаторы), не единый 191.

## 3. Morph-колонки — MorphColumns.php (core)

`packages/core/src/Database/Schema/MorphColumns.php:18-47` — делегирует Blueprint-хелперам по `Config::morphType()`:
`ulid` → `ulidMorphs` → `{name}_id` = **char(26)**; `uuid` → `uuidMorphs` → **char(36)**; default → `morphs` → `unsignedBigInteger`. `{name}_type` — всегда varchar(255). Явных override длин нет.
- **Баг MySQL `Data truncated for column 'model_id'`:** ULID (26 симв) вставляется в колонку, собранную как `unsignedBigInteger` → морф-конфиг теста (`ulid`) не применился ДО прогона миграций RefreshDatabase (config-timing теста), либо индекс §1. Диагностировать: root в тайминге config vs миграция.

## 4. LIKE escape — DirectGrantResource.php (filament)

`packages/filament/src/Resources/DirectGrantResource.php:66-75` (в `getSearchResultsUsing`):
```php
$column = $query->getQuery()->getGrammar()->wrap($labelColumn);
return $query->whereRaw("{$column} LIKE ? ESCAPE '\\'", ['%'.self::escapeLikeValue($search).'%'])...
```
helper `escapeLikeValue` (204-207): `addcslashes($value, '\\%_')`. **Баг MySQL:** `ESCAPE '\\'` — захардкоженный raw-SQL, backslash-escape различается по драйверам (комментарий 69-72 сам отмечает про SQLite). Тест: `tests/Feature/Filament/DirectGrantResourceLikeEscapeTest.php` (2 кейса: `_` и `%` как литералы, строки 32-50).

## 5. expires_at — ТЕСТ-фикстура, не прикладной баг

- Запрос: `packages/context/src/ContextPermissionLayer.php:61-73` (`contextPermissions()`) — безусловно `whereNull('expires_at')->orWhere('expires_at','>',now())` на таблице из `config('az-guard-context.table_names.context_roles')`.
- Колонка `expires_at` **штатно существует**: добавляется миграцией `packages/context/.../2026_01_01_000011_add_expires_at_to_az_guard_context_roles_table.php:17-19`, читающей ТУ ЖЕ config-имя таблицы.
- Тест `tests/Feature/Context/ContextTableNameConfigTest.php`: helper `createContextRolesTable()` (36-47) строит кастомную таблицу **БЕЗ `expires_at`** (`$table->timestamps()` без колонки) и репойнтит config на неё (59/97) → запрос бьёт в несуществующую колонку. **Root — неполная тест-фикстура** (не прогоняет 000011-эквивалент); реальный кастом-путь (миграция 000011 по config-имени) колонку создаёт. Фикс — в ТЕСТЕ (добить фикстуру до канонической схемы), прикладной код не трогать.

## 6. Wildcard-суперадмин — НЕ boolean-DB-баг (каскад §1)

- `isSuperAdmin()` — `packages/core/src/Concerns/HasPermissions.php:153-156` → `permissionSet($panelId)->isWildcard()`.
- `PermissionSet::$wildcard` — `Registry/Values/PermissionSet.php:51` `in_array(self::WILDCARD, $unique, strict: true)` (строка `'*'`), геттер 157-160; hot-path `check()` короткоциркуитит на `$this->wildcard` (108).
- **Нет** boolean-DB-колонки (`is_super`) и НИ ОДНОГО сравнения PG `true/false` vs `0/1` в суперадмин-пути. Wildcard — `permission_key`-строка `'*'`, матч строковый. Единственные `=== true` — в тест-дубле `AzGuardFake.php:102/140` (замыкания) и `preg_match(...) === 1` матчеров — не DB-boolean.
- **Вывод:** сбой `AuthorizerExtendedTest`/`HasAzGuardTest` на PG — **каскад** от отравленной транзакции миграции §1 (COALESCE-индекс не создался → seed/insert падает → wildcard не засеян → `false`), НЕ независимый boolean-баг. Фикс §1 снимает симптом; отдельного item не нужно (verify после P4.8).
