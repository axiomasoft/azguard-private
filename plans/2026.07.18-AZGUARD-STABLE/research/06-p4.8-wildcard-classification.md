# 06 — P4.8 wildcard: минимальный follow-up и граница SemVer

> Слой 2. Синтез по `findings/P4.8-wildcard-follow-up-2026-07-21.md`.

## Решение

Две оставшиеся PG assertions принадлежат тестовым фикстурам, а не P4.8 migration
000005: anonymous class-name содержит NUL и не является переносимым значением
persistent `Role::$class_name`. P4.11 меняет только два tests на существующий
именованный `SuperAdminRole`, сохраняя проверяемое требование — wildcard
предоставляет полный доступ и через `hasPermission()`, и через `Gate::before`.

## Граница P3 / SemVer

P4.11 не меняет `packages/**`, публичные `@api` типы, API snapshot, конфигурацию
или семантику wildcard. По `root/semver-policy.md` это test-fixture portability
fix, не SemVer/bump-событие и не причина re-open P3. RAG:— (repo-grounded:
`root/semver-policy.md` §1–4; `findings/P4.8-wildcard-follow-up-2026-07-21.md`).

## Fail-closed граница

P4.11 не вправе заменить assertion на ожидание `false`, добавить driver-skip,
нормализовать production `class_name` или менять resolver. Если именованный class
fixture не докажет `true` на PG, исходная гипотеза опровергнута: item ставится
`🔴 Blocked` с §10 escalation и требуется отдельный design verdict о runtime
semantics / P3 freeze.
