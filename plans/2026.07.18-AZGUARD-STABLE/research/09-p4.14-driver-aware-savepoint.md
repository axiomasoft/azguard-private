# 09 — P4.14: preserve the cross-driver negative contract and recover PostgreSQL

> Layer 2 synthesis from `findings/P4.10-full-lane-blockers-2026-07-22.md §B`,
> `findings/P4.14-laravel-transaction-semantics-2026-07-22.md`, the current rollback
> test and the existing unique-constraint test helper.

## Facts and invariant

`ScopeClassMigrationRollbackTest` explicitly asserts that rollback with a null
`scope_class` throws `Illuminate\Database\QueryException`. That is an internal test
contract, not public package API, but it is deliberately cross-driver and already passes
on SQLite/MySQL when `migration->down()` is invoked directly. PostgreSQL requires a
savepoint because its ambient `RefreshDatabase` transaction otherwise remains aborted
after the expected error (`25P02`).

Laravel's locked transaction implementation provides a nested savepoint and rethrows a
closure exception, but the recorded MySQL DDL execution loses that original surface while
Laravel unwinds the savepoint. The existing `expectUniqueConstraintViolation()` in
`ModelHasRolesScopesUniqueConstraintTest.php` already embodies the relevant narrow
portability pattern: wrap the operation only for `pgsql`, retain direct execution and
`QueryException` elsewhere. RAG:✅ 2026-07-22
(`findings/P4.14-laravel-transaction-semantics-2026-07-22.md`).

## Alternatives considered

| Option | Result | Decision |
|:--|:--|:--|
| A — local `pgsql` savepoint helper; direct SQLite/MySQL operation; assert `QueryException` everywhere | Recovers PG transaction and retains the existing portable negative contract. A normal query after the assertion proves connection/lifecycle recovery. | **Recommended and selected (D39).** |
| B — universal wrapper, then assert `Throwable`, message text or SQLSTATE | Permits the MySQL wrapper-induced `PDOException`, but weakens the explicit contract and can accept a savepoint-unwind failure rather than the migration constraint failure. | Rejected. |
| C — change migration/harness or use raw PDO savepoints | Enlarges ownership and risks production/global test behaviour for a failure isolated to one expected test operation. | Rejected. |

No owner decision is required: this is a test-only implementation choice with a
repository precedent, deterministic three-driver validation, and no public product/API
trade-off. P3 snapshot and SemVer remain unchanged. RAG:— (repo-grounded:
`tests/Feature/ScopeClassMigrationRollbackTest.php:28-54`,
`tests/Feature/ModelHasRolesScopesUniqueConstraintTest.php:17-32`,
`root/semver-policy.md §1-4`).

## Exact implementation contract

In `tests/Feature/ScopeClassMigrationRollbackTest.php`, add one file-local helper accepting
the `migration->down()` closure. It must create:

```php
$operation = DB::getDriverName() === 'pgsql'
    ? fn (): mixed => DB::transaction($operation)
    : $operation;
```

The negative test calls `expect($operation)->toThrow(QueryException::class)` and then
queries the configured `model_has_scopes` table via `DB::table(...)->exists()` successfully.
It does not catch exceptions, inspect driver-specific text, use raw PDO, alter test
registration or touch the migration. The positive sibling remains unchanged except for
shared local helper use only if that removes duplication without changing its direct
success semantics.
