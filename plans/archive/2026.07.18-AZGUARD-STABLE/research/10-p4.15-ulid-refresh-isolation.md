# P4.15 — ULID morph RefreshDatabase isolation design

> Layer 2 synthesis, 2026-07-22. Sources: `findings/P4.10-ulid-refresh-state-2026-07-22.md`.

## Decision

Add `#[ResetRefreshDatabaseState]` from Orchestra Testbench to the existing
`MorphTypeTestCase` and import that attribute. This is the narrowest supported boundary
at which the ULID config must precede `RefreshDatabase`'s first `migrate:fresh`, even
when PHPUnit's global random order ran an integer-morph test class first.

The attribute resets before and after the generated Pest class. Its before-class reset
forces the first MorphType test to migrate under the existing `getEnvironmentSetUp()`
ULID override; its after-class reset prevents that ULID schema from becoming a hidden
input to a later ordinary test class. The test body, global `tests/Pest.php` mapping,
production `MorphColumns`, package migrations, configuration API, and P3 snapshot stay
unchanged.

## Acceptance proof

The previous full-suite seed `1784693070` is a deterministic regression proof, not a
new permanent ordering dependency. Run it on PostgreSQL after the minimal change, then
run the normal full PostgreSQL and MySQL lanes from a clean committed worktree. P4.10
cannot accept CI/docs/baseline until its own repeated union proof is green.

## Review focus

A read-only full review must verify that the attribute comes from the installed
Testbench namespace, is class-local to `MorphTypeTestCase`, and that no static manual
reset, Pest global hook, migration, public config/API, or P3 snapshot change entered the
diff. If the regression seed still fails, or the reset exposes a different dependency,
stop and escalate rather than widen P4.15.
