# 08 — P4.13/P4.14: recover P4.10 full-lane blockers

> Layer 2 synthesis from `findings/P4.10-full-lane-blockers-2026-07-22.md`, P4.10,
> P4.12 and D37.

## Decision

Do not rewrite P4.12 or P4.10 Completion Notes. They accurately preserve the evidence
available when those steps ran. Add two ordered, narrow follow-up items instead:

1. **P4.13** replaces only the forbidden `sha1()` implementation detail in the already
   proven private `MorphColumns` naming helper with a permitted deterministic digest
   derived from the same table-and-morph input. It retains the 48-character-name
   budget, all morph paths, long-name fixture and three-driver proof.
2. **P4.14** makes the expected PostgreSQL migration rollback failure transaction-safe
   in its test seam. A nested Laravel transaction creates a PostgreSQL savepoint; the
   test must prove the outer test transaction still accepts a query after the expected
   exception. It does not alter migration 000004's documented unsafe rollback.

Only after both are terminal may P4.10 re-run its full PostgreSQL/MySQL proof. CI,
documentation and the B6 review remain deliberately deferred: accepting them before the
full lanes are green would turn a failed validation gate into a cosmetic progress claim.

## SemVer and P3 freeze

Both repairs are internal/test-only. `MorphColumns::add()` keeps its public signature,
configuration keys, created columns and index semantics; only the physical index
identifier's digest implementation changes. P4.14 changes only test transaction
isolation. Therefore the planned SemVer impact is **no change** and the P3 API snapshot
must remain untouched. Any need to change public API/configuration or the snapshot is a
§10 escalation, not a local fix.
