# P4.10 — clean-vendor union-proof design

> Layer 2 synthesis from `findings/P4.10-debug-stdout-2026-07-22.md`.

P4.10 owns the command-level acceptance of full PostgreSQL and MySQL lanes. The P4.15
result proves the ULID lifecycle repair at the Pest level but cannot substitute for that
acceptance while a copied local `vendor/` emits strict-output noise.

Run the P4.10 validation from a new detached worktree at the P4.15 bookkeeping commit,
with `composer update --prefer-dist --no-interaction --no-progress` completed locally in
that worktree. Do not symlink or copy the caller's ignored `vendor/`; the fresh install is
the same dependency shape declared by `test-db-matrix`. Only a zero-exit PostgreSQL command
and a zero-exit MySQL command satisfy D30's union rule.

The committed `tests/Pest.php` mapping for a missing `DebugPgAbortTest.php` is recorded as
an unrelated stale registration. It must not be silently repaired in P4.10: a subsequent
item or explicit owner decision owns it if it affects a clean proof.
