# P4.8 — PG wildcard follow-up: воспроизведение и классификация (2026-07-21)

> Слой 1. Read-only воспроизведение после commits `1179b7c` и `91a67d7`.
> Вердикт: repo-grounded; production-код не менялся.

## Воспроизведение

```text
PGSQL_PORT=25432 composer test:pgsql -- --filter='Authorizer|HasAzGuard'
```

Результат: `37` tests, `35` passed, `2` failed, без SQLSTATE и без `current
transaction is aborted`.

| Тест | Assertion | Результат |
|:--|:--|:--|
| `tests/Feature/AuthorizerExtendedTest.php` | `Gate::allows()` для wildcard role | false, строка 53 |
| `tests/Unit/Concerns/HasAzGuardTest.php` | `hasPermission()` для wildcard role | false, строка 145 |

Оба теста записывают в persistent `roles.class_name` значение `get_class()` от
анонимного класса `extends BaseRole` через общий `createRoleWithClass()`
(`tests/Pest.php:120-126`). В PHP такое имя содержит NUL-байт: локальная
инспекция `bin2hex(get_class(new class extends X {}))` содержит `00` между
`anonymous` и координатами исходника. Это не валидный переносимый class-string
для хранимого поля `class_name`; `Role::getRoleLogic()` в этом случае возвращает
`null`, а `ClassRoleGrantSource` не получает `'*'`.

## Контроль, отделяющий fixture от runtime

```text
PGSQL_PORT=25432 composer test:pgsql -- --filter='IntegrationPolishTest|PanelRoleEnumEntrypointsTest|GateIntegrationScopedTest'
```

Результат: `22` tests, `22` passed. Эти тесты используют именованный
`AzGuard\Roles\SuperAdminRole` / `AzGuard\Tests\Stubs\Roles\SuperAdminRole` и
проходят тот же путь `createRoleWithClass()` → stored `class_name` →
`ClassRoleGrantSource` → `PermissionSet::wildcard()`.

## Классификация

`1179b7c` устранил COALESCE/rollback-корень migration 000005, а `91a67d7`
добавил UUID-доказательство. Оставшиеся две ошибки не являются ни PG boolean
семантикой, ни transaction-abort каскадом, ни доказательством дефекта wildcard
runtime. Это portability-дефект двух test fixtures: они пытаются хранить
непереносимое имя анонимного класса в `roles.class_name`.

Минимальный follow-up — P4.11: заменить только эти два fixture на уже имеющийся
именованный `tests/Stubs/Roles/SuperAdminRole.php`, сохранить обе assertions и
проверить SQLite + PG. Любой результат, при котором именованный fixture не
даёт wildcard на PG, означает runtime defect: P4.11 не ослабляет assertion и
эскалирует в `task:plan-design`, не меняя P4.8/P3 молча.
