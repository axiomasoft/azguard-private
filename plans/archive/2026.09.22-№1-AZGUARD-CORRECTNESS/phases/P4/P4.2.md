### P4.2 — Согласовать панель, permission и attribute validation

D14 storage rule (normative): Every final resolved panel ID is at most 128
characters before persistence on every official core/context/Filament/CLI write path,
regardless of `strict_panels`. The existing lenient
registration policy applies only to known/unknown IDs, not physical width. Validate
128 accepted and 129 rejected in strict and legacy modes, including configured
default/current/fallback paths. Record this public behavior change in RU/EN
upgrade/configuration docs, root CHANGELOG and API/BC evidence. P6.2 consumes
this boundary for its fresh and deployed MySQL index paths.

**Intent:** Сделать panel, permission, route-attribute и Gate ownership validation однозначной, не включая breaking strict defaults молча.
**Why:** RAG:— F12–F14 подтверждают inconsistent final-panel checks, silent missing attributes и enum/string normalization drift. Current `Gate::before` может отдать AzGuard wildcard `true` для ability, которой AzGuard не владеет. D7 фиксирует BC и один итоговый review.
**Scope Included:** Final explicit/default/current panel validation; strict empty-registry/default boot behavior; unified key syntax/resolution for strings, enums, Permission classes, wildcard and dynamic placeholders; missing-vs-skip route enforcement and doctor output; catalog ownership check before AzGuard authorization; RU/EN upgrade/config/access docs and root changelog.
**Scope Excluded:** Renaming existing `PermissionName`; forcing strict config on upgrade; requiring exactly three key segments; rejecting documented `*`, `**` or `{segment}` forms; intercepting ordinary Laravel policy abilities; rewriting all Gate calls; new route-cache compiler; repeated review stages.
**Inputs:** terminal GREEN `phases/P4/P4.1.state.md` · `phases/P1/P1.1.state.md` · `phases/P1/P1.2.state.md` · `findings/p1.1-execution-2026-09-23.md` · `findings/p1.2-execution-2026-09-23.md` · `plan.md` · `phases/P4/P4.md` · `findings/verification.md` · `decisions/D7-p4-runtime-validation-and-bounded-review.md` · `docs/reference.md` · `research/P4-design.md` · `research/P4-design-rag.md` · `artifacts/P4-design/examples.md`.
**Files:** `packages/core/src/Panels/PanelResolver.php` · `packages/core/src/Panels/Panel.php` · `packages/core/src/Permissions/PermissionKey.php` / `PermissionName.php` and one internal grammar/ownership helper if needed · `packages/core/src/Http/Middleware/CheckAccess.php` · `packages/core/src/Guard/Authorizer.php` · `packages/core/src/Registry/Resolver/EffectivePermissionResolver.php` · `packages/core/src/Configuration/Config.php` and config · `AzGuardDiagnostics.php` / `DoctorCommand.php` · targeted tests · EN/RU configuration/http-access/upgrading docs and root `CHANGELOG.md`.
**Required Reads:** 1) `packages/core/src/Panels/PanelResolver.php` 2) `packages/core/src/Panels/Panel.php` 3) `packages/core/src/Permissions/PermissionName.php` and `packages/core/src/Permissions/PermissionKey.php` 4) `packages/core/src/Http/Middleware/CheckAccess.php` 5) `packages/core/src/Guard/Authorizer.php` 6) `packages/core/src/Registry/Resolver/EffectivePermissionResolver.php` 7) `packages/core/src/Guard/AzGuardDiagnostics.php` 8) `tests/Unit/Support/StrictPanelsTest.php` and `tests/Feature/CheckAccessMiddlewareTest.php`.
**Implementation Rules:** Validate the final resolved panel in every resolver path. With `strict_panels=true`, unknown explicit/configured/current/fallback IDs throw even when registry is empty; validate configured default after providers register. With strict off, retain lenient/debug behavior. Add one opt-in `require_permission_attributes` config defaulting false: strict runtime raises a named configuration exception when `CheckAccess` reaches a controller action with neither `CheckPermission` nor `SkipGuardCheck`; doctor reports the same route as warning in legacy mode and error in strict mode. Preserve explicit skip. Route every supported permission form through one resolver/grammar helper: no empty/whitespace/empty-dot segments; global `*`, whole-segment hierarchical `*`/`**`, and documented `{name}` dynamic segments remain legal; do not impose a three-segment count. Avoid double panel prefix and scope pure/backed enums and Permission classes consistently. Extract/reuse one catalog-key ownership matcher (exact or registered dynamic definition) in resolver and Authorizer; `Authorizer::check()` returns `null` before wildcard evaluation for a foreign ability so later Laravel policies run.
**Code Guidance:** Prefer a small internal parser/matcher over a public value-object migration. Keep public `PermissionKey`, `PermissionName`, Panel, middleware and config signatures additive. Do not use prefix alone as ownership: require exact catalog membership or an existing dynamic definition. Reuse the resolver's current segment-wise dynamic semantics instead of duplicating regexes. Route diagnostics should inspect only routes carrying the AzGuard middleware and must tolerate closures/unresolvable actions.
**Validation:** 1) strict explicit/default/current/`app` fallback rejects unknown IDs including empty registry, while legacy cases stay compatible; registered defaults pass after boot; 2) missing attribute passes in legacy, fails with named exception in opt-in strict, and `SkipGuardCheck` passes in both; doctor warning/error and JSON/text remain aligned; 3) raw/full strings are not double-prefixed; pure/backed enums and Permission classes resolve to catalog keys; malformed empty/dot/space/wildcard/dynamic forms fail while valid multi-segment, `*`, `app.*`, `app.**`, and `app.team.{id}.edit` forms pass; 4) exact and concrete-dynamic AzGuard abilities are evaluated, foreign ability returns null and reaches a normal Laravel policy even for wildcard user; 5) `vendor/bin/pest tests/Unit/Support/StrictPanelsTest.php tests/Feature/CheckAccessMiddlewareTest.php tests/Feature/AuthorizerExtendedTest.php tests/Feature/AuthorizerPanelResolutionTest.php tests/Feature/DoctorCommandTest.php tests/Unit/Registry/EffectivePermissionResolverTest.php`; 6) P4.1 focused suite, changed-file Pint/PHPStan, docs parity, API snapshot if public surface changes, `git diff --check`; 7) one light review of changed lifecycle/validation/Gate seams, with material fixes inline and no automatic follow-up review.
**Deliverables:** Consistent panel resolution; explicit missing/skip policy; reusable compatible permission grammar and catalog ownership boundary; ordinary Gate fallback preserved; diagnostics/docs/changelog; one recorded light review for all P4.
