### P7.2 — Согласовать документацию и release recipe

**Intent:** Опубликовать согласованное описание итогового поведения и сделать changelog частью candidate commit до тега.
**Why:** RAG:— F21–F23, D10: `RELEASING.md` разрешает git-cliff после tag, а `changelog.yml` действительно пишет поздний commit в `main`; root `UPGRADING.md`, RU/EN pages и package references должны описывать принятые P1–P6 контракты без stale claims.
**Scope Included:** Current-state glossary definition/record/assignment; upgrade steps для cache identity/expiry, revision/backend, subclass models, panel/default validation, role identity, fresh/upgrade migrations; RU/EN/UPGRADING parity; один root `[Unreleased]` ledger; pre-tag candidate check и read-only release validation; точечные stale pointers.
**Scope Excluded:** Release/tag/push, GitHub Release, split/Packagist, массовое переписывание истории docs/changelog, автоматический schema/class rename, изменение Chatom и расширение security policy без measured finding.
**Inputs:** terminal GREEN `phases/P7/P7.1.state.md` and all predecessor closure from P1–P6 · `plan.md` · `phases/P7/P7.md` · accepted D3/D13/D6/D7/D8/D14/D10 decisions · P7.1 support/BC evidence · `research/P7-design.md` · `research/P7-design-rag.md` · `artifacts/P7-design/examples.md`.
**Files:** `CHANGELOG.md` · `UPGRADING.md` · `RELEASING.md` · `DEVELOPMENT.md` only for support commands · `docs/introduction/upgrading.md` and `docs/ru/introduction/upgrading.md` · affected EN/RU pairs in `docs/advanced/{cache,configuration,extending,panels,context}.md`, `docs/basic-usage/{roles,filament}.md`, `docs/introduction/{installation,known-limitations,versioning}.md` · `README.md`/`README.ru.md` only for stale entry links · new `bin/release-preflight.sh` · `.github/workflows/release.yml` · remove tag-triggered writer `.github/workflows/changelog.yml` after its check moves to `release.yml`; package historical changelogs are read-only.
**Required Reads:** 1) `RELEASING.md` 2) `.github/workflows/changelog.yml` 3) `.github/workflows/release.yml` 4) `CHANGELOG.md` 5) `UPGRADING.md` 6) `docs/introduction/upgrading.md` 7) `docs/ru/introduction/upgrading.md` 8) `decisions/D10-p7-qualification-and-pretag-release-contract.md`; predecessor decisions and P7.1 evidence are consumed from `Inputs`.
**Implementation Rules:** Reconcile docs against actual terminal P1–P7.1 behavior, not anticipated code. Use definition/record/assignment as glossary without renaming PHP classes or tables. Document exact old→new consumer steps, cache-key cold-start/invalidation, custom-source deadline limits, one-DB revision precondition, model subclass and connection limits, panel/default and role-name changes, scoped/context identifiers, fresh versus recorded migration paths and MariaDB verdict from P6. Keep RU/EN paired and links relative. Add release-visible entries to the single root `[Unreleased]`; do not rewrite published history or per-package ledgers. Decide candidate version and SemVer impact from the actual API/default/schema changes, then promote the reviewed root changelog section in the candidate commit before any tag. `bin/release-preflight.sh` accepts version plus candidate git ref, reads that ref's `CHANGELOG.md` without modifying checkout, and fails on missing/mismatched version heading; `release.yml` runs it against the tagged commit before publication. Remove the tag-triggered `changelog.yml` writer so no post-tag commit is needed. Describe the human owner approval/tag/push sequence in `RELEASING.md` but do not perform it in this item.
**Code Guidance:** Make the preflight small and deterministic; use git tree reads and exact version-heading matching, not a working-tree file or network release state. Preserve prerelease handling and the existing split guard. Fix only stale links found in touched pages.
**Validation:** 1) compare each affected RU/EN page and root `UPGRADING.md` with completed decision/behavior evidence; `bash bin/docs-parity-gate.sh` and `bash bin/docs-php-version-gate.sh`, then `npm run docs:build` with installed lockfile dependencies; 2) run `bin/release-preflight.sh` against isolated candidate git fixtures: matching version in commit passes, missing/wrong version and working-tree-only edit fail; no tag/push is created; 3) inspect `release.yml` tag path and confirm validation precedes `softprops/action-gh-release`, `changelog.yml` has no tag-triggered write path, `split.yml` guard remains; 4) `composer validate --strict` on root and package manifests if docs/version constraints change, `git diff --check`; 5) one light review of docs/BC/release-order seams, material fixes inline, no automatic phase audit.
**Deliverables:** Current RU/EN and root upgrade guidance, root release-visible changelog, deterministic pre-tag read-only check, release recipe with owner-controlled publication, removed late changelog writer and one recorded light review.
