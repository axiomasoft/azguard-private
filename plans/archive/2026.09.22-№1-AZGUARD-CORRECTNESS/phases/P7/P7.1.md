### P7.1 — Подтвердить regression и support matrix

D13 and D14 qualification rules (normative): Cross-process cache evidence
includes an authorization check inside a nested transaction, outer rollback,
and a different commit reusing the same revision number; no rolled-back allow
may reach another reader. MySQL qualification records exact version, page size,
row format, charset and emitted index DDL for int/ULID/UUID, exercises fresh
and recorded-upgrade paths, and proves overlength `panel_id`/unsupported profile
fails before schema-changing DDL without row loss. Any smaller-page or MariaDB
profile remains explicitly unsupported unless separately proven; do not label
the generic `mysql:8` job GREEN for D14 without those observations.

**Intent:** Квалифицировать накопленные P1–P6 correctness changes на объявленных runtime, SQL и cache seams.
**Why:** RAG:— F21–F23 и D10: DB matrix, API snapshot и mutation gates уже существуют, но installability каждой объявленной комбинации и реальный Redis не доказаны текущим design. Array-store и skipped Redis test не покрывают lock/worker поведение.
**Scope Included:** Composer-resolved PHP/Laravel/Testbench/Filament grid; SQLite и PostgreSQL/MySQL affected regressions; настоящий Redis cross-process/worker lane; cross-package сценарии revoke/expiry/identity/model override/panel/migration по результатам predecessors; объяснение API snapshot delta и measured quality verdict.
**Scope Excluded:** Дублирование продуктовых исправлений P1–P6, произвольное расширение matrix и численных floors, новый DB CI с нуля, незащищённые prod/dev database targets, full ecosystem fleet check.

**Implementation Rules:** Begin with predecessor completion evidence and an affected test map, then add only missing cross-package assertions. A failed scenario in P1–P6 behavior returns to that owning item; P7 owns test/CI orchestration gaps. Keep the existing PHP/Laravel/Testbench include/exclude grid unless Composer resolution proves a specific cell unsupported; run minimum and stable dependency resolution in clean CI/isolated copies, record exact failing cell and correct declaration or matrix together. Preserve PostgreSQL 16/MySQL 8 jobs and require proven `*_test` DB targets before any local engine test. Add a Redis 7 service plus PHP Redis extension to a dedicated CI lane; use a unique test prefix and remove only that prefix after tests. Target cross-process race and post-commit/revoke/failure scenarios from P2; make missing Redis, extension or an unintended skip fail the lane. Keep SQLite array-store tests separate. Snapshot updates require a decision explaining API/BC/version effect and may not be automatic. Evaluate current coverage/type/mutation gates from actual runs; preserve established thresholds unless a separately accepted measured change calls for another value. Do not claim an unavailable CI lane green.
**Code Guidance:** Prefer extending the existing cache/worker tests and CI workflow over new harnesses. Use one end-to-end test only if no current test joins the relevant package seams. Report a compact matrix of command, environment, pass/fail/skip and exact limitation.
**Validation:** 1) `composer validate --strict` for root and each package, plus clean CI `composer update --prefer-lowest` and `--prefer-stable` for each declared PHP/Laravel/Testbench cell; any infeasible cell has a reproduced dependency conflict and an aligned declaration; 2) `vendor/bin/pest --ci` on SQLite `:memory:` and `composer test:pgsql`/`composer test:mysql` after isolated `azguard_test` preflight, with P6 migration tests included; 3) dedicated Redis lane runs `tests/Feature/PermissionCacheCrossProcessRaceTest.php` and affected cache/worker regressions against actual Redis, asserts no relevant skip, tests two processes and commit/revoke behavior; 4) `composer test:api-snapshot`, `composer analyse`, `composer lint:check`, `composer refactor:check`, `composer test:types`, existing coverage/mutation scripts with real coverage driver where required; each result records pass/fail/skip and version, never converts honest skip into pass; 5) one light review of resulting matrix, Redis isolation and cross-package assertions, material fixes inline; `git diff --check`.
**Deliverables:** Resolved support grid, actual SQLite/SQL/Redis regression evidence, justified API/BC verdict, measured existing quality gates, narrow CI/test changes and one recorded light review.
