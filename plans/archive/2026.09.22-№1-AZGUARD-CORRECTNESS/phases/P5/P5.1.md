### P5.1 — Зафиксировать и обеспечить identity code/DB roles

**Intent:** Синхронизировать code roles по устойчивой panel-qualified persisted identity и исключить принятие чужой роли.
**Why:** RAG:— F16: `roles.name` globally unique, `class_name` nullable/nonunique, sync ищет class и создаёт raw name; `ResolvesRole` fallback по `getName()` может выбрать DB-only/чужую роль. D8 задаёт BC и controlled rename.
**Scope Included:** Canonical name для code role, preflight/dry-run и transactional sync, class/name/instance lookup, `hasRole`, super-admin path, stale/invalid diagnostics, RU/EN docs и root changelog.
**Scope Excluded:** Schema/table rename; unique class index до P6; silent DB-only adoption; blind FQCN refactor fallback; автоматическая миграция consumer names; замена level или RoleInterface.
**Inputs:** terminal GREEN `phases/P3/P3.2.state.md` и `phases/P4/P4.2.state.md` · `phases/P2/P2.3.state.md` · `plan.md` · `phases/P5/P5.md` · `findings/verification.md` · `decisions/D8-p5-role-identity-and-safe-scaffold.md` · `research/P5-design.md` · `research/P5-design-rag.md` · `artifacts/P5-design/examples.md`.
**Files:** `packages/core/src/Models/Role.php` · `packages/core/src/Commands/SyncRolesCommand.php` · `SuperAdminCommand.php` · `RoleAssignmentCommand.php` · `packages/core/src/Concerns/ResolvesRole.php` · `HasRoles.php` · `packages/core/src/Guard/AzGuardDiagnostics.php` · one internal role-identity helper if needed · `tests/Feature/SyncRolesCommandTest.php` · `RoleClassResolutionTest.php` · `DoctorCommandTest.php` · `tests/Unit/Models/RoleGetRoleLogicTest.php` · `docs/basic-usage/roles.md` and RU counterpart · `docs/advanced/seeding.md` and RU counterpart · `docs/introduction/upgrading.md` and RU counterpart · root `CHANGELOG.md`.
**Required Reads:** 1) `packages/core/src/Models/Role.php` 2) `packages/core/src/Commands/SyncRolesCommand.php` 3) `packages/core/src/Concerns/ResolvesRole.php` 4) `packages/core/src/Concerns/HasRoles.php` 5) `packages/core/src/Commands/SuperAdminCommand.php` 6) `packages/core/src/Guard/AzGuardDiagnostics.php` 7) `packages/core/database/migrations/2026_01_01_000000_create_az_guard_tables.php` 8) `tests/Feature/SyncRolesCommandTest.php` 9) `tests/Feature/RoleClassResolutionTest.php` 10) `decisions/D8-p5-role-identity-and-safe-scaffold.md` 11) `phases/P3/P3.2.state.md` 12) `phases/P4/P4.2.state.md`.
**Implementation Rules:** Derive deterministic persisted name for every panel-scoped code definition as `{panelId}:{getName()}`; validate components and column length before write. Keep `class_name` as exact code lookup key and `roles.id` as assignment FK; code-role rename updates the same row in one transaction after preflight. Reject duplicate class definitions/rows, canonical-name collision with any other row including DB-only, and stale class rename ambiguity before mutation; dry-run reports the same decisions without writes. Never take a DB-only row merely because its name matches a class. Name strings resolve exact persisted `name`; class/instance checks compare exact `class_name` with no `getName()` fallback. A non-null invalid/missing definition raises a named error and doctor error; null remains DB-only. Preserve `getLevel()`/`level`, custom `Config::roleModel()`, and P2 revision/invalidation for changed rows; no-op does not bump revision. Existing unqualified code rows get controlled upgrade preserving IDs/pivots; ambiguous conflicts fail with manual instructions. Built-in global `SuperAdminRole` retains reserved `super-admin` and global wildcard with exact class lookup; same-name DB-only collision fails before assignment.
**Code Guidance:** Centralize canonical-name and checked class resolution only where shared by sync/lookup; do not mass-assign `class_name`. Document that consumers using old unqualified name strings must migrate to qualified names or class strings. P6 owns any later schema uniqueness proof.
**Validation:** 1) Two panels with different AdminRole FQCN and equal `getName()` create distinct rows, stable IDs and assignments across second sync; 2) controlled legacy rename preserves row ID/pivots/level and reports old/new names in dry-run, while DB-only collision and duplicate class fail before write; 3) exact name/class/instance lookup and `hasRole` distinguish both roles, DB-only remains assignable, missing class string cannot resolve through same name; 4) invalid/missing/noncontract class gives doctor error and fail-closed runtime; 5) built-in super-admin and configured role-model subclass pass; 6) `vendor/bin/pest tests/Feature/SyncRolesCommandTest.php tests/Feature/RoleClassResolutionTest.php tests/Unit/Models/RoleGetRoleLogicTest.php tests/Feature/DoctorCommandTest.php`; 7) focused P2/P3 role/revision regressions, affected Pint/PHPStan, API snapshot if public signatures change, RU/EN upgrade parity, `git diff --check`.
**Deliverables:** Safe canonical code-role identity and lookup, controlled legacy transition, DB-only preservation, actionable diagnostics, focused regressions and upgrade docs/changelog.
