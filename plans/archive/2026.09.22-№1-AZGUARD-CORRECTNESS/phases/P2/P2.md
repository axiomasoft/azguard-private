## Scope Included

Core synchronizer для Filament/CLI: validate desired set до изменения, role-row serialization, optimistic fingerprint, connection-aware transaction и явная replacement scope.

Глобальная permission-state revision в DB изменяется в одной транзакции с официальной mutation и входит в request/durable cache identity. Role/scoped/context/direct paths не полагаются на users()-only обход; loaded relations и scoped-role cache согласованы с revision.

Внутри транзакции на authorization connection D13 отключает чтение и запись всех reusable
cache tiers; проверка разрешения читает текущие DB rows без stale loaded relations и не
публикует uncommitted revision ни при nested commit, ни при rollback.

Cache backend failure не возвращает stale allow. Явная deployment generation и `guard:cache-reset` инвалидируют только AzGuard namespace без store-wide flush.

## Scope Excluded

Durable outbox/audit delivery; production Redis/DB writes; per-role/per-subject revision matrix; поддержка разных DB connections; требование буквально одного increment как замена correctness.

## Acceptance

Невалидный desired set, stale editor, insert/revision failure и rollback не меняют effective rights. Filament снимает только видимые управляемые keys и сохраняет wildcard/dynamic/unknown-panel rows.

После commit новый check любого subject type читает новую revision; старый concurrent refill остаётся под старым key. Official role/scoped/context/direct mutation даёт один authoritative state transition; no-op revision не меняет. Cache outage либо вычисляет uncached current state, либо fail-closed. Reset сохраняет чужие cache keys.

Сценарий 7→uncommitted 8→outer rollback→другая committed 8 не создаёт и не
читает cache entry с правами откатившейся мутации, в том числе в другом reader.

## Validation strategy

P2.1: validation до write, duplicate normalization, insert failure rollback, no-op, stale concurrent editor; не терять невидимые UI wildcard/dynamic/unknown-panel grants.

P2.2: reader до/после root commit, rollback/nested transaction, old-revision concurrent refill; role/scoped/context/direct official paths, loaded roles и scoped-role request cache. Разные connections дают explicit unsupported verdict.

P2.3: cache get/put/lock fault injection, revision write failure, retry, deployment generation; контрольный чужой cache key переживает `guard:cache-reset`.

Конкретные test files/команды и expected outcomes закреплены в item Validation.
Reproduction и исправление выполняются в одном owning item; не коммитить
полную красную suite как отдельную обязательную фазу.
