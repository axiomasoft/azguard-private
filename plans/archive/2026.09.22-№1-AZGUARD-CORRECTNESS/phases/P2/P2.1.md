### P2.1 — Один атомарный role-permission sync

**Intent:** Заменить destructive Filament/CLI writes одним атомарным sync, который меняет только заявленную область и отклоняет stale concurrent edit.
**Why:** RAG:— `findings/verification.md` F4–F5: delete+bulk insert не транзакционны, обходят validator и удаляют невидимые форме rows. D13 фиксирует managed-set и optimistic-fingerprint contract.
**Scope Included:** Internal core synchronizer и compact selection/result values; полная pre-validation; role-row lock; diff-based writes; explicit managed keys/panels; expected fingerprint; Filament и `guard:role-permissions` callers; no-op result.
**Scope Excluded:** Permission-state revision/invalidation P2.2; public HTTP API; durable audit events; переименование tables/models; поддержка role и role-permission models на разных connections; удаление невидимых wildcard/dynamic/unknown-panel rows из Filament.
**Inputs:** terminal GREEN `phases/P1/P1.2.state.md` · `plan.md` · `phases/P2/P2.md` · `findings/verification.md` F4–F5 · `decisions/D13-p2-transaction-local-cache-bypass.md` · `research/P2-design.md` · `research/P2-design-rag.md` · `artifacts/P2-design/examples.md`.
**Files:** new `packages/core/src/Roles/RolePermissionSynchronizer.php`, `RolePermissionSelection.php`, `RolePermissionSyncResult.php` and conflict exception · `packages/core/src/Commands/RolePermissionsCommand.php` · `packages/filament/src/Resources/RoleResource/RelationManagers/RolePermissionsRelationManager.php` · targeted `tests/Feature/RolePermissionSynchronizerTest.php`, `tests/Feature/RolePermissionsCommandTest.php` and Filament sync test.
**Required Reads:** 1) `packages/filament/src/Resources/RoleResource/RelationManagers/RolePermissionsRelationManager.php` 2) `packages/core/src/Commands/RolePermissionsCommand.php` 3) `packages/core/src/Models/RolePermission.php` 4) `packages/core/src/Models/Role.php` 5) `packages/core/src/Registry/Validation/CatalogRolePermissionValidator.php` 6) `tests/Feature/RolePermissionValidationTest.php` 7) `tests/Feature/RolePermissionsCommandTest.php`.
**Implementation Rules:** Normalize `(panel,key)` tuples and validate the complete selected set before opening writes. Inside the role model connection transaction, lock the role row, recompute a stable fingerprint of the currently managed subset, reject mismatch, then delete/add only the diff. Filament's managed universe is exactly the rendered registered catalog keys: persisted keys outside it survive. CLI `sync --panel` is an explicit whole-panel replacement; add/remove are one-key scopes. Reject cross-connection role/permission configuration before mutation. Duplicate input collapses deterministically. Empty/no-change result writes nothing. Preserve custom configured models where current code already supports them; P3 owns remaining override gaps.
**Code Guidance:** Keep selection/result as small immutable values; no repository/interface pair. Fingerprint sorted canonical tuples, not row order/timestamps. Do not depend on Filament panel-wide transactions or Eloquent bulk events. Keep conflict user-visible and retryable; do not silently last-write-wins.
**Validation:** 1) unknown/invalid selected key and stale fingerprint leave rows byte-for-byte unchanged; 2) injected insert failure rolls back prior delete; 3) duplicate keys normalize and exact retry is no-op; 4) two editors from one snapshot serialize and second receives conflict; 5) Filament uncheck removes visible exact key but preserves wildcard, dynamic concrete, unknown panel and non-rendered rows; 6) CLI add/remove/sync retain documented scopes; 7) `vendor/bin/pest tests/Feature/RolePermissionSynchronizerTest.php tests/Feature/RolePermissionValidationTest.php tests/Feature/RolePermissionsCommandTest.php <targeted-filament-sync-test>`; 8) `vendor/bin/pint --test` on changed PHP files and `git diff --check`.
**Deliverables:** One core atomic synchronizer; explicit managed-scope/fingerprint contract; migrated Filament/CLI callers; rollback/no-op/concurrent-editor/invisible-row regressions.
