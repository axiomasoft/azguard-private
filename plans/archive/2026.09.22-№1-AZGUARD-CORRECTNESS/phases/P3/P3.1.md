### P3.1 — Закрыть runtime bypasses config моделей

**Intent:** Сделать четыре опубликованных model override рабочими на официальных core read/write paths.
**Why:** RAG:— `findings/verification.md` F9–F10: `HasRoles`, `HasScopedRoles`, `HasDirectGrants` и `GrantBuilder` обходят Config; `DatabaseRoleGrantSource` начинает raw query без model semantics. D6 фиксирует subclass/table/scope/connection contract.
**Scope Included:** Config model validation; configured Role/Scope/DirectGrant/RolePermission в relations, scoped-role mutations/reads, grant builder и database-role source; model table/connection/global-scope semantics; explicit same-connection guard до mutation/query join.
**Scope Excluded:** ModelRegistry/repository abstraction; arbitrary non-subclass ORM; context model configurability; split-connection relations/transactions; global scope для raw pivot table; blanket architecture ban на базовые type-hints.
**Inputs:** terminal GREEN `phases/P2/P2.3.state.md` · `plan.md` · `phases/P3/P3.md` · `findings/verification.md` F9–F10 · `decisions/D6-p3-subclass-model-contract-and-single-review.md` · `research/P3-design.md` · `research/P3-design-rag.md` · `artifacts/P3-design/examples.md`.
**Files:** `packages/core/src/Configuration/Config.php` and model-config exception · `packages/core/src/Concerns/HasRoles.php` · `HasScopedRoles.php` · `HasDirectGrants.php` · `packages/core/src/Grants/GrantBuilder.php` · `packages/core/src/Registry/Sources/DatabaseRoleGrantSource.php` · targeted custom model stubs and new `tests/Feature/ConfiguredModelsTest.php` · affected existing grant/scoped-role tests.
**Required Reads:** 1) `packages/core/src/Configuration/Config.php` 2) `packages/core/src/Concerns/HasRoles.php` 3) `packages/core/src/Concerns/HasScopedRoles.php` 4) `packages/core/src/Concerns/HasDirectGrants.php` 5) `packages/core/src/Grants/GrantBuilder.php` 6) `packages/core/src/Registry/Sources/DatabaseRoleGrantSource.php` 7) `packages/core/src/Models/Role.php` 8) `tests/Feature/ExtensionSwapTest.php`.
**Implementation Rules:** Each accessor accepts only an existing subclass of its documented base and throws one actionable AzGuard model-config exception naming key, received class and expected base. Resolve runtime queries/relations through the configured class; base-class parameter/return type-hints remain valid for subclasses. Model `getTable()` and effective connection govern Eloquent paths. Database-role lookup starts from the configured RolePermission Eloquent builder, joins the configured pivot table on that builder's connection, and therefore honors only RolePermission scopes, not invented pivot/Role scopes. Require all four AzGuard models plus P2 permission-state storage to resolve to one connection; reject mismatch before query/mutation. Preserve events, local scopes and return types; do not add a registry layer.
**Code Guidance:** Use local `$model = Config::*Model()` / model instances at each seam. A small private validation helper inside `Config` is enough. Replace concrete static queries, not correct `Role`/`DirectGrant` subclass-compatible type declarations. Keep raw pivot identifiers from existing table-name config and qualify with the originating model table.
**Validation:** 1) four custom subclasses with distinct tables/event markers are observed on relation, attach/sync, scoped-role, direct-grant and database-role paths; 2) custom DirectGrant and RolePermission global scopes affect their originating reads; 3) default model class is never instantiated on those paths; 4) invalid/non-subclass class gives the named config exception; 5) connection mismatch fails before any row changes; 6) default configuration behavior remains green; 7) `vendor/bin/pest tests/Feature/ConfiguredModelsTest.php tests/Feature/ExtensionSwapTest.php tests/Feature/DatabaseRoleGrantSourceTest.php tests/Feature/HasDirectGrantsTest.php tests/Feature/ScopedRolePanelIsolationTest.php`; 8) changed-file Pint, PHPStan and `git diff --check`.
**Deliverables:** Validated subclass contract; all named core bypasses removed; model-backed database role query; custom table/scope/event/connection regressions; no separate review stage.
