# P6.2 execution — 2026-09-23

**Item:** P6.2 — SQL identity portability
**Route:** `frontier/high` (Grok 4.7)
**Review:** light (inline)

## Delivered

- `NullSafeUniqueIndex` quotes validated identifiers and builds one exact unique key.
- PostgreSQL 16+ uses `NULLS NOT DISTINCT`. SQLite and MySQL use an `IS NULL` marker plus the full value for every nullable component. No `SUBSTRING`, prefix or hash.
- Fresh `000003` stores `panel_id` as `VARCHAR(128)`. Fresh `000005` uses the helper. Recorded databases upgrade through idempotent `000006`, which preflights overlong panel ids and engine capacity before schema DDL, then narrows, dedupes, swaps the index and adds nullable unique `roles.class_name`.
- Context `000010` creates and drops the configured table. `ModelHasScope` ids are documented as `int|string`.
- MariaDB is an explicit unsupported verdict. This item does not claim MariaDB support.

## Light review

| Seam | Verdict |
|:--|:--|
| Fresh `000005` and upgrade `000006` | Both emit `NullSafeUniqueIndex::createSql`. Repeated `000006` is a no-op. `down()` restores the historical sentinel index, then `up()` returns the exact index. |
| Preflight before DDL | Overlong `panel_id`, 8 KiB pages, 4 KiB pages, `COMPACT` row format and a MariaDB version string abort with the legacy index and the original row still present. |
| Identifiers | Dot-separated segments are grammar-quoted. SQL-like names fail before `Schema::create`. |

| Null tuple | All-null scope tuples collide. `NULL` stays distinct from `0`, `''` and the all-zero UUID. Values that differ after character 191 stay distinct. |
