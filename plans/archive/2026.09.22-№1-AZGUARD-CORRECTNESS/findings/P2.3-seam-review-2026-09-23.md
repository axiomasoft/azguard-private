# P2.3 light seam review — role-sync / revision / cache-failure

Inspected the three P2 integration seams after P2.1–P2.3 product work. No
material defect found that requires a follow-up item.

## Role-permission sync (P2.1)

`RolePermissionSynchronizer` still validates before the transaction, locks the
role row, diffs the managed set, and preserves unmanaged rows. A changed diff
now calls `PermissionStateRevision::bump()` on the same connection before
commit. No-op returns without a bump. Split role / role-permission connections
still fail before writes.

## Revision / transaction bypass (P2.2)

Official mutators in `HasRoles`, `HasScopedRoles`, `HasDirectGrants`,
`GrantBuilder` and `ContextGrantBuilder` join `PermissionStateRevision::mutate()`.
`PermissionCache` and `ScopedRoleCache` skip reusable tiers at a positive
authorization-connection transaction level. `ClassRoleGrantSource` queries
`roles()` instead of a loaded relation. The 7→uncommitted 8→rollback→later 8
regression lives in `PermissionStateRevisionProtocolTest`.

## Cache failure and reset (P2.3)

Durable get/put and epoch bump catch only store transport exceptions, then
recompute without persisting. Source/DB exceptions propagate. Cache keys include
`cache.generation`. `guard:cache-reset` bumps the DB revision, clears local
request/scoped caches, and does not call store `flush()`. A missing
permission-state row leaves the command nonzero.

No automatic follow-up stage.
