# P4.2 light seam review — panel validation / grammar / Gate ownership

Inspected the P4 lifecycle and validation seams after P4.1–P4.2 product work.
No material defect found that requires a follow-up item.

## Final panel resolution

`PanelResolver` validates the computed id on `resolve` / `resolveOrFail` /
`resolveDefault`. Width 128 is always enforced. `strict_panels` throws
`PanelNotFoundException` for unknown explicit, configured, current and `app`
fallback ids, including an empty registry. Lenient mode still skip-logs when
the registry is empty. `Panel::id()` rejects 129 characters at the write
boundary.

## Permission grammar and double prefix

`PermissionGrammar` is the single syntax boundary. Global `*`, whole-segment
`*`/`**`, and `{name}` placeholders remain legal. `Panel::scope` does not
re-prefix an already scoped key. Pure/backed enums and Permission classes go
through `PermissionGrammar::raw` then the same scope path.

## Gate ownership

`Authorizer::check()` / `explain()` call `CatalogKeyMatcher::owns()` before
wildcard evaluation. Ownership is exact catalog membership or a registered
dynamic definition, not a prefix. Foreign abilities return `null` so
`Gate::before` continues to Laravel policies. Catalog-owned keys still honour
AzGuard `*`. `EffectivePermissionResolver` reuses the same matcher.

## Attributes and doctor

`require_permission_attributes` defaults false. Missing attributes pass at
runtime; opt-in raises `MissingPermissionAttributeException`. `SkipGuardCheck`
is an explicit bypass. `AzGuardDiagnostics` inspects only CheckAccess routes
and skips closures/unresolvable actions. Warning (legacy) and error (opt-in)
share one message; JSON/text stay aligned.

No automatic follow-up stage.
