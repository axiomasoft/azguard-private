### P2.2 — Согласовать revision и commit protocol

**Intent:** Сделать DB-backed permission-state revision единым authoritative fence для committed authorization mutations и всех subject types.
**Why:** RAG:— `findings/verification.md` F6–F8 и design audit A1: дубли invalidation, неполный `Role::users()`, commit/cache race и uncommitted cache poisoning. RAG:✅ Laravel root-commit callback не является durable delivery. D13 выбирает DB revision и transaction-local cache bypass.
**Scope Included:** Additive permission-state migration/config; revision reader/bump service; revision в P1 cache identity; role-permission, role/scoped-role, direct/context official mutations; no-op detection; current/original identity; loaded roles и `ScopedRoleCache`; events как notifications без второго authoritative invalidation.
**Scope Excluded:** Durable outbox; production migrations; per-role/per-subject revision matrix; cross-connection atomicity; произвольные raw/bulk external writes; exact one increment как acceptance; удаление public events.
**Inputs:** terminal GREEN `phases/P2/P2.1.state.md` · `phases/P1/P1.1.state.md` · `plan.md` · `phases/P2/P2.md` · `findings/verification.md` F6–F8 · D13 · `research/P2-design.md` · `research/P2-design-rag.md` · `artifacts/P2-design/examples.md`.
**Files:** new `packages/core/database/migrations/2026_01_01_000006_create_az_guard_permission_state_table.php` and `packages/core/src/Registry/Resolver/PermissionStateRevision.php` · core config/`Config.php` · `PermissionCache.php`, `EffectivePermissionResolver.php`, `ClassRoleGrantSource.php`, `ScopedRoleCache.php` · P2.1 synchronizer · official mutators under core concerns/grants and context builder/model · core/context service providers · targeted revision/transaction tests.
**Required Reads:** 1) `packages/core/src/Registry/Resolver/PermissionCache.php` 2) `packages/core/src/Registry/Resolver/EffectivePermissionResolver.php` 3) `packages/core/src/Registry/Sources/ClassRoleGrantSource.php` 4) `packages/core/src/Runtime/ScopedRoleCache.php` 5) `packages/core/src/Concerns/HasRoles.php` 6) `packages/core/src/Concerns/HasScopedRoles.php` 7) `packages/core/src/Grants/GrantBuilder.php` 8) `packages/context/src/ContextGrantBuilder.php`.
**Implementation Rules:** Create one seeded global revision row on the same configured DB connection as supported authorization tables. Every official mutation owns/joins a connection-aware transaction and increments revision only when rows changed; revision failure rolls the mutation back. Outside a transaction, resolver obtains committed revision before each request/durable lookup and keys reusable tiers by it. At any positive transaction level on the authorization connection, bypass all request/durable/scoped-role cache reads and writes, including prewarmed entries; resolve fresh on that connection without stale loaded relations and use the result only for that check. Nested commit/rollback never publishes it. After outer completion, reread committed revision before using/refilling caches. If connection or transaction state cannot be established reliably, fail closed. A refill started under revision N outside a transaction may finish only under N; after commit N+1 cannot read it. On recompute, class-role lookup must not reuse a stale loaded `roles` relation; `ScopedRoleCache` is revision-aware. P2.1 bulk diff bumps explicitly. Core/context fluent builders and role/scoped traits use the same mutation coordinator; current public events remain observable but cache listeners/inline flushes are not a second authority. Instance observers may remain documented safety nets, while query bulk writes outside official APIs require explicit reset. Fail fast before write when state row and mutation use different connections.
**Code Guidance:** Keep revision scalar/global and monotonic; do not add role vectors or enumerate holders. Read it from DB as correctness evidence, not from the cache being fenced. Preserve P1 per-subject epoch only as compatible local optimization. Reuse one transaction helper rather than duplicating begin/commit logic across traits/builders.
**Validation:** 1) reader/refill before commit stays on N; first check begun after commit reads N+1 and current DB state; 2) a same-connection check at revision 7→uncommitted 8 must neither read nor write any reusable cache, including warmed request/scoped/durable entries; outer rollback returns to 7 and a different later commit to 8 cannot reuse the rolled-back allow in a second reader sharing the cache; cover nested savepoint commit/rollback and post-outer-commit refresh; 3) revision write exception rolls back grant/revoke/sync; 4) no-op grant/sync/attach does not bump, retry remains idempotent; 5) role permission change reaches two morph subject types plus scoped assignment without `Role::users()` enumeration; 6) loaded `roles` and warmed `ScopedRoleCache` do not restore revoked rights after N+1 or within a transaction; 7) targeted SQLite `:memory:` Pest for revision protocol plus existing `CrossRequestCacheInvalidationTest.php`, `PermissionCacheEpochInvalidationTest.php`, `RoleAssignmentCommandTest.php` and context invalidation tests; 8) `vendor/bin/phpstan analyse --memory-limit=1G`, changed-file Pint and `git diff --check`.
**Deliverables:** Transactional permission-state revision; revision-aware request/durable/scoped caches; official core/context mutation map with one authority; nested rollback/refill/multi-subject regressions; explicit cross-connection/bulk-maintenance verdict.
