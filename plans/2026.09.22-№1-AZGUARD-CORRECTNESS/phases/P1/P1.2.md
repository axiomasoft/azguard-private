### P1.2 — Учитывать expiration на каждом cache hit

**Intent:** Исключить stale allow после absolute expiry даже при cache hit в том же long-lived request/job scope и при backend TTL, округлённом позже deadline.
**Why:** RAG:— `findings/verification.md` F2: DirectGrant/ContextRole фильтруют expiry только в DB query, а request/durable cache хранит только keys. RAG:✅ PSR-16/Laravel Cache не дают application authorization deadline guarantee; D3 выбирает absolute metadata в текущем public `PermissionSet` без смены interface return types.
**Scope Included:** Additive nullable `validUntil` в immutable `PermissionSet`; minimum deadline при merge и preservation при filter/wildcard; DirectGrantSource и ContextPermissionLayer получают active keys и nearest expiry одним bounded read; PermissionCache request/durable envelope v2, absolute hit check и backend expiry `min(config TTL, validUntil)`; compatibility с legacy custom sources/layers.
**Scope Excluded:** Breaking return-type/interface changes; обязательный deadline для legacy custom sources; per-permission provenance; cache outage/retry/outbox P2; DB pruning; stale-while-revalidate; новые tables/columns.
**Inputs:** `phases/P1/P1.1.state.md` as terminal GREEN P1.1 evidence · `plan.md` · `phases/P1/P1.md` · `findings/verification.md` F2–F3 · `decisions/D2-correctness-and-compatibility.md` · `decisions/D3-p1-cache-identity-and-expiry.md` · `docs/reference.md` · `research/P1-design.md` · `research/P1-design-rag.md` · `artifacts/P1-design/examples.md`.
**Files:** `packages/core/src/Registry/Values/PermissionSet.php` · `packages/core/src/Registry/Resolver/PermissionCache.php` · `packages/core/src/Registry/Resolver/EffectivePermissionResolver.php` · `packages/core/src/Registry/Sources/DirectGrantSource.php` · `packages/context/src/ContextPermissionLayer.php` · targeted files under `tests/Unit/Registry/`, `tests/Feature/` and `tests/Fixtures/api-surface.snapshot.php` named in Validation · affected RU/EN cache/extension documentation and root `CHANGELOG.md` if the additive API is release-visible.
**Required Reads:** 1) `packages/core/src/Registry/Values/PermissionSet.php` 2) `packages/core/src/Registry/Resolver/PermissionCache.php` 3) `packages/core/src/Registry/Resolver/EffectivePermissionResolver.php` 4) `packages/core/src/Registry/Sources/DirectGrantSource.php` 5) `packages/context/src/ContextPermissionLayer.php` 6) `packages/context/src/Strategies/GlobalPlusContextStrategy.php` 7) `tests/Feature/DirectGrantSourceTest.php` 8) `tests/Feature/Context/ContextPermissionLayerTest.php`.
**Implementation Rules:** Сохранить существующие constructors, `GrantSource::permissionsFor()` и `PermissionLayer::apply()`; deadline — новый nullable additive API `PermissionSet`. `merge()` берёт minimum из двух non-null deadlines; `filter()` и wildcard path не теряют deadline вклада. Built-in DB reads возвращают keys + nearest active `expires_at` без query-per-row; `expires_at <= now` не входит в set. Request cache хранит сам `PermissionSet`, но перед каждым return проверяет trusted clock; durable cache хранит strict envelope `{version, keys, valid_until}`. Raw arrays, неверная version/schema/time и already-expired envelope являются miss, пересчитываются и перезаписываются. Backend expiry не позже minimum из config TTL и absolute deadline; null config TTL не отменяет deadline. На boundary `now >= validUntil` разрешение не возвращается: один bounded refresh; повторно already-expired result fail-closed и не cache-ируется. Legacy set без deadline продолжает жить по configured TTL; эта граница документируется.
**Code Guidance:** Передавать immutable absolute instant, а не relative seconds; сериализовать его в однозначном UTC формате. Recompute всего effective set на earliest expiry — намеренная безопасная гранулярность; не вводить per-key provenance. В тестах использовать frozen Carbon clock и exact boundary, не sleep. Не использовать `Cache::flexible` или stale window для authorization.
**Validation:** 1) в одном `PermissionCache` instance direct grant разрешает до deadline и не разрешает на exact deadline без prune/invalidation; то же для context grant и fresh durable-cache instance; 2) два contributors для одного permission: истечение раннего вклада вызывает recompute, поздний/бессрочный вклад сохраняет allow; 3) merge, filter, global wildcard и все три context strategies сохраняют корректный nearest deadline; 4) raw v1 array, wrong version, malformed/missing keys/time и expired v2 envelope не возвращают stale allow; 5) существующий custom `GrantSource` без deadline и custom `PermissionLayer` остаются совместимы, а source, создавший set с `validUntil`, проходит exact-boundary regression; 6) `vendor/bin/pest tests/Unit/Registry/PermissionSetTest.php tests/Unit/Registry/PermissionCacheTest.php tests/Unit/Registry/EffectivePermissionResolverTest.php tests/Feature/DirectGrantSourceTest.php tests/Feature/Context/ContextPermissionLayerTest.php tests/Feature/CustomGrantSourceTest.php tests/Unit/ApiBoundaryTest.php`; 7) `vendor/bin/phpstan analyse --memory-limit=1G` для affected packages, `vendor/bin/pint --test` на changed PHP files и `git diff --check`; 8) API snapshot меняется только на запланированный additive `PermissionSet` API.
**Deliverables:** Additive deadline-aware `PermissionSet`; built-in direct/context nearest-expiry propagation; strict v2 cache envelope с hit-time deadline check в request и durable tiers; regression для exact boundary, multiple contributors, wildcard/context strategies, malformed legacy payload и custom-source compatibility; release-visible docs/CHANGELOG для нового API.
