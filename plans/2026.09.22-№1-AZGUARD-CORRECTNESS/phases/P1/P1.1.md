### P1.1 — Изолировать все cache keys по субъекту

**Intent:** Дать cache/read/invalidation paths одну каноническую identity субъекта, чтобы два Eloquent-типа с одинаковым ID не делили permissions и invalidation.
**Why:** RAG:— `findings/verification.md` F1 воспроизводит cache collision: resolver и observers передают только ID; `HasScopedRoles` тоже строит request key без user morph type. D3 фиксирует identity и cache namespace.
**Scope Included:** Внутренняя immutable subject identity из persisted morph type + canonical string ID; безопасное кодирование subject/panel/discriminator; request cache, durable permission key, epoch key, durable/request forget, DirectGrant/ContextRole old+new identity invalidation и `ScopedRoleCache`; cache-key namespace v2.
**Scope Excluded:** P2 transaction/failure protocol; глобальный cache reset; tenant/database-connection identity; DB schema; public resolver/GrantSource/PermissionLayer signatures; unrelated scoped-role query behavior.
**Inputs:** `plan.md` · `phases/P1/P1.md` · `findings/verification.md` F1 · `decisions/D2-correctness-and-compatibility.md` · `decisions/D3-p1-cache-identity-and-expiry.md` · `research/P1-design.md` · `research/P1-design-rag.md` · `artifacts/P1-design/examples.md`.
**Files:** `packages/core/src/Registry/Resolver/SubjectIdentity.php` · `packages/core/src/Registry/Resolver/PermissionCache.php` · `packages/core/src/Registry/Resolver/EffectivePermissionResolver.php` · `packages/core/src/Models/DirectGrant.php` · `packages/context/src/Models/ContextRole.php` · `packages/core/src/Concerns/HasScopedRoles.php` · `packages/core/src/Runtime/ScopedRoleCache.php` · targeted files under `tests/Unit/Registry/`, `tests/Unit/Support/` and `tests/Feature/` named in Validation.
**Required Reads:** 1) `packages/core/src/Registry/Resolver/PermissionCache.php` 2) `packages/core/src/Registry/Resolver/EffectivePermissionResolver.php` 3) `packages/core/src/Models/DirectGrant.php` 4) `packages/context/src/Models/ContextRole.php` 5) `packages/core/src/Concerns/HasScopedRoles.php` 6) `packages/core/src/Runtime/ScopedRoleCache.php` 7) `tests/Unit/Registry/PermissionCacheTest.php` 8) `tests/Feature/DirectGrantMorphMapTest.php`.
**Implementation Rules:** Ввести один internal `SubjectIdentity` с constructors из `Authenticatable` и из уже persisted `(morph type, id)`; на read path брать `getMorphClass()`, в model observers — persisted current/original morph type и ID. ID нормализовать string cast: `1` и `"1"` совпадают, `"01"` не переписывается. Не склеивать raw segments разделителем: канонически сериализовать tuple и получать fixed-length URL-safe digest. Epoch digest включает subject+panel и тем самым инвалидирует все contexts; permission digest добавляет discriminator. Ключи используют portable alphabet и не длиннее 64 bytes. Новый `v2` prefix не читает v1 keys; mass flush не нужен. При update/move grant инвалидировать как original, так и current full identity. Все публичные контракты остаются совместимыми.
**Code Guidance:** `SubjectIdentity` отвечает за каноничные bytes/digest; `PermissionCache` только компонует version/kind/epoch. Не дублировать encoding в observers и `HasScopedRoles`. Для request arrays можно использовать тот же digest, чтобы read/forget keys не расходились. `ScopedRoleCache` остаётся request-scoped; меняется только key identity.
**Validation:** 1) регрессия resolver/cache: `User#1` и другой authenticatable model `Admin#1` в одной panel вызывают два resolution и видят разные sets в request и named persistent store; 2) forget/epoch одного type не меняет key/result другого type, но сбрасывает все discriminators своего subject+panel; 3) morph alias, FQCN, int/string, UUID/ULID, unicode/separator panel/context values дают детерминированные portable keys без collision; 4) DirectGrant/ContextRole move бумпает original и current typed identity; 5) scoped-role cache не смешивает два auth types с ID=1; 6) `vendor/bin/pest tests/Unit/Registry/PermissionCacheTest.php tests/Unit/Registry/EffectivePermissionResolverTest.php tests/Unit/Support/ScopedRoleCacheTest.php tests/Feature/DirectGrantMorphMapTest.php tests/Feature/PermissionCacheEpochInvalidationTest.php`; 7) при доступном isolated Redis `vendor/bin/pest tests/Feature/PermissionCacheCrossProcessRaceTest.php`, иначе явно зафиксировать Redis `unavailable`, не GREEN; 8) `vendor/bin/pint --test` на changed PHP files и `git diff --check`.
**Deliverables:** Один канонический `SubjectIdentity`; v2 request/durable/epoch keys без type collision; typed current/original invalidation для core/context grants; typed scoped-role request key; targeted GREEN evidence и честный Redis availability verdict.
