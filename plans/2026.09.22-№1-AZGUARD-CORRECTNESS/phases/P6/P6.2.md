### P6.2 — Проверить SQL identity portability

**Intent:** Заменить sentinel/prefix uniqueness на exact null-safe identity и довести configurable schema names до migration parity.
**Why:** RAG:— F19/F21, D8 и design audit A2: 000005 вставляет raw table names, сводит `NULL` к legitimate zero/empty sentinels и обрезает MySQL type columns; полный ключ с тремя default VARCHAR(255) не помещается в InnoDB. Context runtime читает configured table, но 000010 create/down hardcode default. Первичные DB docs в `docs/reference.md`; D14 задаёт feasible driver/schema verdict.
**Scope Included:** One internal driver-aware null-safe index compiler; forward migration for already-recorded 000005; future-fresh parity; nullable `roles.class_name` uniqueness after P5 cleanup; safe grammar quoting of configured tables/indexes; context create/down config parity; morph/context PHPDoc and focused docs.
**Scope Excluded:** MariaDB support without an actual isolated run; accepting arbitrary SQL/aliases in config names; silent truncation/prefix uniqueness; live migration; renaming existing consumer tables; automatic movement of a deployed default context table when config changes.

**Implementation Rules:** Centralize create/drop in one internal helper and quote table/index identifiers with the active Laravel grammar; accept only validated dot-separated identifier segments, never aliases/comments/expressions. PostgreSQL 16+ uses exact composite `NULLS NOT DISTINCT`. SQLite uses a unique expression index whose key contains an explicit null marker plus a normalized value for every nullable component. MySQL support is non-MariaDB >=8.0.13, InnoDB 16-KiB pages and DYNAMIC/COMPRESSED row format under the declared utf8mb4/int/UUID/ULID schema; use supported functional/generated key parts with null markers and full exact values—no `SUBSTRING`, prefix or hash. Future-fresh 000003 bounds `model_has_scopes.panel_id` to 128 characters. New idempotent 000006 preflights actual engine/key capacity and any deployed panel value longer than 128 **before schema-changing DDL**; reject unsupported capacity/overlength without truncation, with explicit consumer data-migration guidance. Then narrow the existing column, create/verify the exact replacement, and drop the legacy index; retry converges after interruption. 000005 uses the same helper for fresh installs; editing it is not the deployed upgrade path. Detect MariaDB via the connection, not driver string alone, and fail with a named unsupported verdict unless this item adds and passes an actual MariaDB job. Dedupe via P6.1 and add nullable unique `roles.class_name` after P5 cleanup. Context 000010 resolves one configured table name for both up/down; existing deployed default tables move only by documented explicit consumer migration. Preserve int/UUID/ULID columns and accept legitimate zero, empty string and all-zero UUID as data distinct from NULL. Correct `ModelHasScope` PHPDoc to `int|string` IDs.
**Code Guidance:** Prefer capability/version checks and small driver branches over a generic schema registry. Keep index names deterministic. Do not rely on raw interpolation, prefix-only uniqueness, probabilistic hashes, or application-only preflight for a DB uniqueness invariant.
**Validation:** 1) Fresh and legacy-index upgrade yield the same exact indexes on SQLite, PostgreSQL 16 and the declared MySQL 8.0.13+ with 16-KiB pages and DYNAMIC-or-COMPRESSED row format profile; repeated 000006 is no-op and down/up is deterministic; 2) preflight rejects deployed `panel_id` >128 and 8-/4-KiB or old-row-format MySQL before schema-changing DDL, preserves rows and legacy index, and retry after explicit data repair converges; inspect emitted DDL and calculate worst-case key bytes for int/ULID/UUID under actual charset, then execute DDL on isolated MySQL; 3) duplicates collide only for equal full tuples, including all-null nullable components, while null versus `0`, `''`, all-zero UUID and values differing after character 191 remain distinct; 4) int/ULID/UUID morph fixtures and nullable `class_name` uniqueness pass; 5) reserved/mixed-case and supported schema-qualified custom core table names are quoted safely, invalid SQL-like names fail before DDL; custom context table is used by both 000010 up/down; 6) targeted Pest files run on SQLite and isolated `azguard_test` PostgreSQL/MySQL after preflight; actual MariaDB run is required before any support claim; 7) affected Pint/PHPStan, API/BC snapshot for new panel width behavior, RU/EN docs parity and `git diff --check`; 8) one light review of the final P6 migration/index/identifier seams, with material fixes inline and no automatic second review.
**Deliverables:** Exact cross-engine identity constraints for declared engines, explicit MariaDB verdict, safe fresh/upgrade migration paths, configurable table-name parity, corrected model docs, regressions/docs/changelog and one recorded light review.
