## Scope Included

Свести результаты P1–P6 и закрыть только недостающие cross-package regressions;
проверить installability существующей support matrix и обязательный Redis lane с
реальным backend. Измерить затронутые mutation/coverage gates без новых порогов.

Согласовать glossary, RU/EN и upgrade guidance с фактическими результатами фаз;
root changelog и candidate release check должны предшествовать tag.

## Scope Excluded

Новая full-fleet проверка экосистемы, немотивированные coverage/analysis thresholds, запуск deploy/release/tag/push; перенос общего AGENTS в Chatom.

## Acceptance

Affected package checks и cross-package regressions зелёные с явными env/support
limits; реальный Redis lane не превращает skip в успех. Composer-resolved support
grid и фактические CI lanes согласованы. API snapshot delta имеет явное BC/version
решение. RU/EN/UPGRADING описывают фактическое поведение. Read-only release
preflight доказывает, что root CHANGELOG присутствует в candidate/tagged commit
до публикации; релиз здесь не публикуется.

## Validation strategy

P7.1: selected Pest suites, PHPStan/Pint/Rector/types/API snapshot по затронутым
путям; Composer installability declared grid; PostgreSQL/MySQL только на
изолированных `*_test`; Redis service/extension и cross-process checks должны
исполняться, а не skip. Existing coverage/mutation thresholds оцениваются по
измеренным результатам, без произвольного повышения.

P7.2: docs parity/PHP floor/build; просмотр old→new upgrade steps по решениям
P1–P6; candidate release preflight проверяет version entry в commit tree и
tag workflow не создаёт поздний changelog commit. Dependency audit/action pins
оцениваются только при отдельном measured security finding, не как новый gate.

Конкретные команды и outcomes находятся в item specs. Reproduction и исправление
выполняются в одном owning item; не коммитить полную красную suite как отдельную фазу.
