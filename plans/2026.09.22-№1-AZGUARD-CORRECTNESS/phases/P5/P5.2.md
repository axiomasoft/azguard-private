### P5.2 — Сделать scaffold предсказуемым

**Intent:** Создавать панель и добавлять домен без перезаписи существующего кода, с правильными policy model/actor types.
**Why:** RAG:— F17: `make:guard-panel` отказывает на existing path без `--force`, provider stub привязан к первому domain, policy stub использует `App\Models\User` и `App\Models\{{ domain }}`; config regex пишет в неизвестный PHP layout. D8 задаёт additive CLI contract.
**Scope Included:** `make:guard-panel` для новой панели, новый `make:guard-domain` для существующей, общий узкий generator/validation helper, provider/config registration, model/actor placeholders, doctor integration, targeted tests, RU/EN docs/changelog and one light review.
**Scope Excluded:** General PHP parser/AST, rewriting custom providers, implicit force-overwrite, CLI namespace rename, arbitrary auth provider discovery, silent policy registration on unsupported layout.
**Inputs:** terminal GREEN `phases/P5/P5.1.state.md` · `phases/P3/P3.2.state.md` · `phases/P4/P4.2.state.md` · `plan.md` · `phases/P5/P5.md` · `findings/verification.md` · `decisions/D8-p5-role-identity-and-safe-scaffold.md` · `research/P5-design.md` · `research/P5-design-rag.md` · `artifacts/P5-design/examples.md`.
**Files:** `packages/core/src/Commands/MakeGuardPanelCommand.php` · new `packages/core/src/Commands/MakeGuardDomainCommand.php` and one shared internal generator/validation helper · `packages/core/src/Commands/Concerns/ResolvesGuardNamespaces.php` · `SupportsForcefulGeneration.php` · `packages/core/src/AzGuardServiceProvider.php` · `packages/core/stubs/panel/guardpanelprovider.stub` · `domain-policy.stub` · `domain-permission.stub` · `domain-abilities.stub` · `role.stub` · `packages/core/src/Guard/AzGuardDiagnostics.php` · `tests/Feature/MakeGuardPanelCommandTest.php` · new `tests/Feature/MakeGuardDomainCommandTest.php` · `tests/Feature/DoctorCommandTest.php` · `docs/basic-usage/artisan-commands.md`, RU counterpart · `docs/basic-usage/roles.md`, RU counterpart · `docs/introduction/upgrading.md`, RU counterpart and root `CHANGELOG.md`.
**Required Reads:** 1) `packages/core/src/Commands/MakeGuardPanelCommand.php` 2) `packages/core/src/Commands/Concerns/ResolvesGuardNamespaces.php` 3) `packages/core/src/Commands/Concerns/SupportsForcefulGeneration.php` 4) `packages/core/stubs/panel/guardpanelprovider.stub` 5) `packages/core/stubs/panel/domain-policy.stub` 6) `packages/core/src/AzGuardServiceProvider.php` 7) `packages/core/src/Guard/AzGuardDiagnostics.php` 8) `tests/Feature/MakeGuardPanelCommandTest.php` 9) `tests/Feature/DoctorCommandTest.php` 10) `decisions/D8-p5-role-identity-and-safe-scaffold.md` 11) `phases/P5/P5.1.state.md`.
**Implementation Rules:** New panel path fails if occupied; add-domain operates only in an existing panel and adds only its new domain. Neither command overwrites unrelated files by default; repeated identical generation is no-op, conflicting generated content fails with a file list and remedy. `--force` is scoped to generated target files, never the whole panel. Validate panel/domain PHP identifiers, path containment, option FQCNs and model/actor contracts before filesystem mutation. For the documented safe path, `--model` identifies an existing Eloquent domain model; `--actor` is explicit or resolves from configured auth provider and must be Authenticatable. Keep old panel command signature accepted: without `--model`, retain its legacy convention with a warning and document it is unvalidated; add-domain requires `--model` or configured domain model. Substitute validated FQCNs, not plural domain text, into policy; generated PHP must parse. Register new provider only in recognized config shape; add domain enum only to recognized generated provider shape. On unrecognized/custom PHP, leave it unchanged and print exact manual registration instructions. Doctor reports generated invalid model/actor and missing enum registration without changing JSON/text shape. Use atomic write/rollback for owned generated targets where feasible, with no partial config rewrite on failure.
**Code Guidance:** Share file-existence and placeholder logic between commands. Do not parse arbitrary PHP with regex; recognize the package's own generated template and fail closed for other layouts. Keep `role.stub` compatible with P5.1 canonical sync.
**Validation:** 1) `make:guard-panel Admin Documents --model=App\Models\Document --actor=<custom Authenticatable>` renders correct policy FQCN, enum and provider; generated files pass `php -l` and class load smoke; 2) `make:guard-domain Admin Invoices --model=<Invoice FQCN>` adds enum/provider entry, preserves Documents and custom code, and second identical run changes no bytes; 3) invalid identifier/path traversal, unknown model/actor, unknown panel, conflicting domain, nonstandard provider/config fail before overwrite with actionable output; 4) `--force` affects only target generated files; old CLI invocation remains accepted with compatibility warning; doctor text/JSON identify scaffold issues; 5) `vendor/bin/pest tests/Feature/MakeGuardPanelCommandTest.php tests/Feature/MakeGuardDomainCommandTest.php tests/Feature/DoctorCommandTest.php`; 6) PHP lint on generated fixtures, changed-file Pint/PHPStan, docs parity, API snapshot if public surface changes, `git diff --check`; 7) one light review of changed role identity/scaffold/diagnostics seams, with material repair inline and no automatic follow-up review.
**Deliverables:** Safe panel/add-domain commands, valid configurable stubs and registration, isolated filesystem/doctor regressions, RU/EN usage and upgrade notes, root changelog and one recorded light review.
