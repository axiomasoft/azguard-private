## Scope Included

- Scoped current-panel state при long-lived registry; existing Facade/manager signatures;
  nested restore через `finally`; HTTP/Octane/queue/sync lifecycle и F15 auth-model guard.
- Проверка итоговой explicit/default/current panel, включая empty registry в strict mode.
- Storage limit 128 символов для итогового panel ID при любом strictness; D14 связывает
  его с exact MySQL index и требует явной upgrade/BC документации.
- Одна normalization/grammar boundary для string, UnitEnum/BackedEnum, Permission class,
  wildcard и dynamic keys; явная ownership boundary перед `Gate::before`.
- Opt-in runtime enforcement для route без `CheckPermission`; `SkipGuardCheck` остаётся
  явным bypass; doctor видит legacy и strict режимы.

## Scope Excluded

Переписывание Panel DSL или Gate; новый public PanelContext API; fiber/coroutine
safety claim; silent strict defaults на upgrade; трёхстадийный item/post/phase review;
всеобщая проверка чужих Laravel abilities или рейтинг всех routes.

## Acceptance

Nested success/exception возвращают outer panel; следующий request/job получает
новый scoped state, а sync job не стирает current state. Auth provider model query не
рекурсирует через `Auth::check()`.

При `strict_panels=true` unknown explicit/default/current panel отвергается и при
пустом registry; default валидируется после registration. Legacy defaults не
меняются молча, кроме явного storage limit 128: 129 символов отвергаются и при
strict off до записи. Missing attribute и explicit skip различаются. Strings,
pure/backed enums, Permission classes, wildcard/dynamic keys проходят одну boundary.
Не принадлежащая catalog/panel ability возвращает `null` из AzGuard `Gate::before`,
даже для AzGuard wildcard user, и доходит до Laravel policy.

## Validation strategy

P4.1: scoped-container reset, nested success/exception, HTTP/queue/Octane/sync semantics,
custom manager contract и ограниченное воспроизведение auth-model recursion F15.

P4.2: unknown explicit/default/current/empty-registry; legacy/strict missing attributes;
malformed, wildcard и dynamic keys; pure/backed/class-based parity; catalog ownership и
unrelated Laravel policy fallback. После GREEN — один light review изменённых seams.

Конкретные test files/команды и expected outcomes закреплены в item Validation.
Reproduction и исправление выполняются в одном owning item; не коммитить
полную красную suite как отдельную обязательную фазу.
