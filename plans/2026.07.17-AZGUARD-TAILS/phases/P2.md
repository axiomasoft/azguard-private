### P2.2 — T4: literal '*' не матчит dynamic-плейсхолдер при wildcard-off

**Status:** ⬜ Not started
**Intent:** `EffectivePermissionResolver::filterAgainstCatalog()`, ветка
`! Config::wildcardEnabled()` (строки 129-134), проверяет
`$this->catalog->has($panelId, $key) || $this->matchesDynamicDefinition($key,
$dynamicDefinitions)` БЕЗ предварительной проверки `str_contains($key,
PermissionKey::WILDCARD)` — литеральный `*` в грант-ключе (например,
`"app.docs.*"`) может случайно совпасть с dynamic-определением каталога вида
`"app.docs.{something}"` (плейсхолдер-сегмент матчит ЛЮБУЮ строку сегмента, включая
буквальный `"*"`), хотя докблок метода (строки 106-113) обещает: «with the feature off,
patterns are treated as unknown exact keys and removed». Добавить ту же защиту, что уже
есть в wildcard-ON ветке (строка 143: `if (! str_contains($key, WILDCARD)) { … }`).
**Why:** RAG:— (repo-grounded: `EffectivePermissionResolver.php:122-165`, метод
`matchesDynamicPattern()` строки 185-199 — плейсхолдер-сегмент `{seg}` матчит ЛЮБОЙ
непустой сегмент без сравнения содержимого, включая буквальный `"*"`). Вред на данный
момент нулевой (ключ, содержащий `*`, при выключенном wildcard всё равно инертен — не
матчится другими путями в резолвере), но поведение противоречит собственной
документации метода и является скрытой миной для будущего рефакторинга.
**Scope Included:** правка ветки `! Config::wildcardEnabled()` в
`filterAgainstCatalog()`, исключающая ключи с `WILDCARD`-символом из
dynamic-сопоставления; regression-тест, доказывающий: (1) грант `"app.team.*"` при
wildcard OFF и наличии каталожного dynamic-определения `"app.team.{id}"` теперь
ОТБРАСЫВАЕТСЯ (сейчас — сохраняется, это баг); (2) существующее поведение — реальный
конкретный ключ `"app.team.42"` матчит dynamic-определение как и раньше — НЕ
регрессирует.
**Scope Excluded:** wildcard-ON ветка (строки 137-160) — уже корректна, не трогать;
`matchesDynamicPattern()`/`matchesDynamicDefinition()` — сама логика плейсхолдеров не
меняется, только КОГДА она вызывается.
**Inputs:** `PermissionKey::WILDCARD` (константа, уже импортирована и используется в
этом файле — строка 143 wildcard-ON ветки, паттерн для копирования).
**Files:** `packages/core/src/Registry/Resolver/EffectivePermissionResolver.php`
(приватный метод `filterAgainstCatalog`, строки 122-165) ·
`tests/Unit/Registry/` — найти существующий тест-файл на `EffectivePermissionResolver`
(если есть) или создать новый (см. Required Reads) · `packages/core/CHANGELOG.md`
(Deliverable — запись под `### Fixed`) · `REMAINDER_REPORT.md` (D6: строка T4 → Статус
«Закрыт» + ссылка на коммит) · `IMPROVEMENT_PLAN.md` (D6: колонка `Status` строки T4).
Все три — repo-доки, идут в item-commit (не bookkeeping).
**Required Reads:** 1) `packages/core/src/Registry/Resolver/EffectivePermissionResolver.php`
целиком, особое внимание строкам 106-165 (обе ветки `filterAgainstCatalog`) и 174-201
(`matchesDynamicDefinition`/`matchesDynamicPattern`) 2)
`ls tests/Unit/Registry/ tests/Feature/ | grep -i resolver` — определить существующий
тестовый дом для этого класса перед созданием нового файла 3)
`packages/core/src/PermissionKey.php` — сигнатура/значение константы `WILDCARD`.
**Implementation Rules:** зеркалить ТОЧНО ту же проверку, что уже стоит на строке 143
wildcard-ON ветки (`! str_contains($key, PermissionKey::WILDCARD)`) — не изобретать
другую формулировку защиты (например regex) ради «единообразия» с чем-то ещё:
единственный эталон — соседняя ветка этого же метода.
**Code Guidance:** в ветке `! Config::wildcardEnabled()` (строка 130-131) заменить
однострочный filter-callback на явную проверку: если `str_contains($key,
PermissionKey::WILDCARD)` — вернуть `false` СРАЗУ (ключ с `*` при выключенном wildcard
всегда отбрасывается, dynamic-проверка для него не выполняется); иначе — прежняя

`logDroppedKeys()` вызов (строка 132) — он остаётся после фильтрации, лог сам покажет
дропнутый `*`-ключ, если раньше это было не так — это ЧАСТЬ ожидаемого исправления, не
побочный эффект для сокрытия.

роллбэке (тихое удаление строк = потеря scoped-role назначений), НЕ технический
