# P14 — Прямая выдача `*` невозможна, суперадмин — признак роли

**Probe:** P14
**Finding:** N13
**Owning rationale:** Колонка Probe досье относит P14 к V02 (P1.1–P1.2, грамматика ключа), V17 (P4.7) и V22 (P5.2); запрет голых `*`/`**` вводит грамматика P1.2, поэтому owning item — P1.2, а P4.7 и P5.2 остаются в Scenarios.
**Owning item:** PLAN2.P1.2
**Scenarios:** V02, V17, V22
**Defect in 0.3:** `AzGuard::forUser($user)->on('test')->grant('*')` делал пользователя суперадмином через публичный fluent API. Тест: `audits/2026-09-29-audit/opus/evidence/probes/OpusAuditProbesTest.php`, `it('P14: a direct grant of * through the public fluent API makes the user superadmin')`.
**Required behavior:** Голые `*`/`**` не принимаются как ключ ни в роли БД, ни в прямом праве (`InvalidPermissionKeyException`); суперадмин появляется только через роль с признаком суперадмина.
**Status:** pending

## Сценарий на целевом API

```php
expect(fn () => $user->guard('admin')->grantPermission('*'))->toThrow(InvalidPermissionKeyException::class)
    ->and(fn () => $user->guard('admin')->grantPermission('**'))->toThrow(InvalidPermissionKeyException::class)
    ->and($user->guard('admin')->isSuperAdmin())->toBeFalse();

$user->guard('admin')->grantRole('root');   // роль с признаком суперадмина
expect($user->guard('admin')->isSuperAdmin())->toBeTrue();
```
