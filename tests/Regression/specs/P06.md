# P06 — Правило контекста принадлежит панели, а не приложению

**Probe:** P06
**Finding:** N07
**Owning item:** PLAN2.P4.6
**Scenarios:** V13
**Defect in 0.3:** Одна глобальная merge-стратегия `DenyWithoutContextStrategy`, нужная панели с контекстом, обнуляла права панели `admin`, где контекста нет. Тест: `audits/2026-09-29-audit/opus/evidence/probes/OpusAuditContextProbesTest.php`, `it('P06: DenyWithoutContext configured for the tenant panel also zeroes the admin panel')`.
**Required behavior:** Правило области задаётся на панель: `isolated(Store::class)` в `seller` и `none()` в `admin`; ambient `store:1` не применяется к `none()`, а явный `on: store` в `none()` отклоняется.
**Status:** covered: tests/Regression/P06Test.php::P06 keeps a none panel independent of another panels isolated ambient context

## Сценарий на целевом API

```php
AzGuard::configurePanel('seller', fn (PanelBuilder $panel) => $panel->scopes(AssignmentScopePolicy::isolated(Store::class)));
AzGuard::configurePanel('admin', fn (PanelBuilder $panel) => $panel->scopes(AssignmentScopePolicy::none()));
$admin->guard('admin')->grantPermission(AdminOrderPermission::Refund);

AzGuard::withinScope(AssignmentScopeRef::of('store', 1), function () use ($admin): void {
    expect($admin->hasPermission(AdminOrderPermission::Refund, guard: 'admin'))->toBeTrue();   // admin не затронут
});
// явный on: store в панели с none() отклоняется
```
