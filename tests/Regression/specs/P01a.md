# P01a — Wildcard class-роли не пересекает панели

**Probe:** P01a
**Finding:** N01
**Scenarios:** V15, V17
**Defect in 0.3:** Class-роль с `*`, зарегистрированная в панели `test`, давала в панели `admin` и `hasPermission`, и `isSuperAdmin`, и `Gate::allows`. Тест: `audits/2026-09-29-audit/opus/evidence/probes/OpusAuditProbesTest.php`, `it('P01a: a class role with * registered on panel "test" is superadmin on panel "admin"')`.
**Required behavior:** Роль с признаком суперадмина действует только в панели, где она объявлена; в другой панели `hasPermission`, `isSuperAdmin` и Gate отказывают одинаково.
**Status:** covered: tests/Regression/P01aTest.php::P01a never promotes a role from another panel to superadmin authority

## Сценарий на целевом API

```php
$user->guard('test')->grantRole('super');   // code-роль с признаком суперадмина панели test

expect($user->guard('test')->isSuperAdmin())->toBeTrue()
    ->and($user->guard('admin')->isSuperAdmin())->toBeFalse()
    ->and($user->hasPermission(AdminUserPermission::Delete, guard: 'admin'))->toBeFalse()
    ->and(Gate::forUser($user)->allows('admin:users.delete'))->toBeFalse();
```

## Покрытие текущего слоя

Core `decide` и `Authorizer::isSuperAdmin` проверяют свою панель и отклоняют чужой `RoleKey` до authority. Публичный subject API и Gate bridge проверяются своими тестами.
